# OpenLife · 旧项目系统完整容纳与 CardWorld 接线规范

> 建立于 2026-11-06。第 1–10 节保留原迁移契约及首轮记录，第 11 节记录本轮迁回引擎后的状态。
> 来源：`../archives/openlife-engine-20261102/` 的 `需求书.txt`、`docs/MODULES.md`、
> `docs/POSITIONING.md`、`docs/plans/long-term-game-design-2026-10-22.md` 与当前 CardWorld 源码。
> 旧版归档不因当前迁移而修改。

## 1. 产品定位与取舍

产品是“单人生活探索 + NPC 自主生活 + 可持续变化的聚落与世界”，不是万能上帝视角。
CardWorld 的地图、卡牌、时间、交互与美术尽量保留；旧引擎的规则、认知、历史、扩展能力分阶段接回。
玩家在真实环境中生活；自己的经历改变别人、生态、知识、制度，后代继承实际后果。
**首要目标是深度而非模块数量**。核心聚落按 10–50 人设计，个体精细模拟上限 80 人。
不因为重引擎而加入固定主线、战斗系统、伪按钮、远方万人逐帧模拟、全知 NPC 信息页、强制在线。

### 事实与证据边界

1. 旧仓库被归档而非删除。档案中有 `packages/`、`modules/`、`tests/`、`packs/`、`docs/`，但它们**目前不在 CardWorld 运行时中加载**。
2. `legacy-capabilities.json` 从档案的 `docs/MODULES.md` 自动抽取：11 个核心包；63 条模块导出记录、62 个不同模块 ID（`narrative-voice` 有重复导出）。文档曾称“60 个模块包”，那不是当前模块 ID 的精确个数。
3. 当前 CardWorld 有独立的天气、生态、关系、知识、家庭、历史等简化机制。功能相似不等于已经复用旧模块。
4. 2026-11-06 首批接入 `npc-social.js`、`npc-knowledge.js`、`npc-goals.js`：NPC—NPC 交往、实际协作关系、个体理论传播、受需要驱动的自愿补粮任务、增量存档；`voice.js` 部分库存相关对白已做状态约束。它们是**首批适配实现**，不是旧 `epistemic-state`、`settlement-locations` 完整运行。
5. 当前 `app.js` 和样式、地图、村子数据有原先未提交改动。迁移必须以实际工作区为基线，不得覆盖原改动。

## 2. 不能破坏的架构约束

- **一个世界真相。** `CardWorld` 和旧 `WorldModel` 不能同时独立持有物品、人物、天气、时间的权威状态。过渡期旧代码不写当前世界；后期迁入核心时切换所有权，旧路径删除。
- **命令 → 校验 → 规则 → 事务 → 状态 → 事件。** 玩家 UI、NPC、LLM、时间跳跃和内容包都不能绕过权限或凭空制造世界事实。
- **真相、观察、知识、记忆、信念分离。** NPC 不能用调试器里的全知数据规划；互相说话可以传播**主张**，不能直接传播真相或让对方自动掌握发明。
- **时间统一、随机可重放。** 后续完整迁移要把 `Math.random()` 改为按世界种子/实体/事件的确定性流，且每个事件边界只结算一次。当前新模块的社交倾向与传播判定已使用稳定散列，其他旧逻辑尚未完成。
- **资源守恒和所有权。** 必须能沿事件追查生产、消费、转移、损毁与借贷；丢失的物品不能由表现层回填。
- **身份、权限、信息一致。** 村民不能天然控制他人；玩家不能查看陌生人的秘密或内部性格精确值。可清点物资、行动成本、期限则应清楚显示。
- **历史不可被覆写。** 角色死亡、家族断绝或模块卸载后，可解释的重要历史记录仍应保留。
- **零假实现。** 不能因为某能力出现在目录或 UI 就称“已实现”；未完成的不出现可点击入口，或者明确标为规划。

## 3. 包与模块的容纳方式

全量清单：[`legacy-capabilities.json`](legacy-capabilities.json)；生成脚本：`scripts/sync-legacy-catalog.mjs`。

module-runtime、save-system、history-runtime、autonomy-runtime、life-contracts。

`source`、`capability`、`stateOwner`、`commands`、`events`、`saveVersion`、`projection`、
`tests`、`migration`、`status`。只写 adapter 或空实现不得标为可用。

## 4. 世界状态的过渡路线

### A. 现状：CardWorld 是权威

`app.js` 的 `boards/me/village/nature/lore` 仍是当前真相。新增
`npcSocial` 与 `npcKnowledge` 只保存 NPC 彼此间交往与个体知识这两类此前缺少的独立事实。
它们只在实际交谈、共同劳动或理论形成/传播后更新，能导出与恢复。
当前 save v1 **仅添加可选字段**，不修改原有数据含义；旧存档没有字段则初始化为空，
已有旧 `lore.theories` 仅恢复**发明或理论记录中注明的发现者**，绝不让所有 NPC 瞬间学会。

### B. 迁移切口：以生活事件作为接线边界

第一个完整迁移事务：`harvestField`（播种→劳作→秋收→实际粮食入仓→记忆/村史）。
命令与效果在新核心执行，再通过投影刷新已有卡牌；临时阶段做**影子对比，不双写状态**。
交易、送礼、托付、出生、知识传授、生态消长依次复用同一模式。

### C. 终态：引擎为权威，CardWorld 为交互与投影

```text
卡牌移动/菜单/自然输入  NPC规则决策  可选AI规划
              \         |        /
                 合法 Command
                     |
            Kernel + Rule Engine
                     |
           原子事务 / Event Log
                     |
              World Model
       /             |             \
  Ecology         Individuals     Society/History
       \             |             /
              权限化 Projection
                     |
           CardWorld UI 及叙事表现
```

AI 只能建议对话或 Command，不拥有状态，不写历史。用户不用 AI API 时游戏依然必须完整可玩。

## 5. NPC 智能升级的具体目标

每个 NPC 拥有独立的 `Personality / Attributes / Needs / Goals / Plans / Beliefs / Memories / Relations / Commitments`。
候选目标由生存压力、个人价值、亲情义务、技能、空间可达、风险、时间与资源估计共同评分；
必须有行动坚持、合法权限、失败反馈、计划中断与恢复。不能只是“每日到点换任务”或“调用 LLM 聊天”。

- 玩家不理 NPC 时，NPC 照常寻找食物、学习、休息、交友、合作、发生纠纷；
- 不知情的 NPC 不能凭空知道全村某处物资或陌生人的秘密；
- 技术传授需要实际接触；错误说法也可以流传；接收者可以不信；
- NPC 愿意与谁交流、为谁帮忙，应由关系与情况共同决定，不应无限刷好感；
- 玩家对 NPC 的控制必须取决于双方关系、雇佣/家庭/组织权限，不可随好感直接永久操纵；
- 高精度只用于玩家附近/核心人物，远处 NPC 必须有聚合结算路径。

**当前只完成第一段社交关系、个体知识传播和一个需求驱动的协助捕鱼选择；尚未接入完整的需要/心理模型、多步骤通用目标规划或 LLM。**
升级旧 `autonomy/brain.ts` 时优先复用旧版“目标评分 + 多步材料计划 + 受挫记忆”思想，
并用现有地图 `findPath` 和卡牌动作替换旧 `settlement-locations` 的空间/活动适配。

## 6. 生态、经济、社会、文明的必须闭环

- **旱涝**：天气→土壤和水位→农作物/鱼/芦苇→存粮/价格→NPC计划/冲突→知识与发明→下一季环境。
- **森林**：采伐→树木生物量→鹿栖息地→捕食关系→狩猎和木材短缺→替代工艺/禁伐约定。
- **生产**：个人劳动→工具损耗/物品产出→归属→仓储/消费/交易→债务信誉→下次经济决策。
- **文化**：个体解释→观点传播→实践→习俗→社会制度→支持/反对/改变→历史遗存。
- **家族**：出生→禀赋与环境→教育/师徒→独立选择→婚育/养育→死亡/交棒→遗产和未了问题。

每个链条必须由实际数据连接，至少可以跟踪一个人、一样物品和一个迟发后果；
不能仅靠弹出一段故事冒充整套模拟。

## 8. 文件和验收命令

```bash
npm start                       # 当前 CardWorld
npm test                        # 新增自动化检查
npm run legacy:catalog          # 从归档重新生成全量模块清单
npm run legacy:check            # 检查是否和归档清单一致
```

新文件：
- `apps/card-world/npc-social.js`：定向关系、实际交谈/合作记忆、稳定交谈倾向。
- `apps/card-world/npc-knowledge.js`：个人理论、来源、主观立场、实际谈话传播。
- `apps/card-world/npc-goals.js`：复用旧版效用仲裁思想，饥荒时从可执行任务中选择协助捕鱼。
- `apps/card-world/voice.js`：部分人物对白按实际存粮、熟食、播种情况筛选。
- `tests/npc-social.test.mjs`、`tests/npc-knowledge.test.mjs`、`tests/npc-goals.test.mjs`、`tests/dialogue-grounding.test.mjs`、`tests/legacy-catalog.test.mjs`。
- `scripts/sync-legacy-catalog.mjs`、`docs/integration/legacy-capabilities.json`。

开发者可用 `window.__mock.npcRelation(a,b)`、`window.__mock.npcBelief(a,id)` 等只读调试入口；
不应直接将世界私密状态显示给玩家。对话文本仍有旧版预写台词，可能不完全反映经济事实，
后续要改为经过世界状态校验的叙述，不要误报“真实 AI 已全部接入”。

## 9. 新工作验收纪律

1. 先 `git status`，明确用户未提交的工作；新工作不覆盖、清空、重置这些文件。
2. 每次接一个小但完整的玩家流程：入口→条件/成本→行动→效果→数日后变化→恢复。
3. 每个新模块列出真实来源、状态所有权、兼容方案和**可证伪的验收案例**。
4. 测试优先：多种子、不同倍速、刚好跨日/跨季、读档重入、丢内容包、低物资、死亡、多人冲突。
5. 不允许无限日志，不逐行写“已审查没问题”；只记录事实、差异、风险、阻断和结论。
6. 只有经过真实执行的内容才可标“已实现”；归档、适配原型、单元测试通过和玩家可用是四个不同状态。

## 11. 引擎源码迁回与玩家入口

归档的核心包、模块、旧客户端、内容包、地图、工程脚本和测试已迁入 `engine/`。原归档保留，迁入时跳过原服务存档、依赖链接和调试产物。旧依赖链接仍指向迁移前的路径，本项目从锁定文件重建工作区链接。完整模式默认仅监听本机。

## 13. 牌桌上的行路、生计和海岸袭扰

- 点空地使用现有地图寻路，拖动仍走近处直线。路程走时钟并耗体力，途中存档保存剩余路线。阻挡提示取第一个实际遇到的墙、岩壁或水域。
- 玩家常规采集耗时降为原来的 65%。到公灶吃一至三份饭需 8 至 16 游戏分钟，结算扣除实际熟食库存。
- 鹿、野猪等地面动物定时选可达的落脚点，拥挤时会分散，追击受地形阻挡。帮助保留操作和存档，地点牌描述眼前情况，崖壁线索可从村民口中听到。
- 黑礁岛在原地图东南外海。第七天以后，村落已落脚或玩家已发现黑礁岛才会触发预警。黑帆先从海上来，登陆后沿路去粮仓，抢走最多三份余粮，留出当季种粮。玩家持矛在途中守住可阻止抢粮。船队、航程和村史随原卡牌档保存，登岛玩法待接入。

## 14. 采集点的季节和库存

自然采集点在库存归零时从牌桌收起，原位置、冷却和牌编号随存档保存。留在采集点上的物件落到原地。旧档里还在等待恢复的采集点按原日期接续，田和建筑保留交互。

每天清晨按季节和天气结算采集库存。雨水补益葛麻、野果、药草和芦苇，夏旱会消耗怕旱植物的库存，春汛会补益湖里的鱼。入冬后许多草本枯败，普通栗树落叶、产量减少，易冻的一处会留下枯株。深林背景树冠四季常绿，两处松树采集点冬天仍可出木，并随时间补充库存。采集点植被在独立图层上更新，跟随真实库存，恢复后在原位置重新出现。

37 项测试通过。浏览器实测采尽葛麻、物件落地、刷新后仍空、旧档待恢复的芦苇按期归来、冬天实际采到松木、春雨恢复库存及夏旱损耗。冬季植被图层也核对了松针绿色和冻坏栗树的枯色。

## 15. 行动力、叠牌与野鸭

- 拖动是路线预览，松手后按点击和自动行动的同一套步速走过去。平地步行的体力消耗约为旧版手动拖动的 15%，停下时缓慢恢复。新局默认手动。开启自动行动时，空闲角色立即找任务，正在执行的手动动作完成后交给 AI。
- 相邻同类物品用数量徽标显示，可以整叠拖动或从详情拿取一份。每张牌仍保留原编号、存放时间和用途。武器与有独立使用次数的物品保持分开。
- 在可攻击目标的牌面选择挥拳、工具近击、投矛或举火把驱赶。实际结果校验距离、地形、体力和冷却。入睡会清除当前气泡及涉及该村民的排队对白。
- 采集点按自己的游戏时间更新库存，恢复时牌面和植被淡入，下一次恢复时刻随档保存。野鸭沿真实湖岸进出水域，繁殖要消耗巢里的蛋，小鸭能跟随成年鸭。种群也会因老死或狩猎减少。

40 项测试通过。浏览器实测自动开关、手动与自动同路段步速、闲置回力、叠牌拆分读档、入睡断话、资源错时淡入、野鸭上岸和下水、孵化、老死、投矛与火把驱赶。旧档、触屏换物、秋收和冬季采木通过回归。
