# 卡牌世界：像环世界那样盖房子（设计）

日期：2026-11-08 · 范围：`apps/card-world`

## 为什么做

现在盖房子是选一种房子（大屋/仓库/窝棚），放一张固定大小的“地基”牌，按步骤交料施工，盖好变成一张牌。
用户不要“地基牌”。要的是：房子多大、占哪片地、墙怎么围、门开在哪，**玩家和村民都能自己定**；
人多了、院子显得挤，村民会**自己扩出一间**，分出房间。房间不用手动指定用途，像环世界那样按屋里放的东西**自动起名**。

用户选定做法 A：地上铺一层看不见的建筑格子，墙沿格子线一段一段地画，门是墙上的一段，封闭的区域自动成为一间屋。

## 目标

- 玩家在地上画墙（沿格子线拖一条，或拖一个框围一圈）、在墙上点出门、取消没盖的墙、拆已盖的墙。
- 画好的墙先是虚线“蓝图”；你或村民把料搬过去，一段段立起来，干到哪儿看得见。
- 墙（含门）把一片地围死，就成了一间屋；屋需要上顶，上了顶才算“屋里”。
- 屋按里面的东西自动起名：有铺位叫卧房，有灶叫灶房，有粮囤或材料堆叫仓房，有饭桌叫堂屋，空的叫空屋；原来的院子仍叫院子。
- 有顶的屋里冬夜不挨冻、下雨能躲；新铺位可以放进任何一间卧房。
- 村民按现实的理由自己扩建：铺位放不下了、有人成了家想要自己一间、材料堆不下了。会的人选地方、划墙、备料、领着盖，先说一声。
- 现有院子和仓房的墙并入新系统：样子不变，但可以在旁边接屋、在墙上开门打通。老存档能读。

## 不做（这一轮）

- 地板、家具品质、房间“好不好看”的打分，以及由此影响的心情。
- 房间用途带来的额外规则（比如“卧房里才睡得香”）。房间名字主要是给人看的。
- 温度模拟（屋里几度）。只看“有顶的屋里”和“外面”。
- 斜墙、楼层、墙的耐久和被野兽或海寇破坏。
- 多种墙材。先只有一种墙（见下），石墙等以后再加。

## 不能做坏的（反目标）

- 村民穿墙、卡在墙里、被关在没门的屋里出不来。
- 村民为了盖墙又把木头砍光（参考 v62.6 刚修的柴火问题）。墙不吃木头，见“材料”。
- 院子被改坏：铺位、灶、饭桌、杂物堆跑出墙外，院门口被堵。
- 老存档读不了，或读进来墙和东西错位。
- 在 500px 宽的 codeg 内置浏览器里没法画墙。

## 约束（现有代码）

- 地图不是格子，牌自由摆放。寻路用 40px 的格子（`mapgen.js` 的 `CELL`）。墙是 `MAP.blocks` 里的矩形：寻路时墙碰到的格子都不能走，直线行走用线段和墙矩形求交（`crossesWall`）。
- 院子（`MAP.house`，560×640）和仓房（`MAP.barn`）是两个带南门的矩形：墙由 `wallsOf` 生成，围栏画在地形画布上（`terrain.js` 的 `paintFence`），屋顶是一个 div（`roofOver`），你走进去时掀开。
- 很多逻辑认 `MAP.house` 这个矩形：铺位位置（`board-layout.js` 的 `BED_SLOTS`）、院里摆设、`inYard`（冬夜取暖等）、杂物堆不出墙。
- 盖房的手艺、领着干、跟着学、失手重来都在 `building.js`（`buildSession`/`helpSession`/`LEAD`），可以沿用。
- 村民的活由 `npc-mind.js` 打分挑选，派活在 `app.js`。
- 用户的存档：第 64 天，三个村民，盖过粮窖、木箱、日晷竿、地窖，没有盖过大屋/仓库/窝棚。

## 做法（Approaches）

| 做法 | 是什么 | 取舍 |
| --- | --- | --- |
| **A. 隐形格子 + 一段段墙**（用户选定） | 建筑格子铺满地图，墙沿格子线，封闭区域自动成屋 | 最像环世界：L 形、凹字形、屋内隔墙、拆墙打通都能做。工作量最大，村民设计形状要专门教。 |
| B. 长方形拼屋 | 每间屋一个长方形，贴着放就共用墙、自动开门 | 省事，沿用现有矩形代码；只能是长方形拼接。 |
| C. 可调大小的地基牌 | 保留地基牌，只是能拉大小 | 用户明确不要地基牌，已排除。 |

用户选 A。村民自己扩建时，仍然先划长方形的屋（一圈墙），这只是村民的选法，墙本身仍是 A 的一段段墙。

## 怎么做（已定的部分）

### 格子与墙段
- **建筑格子 80px**，和 40px 寻路格对齐（一个建筑格 = 2×2 寻路格）。牌是 112×148，一个铺位大约占 1.5×2 个建筑格。院子 560×640 = 7×8 格。*（我的决定：比 40px 好拖、好看，比 120px 灵活。）*
- **墙段** = 一条格子边（横或竖，长 80px）。墙厚 14px，压在格子线上。寻路照旧用矩形：同一直线上连着的段合并成一个矩形放进 `MAP.blocks`。
- **门** = 一段特殊的墙：围合时算墙，人可以走（门那一段不放进 `MAP.blocks`）。一扇门 80px 宽，正好两格寻路格，按现有的严格判定能走。*（我的决定。）*
- 每段墙有状态：**蓝图 → 在盖（已交料、有进度）→ 立好**。门同理。

### 材料（我的决定，留给实跑调平衡）
- 泥墙一段（篱笆糊泥）：芦苇 1 + 黏土 1，工时 60 分钟。不用木头，免得又去砍光林子。
- 门一段：木头 1 + 麻绳 1，工时 60 分钟。
- 屋顶：每 2 格要芦苇 1，每 4 格要麻绳 1；工时每格 20 分钟。
- 对照：一间 3×3 的卧房贴着院墙接出去，约 9 段新墙 + 1 扇门 + 9 格屋顶，合计芦苇约 14、黏土 8、木头 1、麻绳 4。和原来窝棚的用料同一个量级。
- 冬天不和泥：冬天墙和屋顶都停工（沿用 `thaw` 的意思），门可以装。

### 成屋与上顶
- 每次有墙立好或拆掉，就在建筑格上做一次泛洪：从一格出发，被立好的墙或门挡住就停，碰到地图边或范围超过 80 格就算“外面”（院子 7×8=56 格要算得进去）。没漏出去的连通区域就是一间屋（只算立好的墙，蓝图不算）。
- 一间屋刚围好时，自动出现“上顶”的活（像环世界自动铺顶）：屋上方显示虚线屋顶，需要的料和工时见上。上了顶，这间屋才算“屋里”。
- 屋顶画成按格拼出的形状（一组矩形或一条路径），用现在 `.roof` 的样子。你走进这栋房子（门连通的几间屋）时，整栋的顶都掀开。*（我的决定：比只掀一间清楚。）*
- 拆掉一段墙让屋漏开时，这间屋的顶也拆掉，料退回一半到杂物堆。

### 房间名字（自动）
- 按屋里的东西给名字，优先级：灶 → 灶房；铺位 → 卧房（铺位上写着谁睡，名字就叫“阿三的屋”）；粮囤或材料堆 → 仓房；饭桌 → 堂屋；什么都没有 → 空屋。原来的院子永远叫院子，原来的仓房叫仓房。
- 名字显示在屋顶上（顶掀开时显示在屋里的地上），点开屋里的东西时也写“在灶房里”。

### 屋里的作用
- 冬夜取暖：`coldTick` 里的 `inYard(p)` 换成“在有顶的屋里”。
- 下雨：村民躲雨走最近的有顶屋（现在是去火塘）。
- 铺位：新扎的铺位，先放进有空位的卧房，再放空屋（空屋放了铺位就成了卧房）。院子原来的 4 个铺位照旧。每间屋的铺位沿墙排，算法和 `BED_SLOTS` 一样：按屋的形状沿北墙、西墙摆，不压门口。
- 吃的放在有顶的屋里，保鲜时间和放在仓房里一样。*（我的决定，沿用已有的仓房规则。）*

### 玩家怎么画（窄屏也能用）
- ☰ → 手艺本 → 盖房 → 进入“规划”模式。屏幕下方一条小工具栏：**画墙 / 围一间 / 开门 / 取消·拆 / 完成**。规划时地上显示建筑格子的淡网格（只在附近一屏范围画）。
- 画墙：按住拖动，按起点到当前点的主方向吸附成一条横线或竖线。松手生成一串墙段蓝图。
- 围一间：拖一个框，生成四周的墙段；和已有墙重合的段跳过。
- 开门：点一段墙（蓝图或已立好的），切换成门或改回墙。已立好的墙改成门，算一次小改造（要门的料和工时）。
- 取消·拆：点蓝图就删掉；点立好的墙，就成为一个“拆”的活（要锤子，退回一半料）。
- 不能放的地方：水、山崖、出地图、压着建筑或泉眼一类固定的牌；挡住院门口（沿用 `beforeGate`）。人和散放的东西可以压着，墙立起来时挪开。
- 地上已经有不能被墙压的牌（比如铺位）时，提示“这儿压着铺位，挪一挪”。

### 施工（你和村民）
- 蓝图墙段本身就是可以交互的东西（不是一张牌）：把“你”拖到一段蓝图墙上，就把手里合用的料交进去；料齐了就开始干，干完自动去旁边下一段同一批的墙（像现在的 `st.repeat`）。
- 实现上，每段蓝图可以挂一个不显示牌面的轻量“堆”（比如 `wallPlan` 类型），这样现有的 `go(st, key, task, want, stack)`、`supplyPlot`、`workPlot` 那一套能复用。这一点交给实现者决定。
- 村民：一次规划（同一次拖出来的一批段）当成一个工地。会立墙的村民领着干，不会的搭手学（复用 `buildSession`/`helpSession`、`npcSkill`、`LEAD`）。送料的人一次背满，挨着交给最近还缺料的几段。手艺叫“立墙”，阿三一开始会。
- 墙立起来时，压在那条线上的人往屋里或屋外让开，散放的东西挪到旁边（复用 `settleMisplaced` 的思路）。

### 村民自己扩建
- 理由（每天想一次，同时只有一个扩建计划）：
  1. 屋里的人比铺位多，现有屋子里摆不下新铺位 → 接一间卧房（3×3）；
  2. 有人成了家，还没有自己的屋 → 给他们接一间（3×3），铺位挪过去；
  3. 仓房的材料堆摆不下 → 接一间仓房（4×3）。
- 选地方：贴着现有房子的一面外墙，新屋和老屋共用那面墙，在共用墙上开一扇门。要求：地是平的；不压牌；不挡院门口和路；离田、林子留出余地。候选位置打分：离院门近、少新墙段、地平。
- 谁来：会“立墙”的人（手艺 ≥ `LEAD`）。秋收和冬天不开工。
- 先说一声：村史写“阿三说院子挤了，在东墙外划了一间新屋”，并在他身边冒一句。蓝图出现后，你可以用“取消·拆”去掉它；村民这一季不再提同一件事。
- 料不够时，按现有的 `gathererProject`/`supply-plot` 去备料（芦苇、黏土），排在吃饭、收成之后。

### 原有房子和老存档
- 读档时把院子和仓房的围墙换成墙段：贴到最近的格子线上（最多挪 40px，里面的东西跟着挪），院门和仓房门各换成一段 80px 的门（取离原门中心最近的那段；院门口的过道和 `beforeGate` 改用这段门的位置），两间都是已上顶的屋。*（我的决定：原院门 120px 不是格子的整数倍。）*院子的墙仍画成现在的木栅栏样子（墙段带一个 `look` 字段：`fence` 或 `mud`）。
- `MAP.house` 继续保留，指院子那间屋的外框，现有用它的代码（铺位位置、院里摆设、杂物堆）照旧能用。屋子相关的新判断（取暖、躲雨、铺位）改用新的屋子数据。
- 建造菜单里去掉大屋、仓库、窝棚，用画墙代替。木箱、地窖、粮窖、堆肥坑、日晷竿、开荒、船照旧用地基牌，它们是“东西”不是“屋”。
- 存档里已盖好的大屋/仓库/窝棚（用户存档里没有）原样保留；没盖完的地基照旧能盖完。
- 新存档字段：`village.build = { segs: [...], roofs: [...], plans: [...] }`，带版本号。墙段记格子坐标、方向、种类（墙/门）、样子、状态、还缺的料、进度、属于哪次规划。屋子不存，读档后重新算。

### 画面
- 墙画在地形画布之上、牌之下的独立一层（canvas 或 SVG），立好一段只重画这一层，不重画整张地形。蓝图是半透明虚线，在盖的按进度由矮到高（越来越实），立好的是泥墙色（院墙保持木栅栏）。
- 门画成门框和一扇门板，开着的样子。
- 新屋的地面和院子一样铺木板（地形层，屋子变化时只补画那几格）。

### 代码组织
- 新建纯规则模块 `walls.js`：格子换算，墙段的键，拖动转成墙段，合并成寻路矩形，泛洪找屋，屋的名字，屋顶用料，扩建选址（输入是格子占用和现有屋子，输出是一批墙段和门）。配 `tests/walls.test.mjs`。
- `app.js` 负责：存读档、画面、规划 UI、把蓝图挂成可交互的东西、村民派活、取暖/躲雨/铺位接新的屋子数据。
- 文档：`DESIGN.md` 新一节，`README.md` 文件表加 `walls.js`。

## 分批做（顺序）

1. `walls.js` 和测试；把院子、仓房换成墙段（寻路、画面、存档）。玩起来应该和现在一模一样。
2. 玩家规划 UI 和自己施工；村民送料、领着盖、跟着学。
3. 成屋、上顶、掀顶、房间名字；取暖、躲雨、铺位接到新屋。
4. 村民自己扩建。
5. 拆墙、改门、扫尾；在预览档（`?day=1&seed=7`）里跑一年，再用用户存档的副本跑几天，查有没有穿墙、卡住、柴火或芦苇被抢光的情况。

每一批都要能玩、测试全过、不坏老存档，写进 DESIGN.md。

## 留给实现者的

- 墙段数据的具体字段名、寻路矩形怎么合并、画墙那一层用 canvas 还是 SVG。
- 蓝图怎么挂成可交互的“堆”。
- 各段工时和材料数，以实跑调出来的为准（上面是起点）。
- 屋顶形状怎么画好看。
- 村民扩建选址的打分细节。
