# 像素地图美术工作规范

适用：地图场景、像素素材、人物/植物动画、镜头和遮挡。目标是复现已经认可的画面方向，并通过小步对照改善。规则引擎与正式客户端接入仍遵守 [协作指南](../AI_COLLABORATION.md) 和 [玩家路径验收](../PLAYER_PATH_ACCEPTANCE.md)。

## 先读基线，再动手

当前认可基线是 **v6 林缘庭院**。用户于 2026-10-25 评价“现在这个还可以”，认可范围是画面方向，不代表地图、规则或全部素材已经验收。

- [认可画面](../../tools/art-lab/baseline/accepted-v6.png) / [原生画面](../../tools/art-lab/baseline/accepted-v6-native.png)。
- [可运行样例与复现方法](../../tools/art-lab/README.md)：独立工具，不接入正式服务。
- [素材、原生尺寸、裁切、落点与来源](../../tools/art-lab/asset-manifest.json)：参数的唯一机器可读来源。
- [原始视觉参考](../../tools/art-lab/baseline/user-reference.png)：仅作美术观察，不能当作游戏底图。
- v7 是在 v6 上增加动作与交互的**候选版本**；用户认可后才提升基线，保留旧图和版本记录。

基线的主要特征：横屏，人物是一个在世界中生活的人；灰绿/苔绿与暖土色互相衬托；安静地表承托细碎植被；树下与墙脚有地被衔接；前景偏冷暗、中景清楚；道路与可操作空地易读。后续任务保留这些特征，仅调整本轮指定问题。

用户的新指令与认可画面优先。旧版美术规格里的色数、饱和度、镂空比例、粒子数量等具体数值属于调参建议，不能据此把认可画面整体压色、变暗或改成另一种像素风。

## 每轮执行顺序

| 步骤 | 动作 | 完成条件 |
| --- | --- | --- |
| 1 恢复上下文 | 核对当前分支、未提交改动、基线和任务范围；明确正在被其他人修改的文件 | 记录基线、允许修改路径、本轮 1–3 个问题；保留别人的改动 |
| 2 固定对照 | 读取认可图、原始参考和当前实际画面；固定镜头、季节、天气、对象位置与动画时刻 | 有一张真实的改前图及拍摄条件；缺少历史条件时说明比较边界 |
| 3 局部试做 | 先做房屋一角、树、路边植物等小组合，改变一个主要变量 | 能指出改动解决了哪个可见问题；保留独立素材和原件 |
| 4 放回场景 | 以清单中的原生尺度、落点、遮挡和光向接入统一画布 | 原生视图、整数倍视图都可辨认；材质和接地关系协调 |
| 5 检查动态 | 走动、风动、选中、采摘、遮挡和取消；保存固定时刻截图 | 相关操作真实可执行，结果可观察；副作用与未覆盖项写清 |
| 6 对照交付 | 比较同镜头改前/改后，完成下述视觉与技术检查 | 交付可运行入口、图片、源素材/清单、检查结果和待完善项 |

授权范围内继续迭代，候选不覆盖认可基线。小样与正在开发的客户端保持隔离；接入生产代码时再明确文件负责人、接口和验证范围。

## 素材与世界对象

### 分层职责

| 层 | 放什么 | 交付形式 |
| --- | --- | --- |
| 地表 | 裸土、低矮草坪、砂、泥等平面材质 | 独立地表材质；平铺接缝单独验收 |
| 地表覆盖 | 道路、踩踏、湿润、耕地、落叶等 | 可独立更新的覆盖数据/材质 |
| 独立物件 | 房屋、树、灌木、直立花草、栅栏、容器、工位 | 有稳定 ID、地面落点、原生尺寸和状态的对象 |
| 遮挡部件 | 树冠、屋顶、前景墙体 | 可独立处理透明度与排序的部件 |
| 光照/表现 | 接触阴影、投影、天气和少量粒子 | 与对象或场景条件关联，记录参数 |

低矮草坪是地表；直立花株、高草和可采集植物是独立对象。修改、采摘或移动一株植物后，其他对象的位置、身份和动画相位保持稳定。动画相位与自然散布绑定稳定 ID/种子，不绑定数组索引或 `Math.random()`。

房屋先验证比例，再拆墙、屋顶、门与工作锚点。树按地面落点排序，碰撞边界以树干/墙体等真实障碍为依据；树冠属于遮挡，不能用整张 PNG 矩形代替碰撞。正式规则由权威模拟决定，画面不自行创造库存或交易资格。

### 生成或绘制素材

调用图像工具前明确：参考图、编辑目标、输出素材分别是什么。复用 [提示词模板](pixel-art/ASSET_PROMPTS.md)，每个对象单独交付；整幅概念图只用于构图，不代替可拆分地图。

每个素材登记：`source`、原图路径/哈希、有效裁切、原生尺寸、脚底/枢轴、光向、变体/动画帧、透明度处理、来源及状态。尺寸记为逻辑像素，区分“工具生成图的分辨率”和“游戏原生显示尺寸”。

先看形状与比例，再看明暗，最后加纹理。密度有主次：地面和主要路径安静，树冠/灌木局部细碎，人物及关键入口有可读对比。材质纹理不均匀铺满全屏；生成工具输出仍需在原生尺寸检查，不能凭大图漂亮就批量生产。

保留源 PNG。透明素材在至少两种底色上检查边缘、细枝和空洞；阈值处理可能误删细节，必须逐素材确认。动画先验头身比例、衣服、帧尺寸和脚底基线，再验动作；不要将左右镜像的单朝向循环写成完整四向动作。

## 像素网格与渲染

1. 物件先进入原生像素缓存，世界层在同一逻辑画布上绘制；尺寸可以不同，最小绘制单位相同。
2. 固定整数落点和原生绘制尺寸，最终画布使用最近邻整数倍显示。镜头靠近通过裁取更小的世界范围实现，避免每个 DOM 物件各自缩放。
3. 缩采样只在准备缓存时发生。运行中保留原生尺寸；原生像素精修优先于反复缩放高分辨率仿像素图。
4. 摆动使用原生帧、整数像素行偏移或在统一画布内完成的变形；避免连续 CSS 旋转/斜切造成局部模糊。
5. 共用网格不要求全屏只有固定少量颜色。保留材质的冷暖与必要过渡，色板约束应服务于画面。
6. 根部稳定、树干底部固定；遮挡人物时局部淡出树冠/屋顶，保持人物位置可判断。
7. UI 使用清楚的正常文字与触区，不随世界画布降采样。只在选中或需要决策时显示说明，同时保留成本、拒绝理由和结果。

画布在屏幕上的起点也按设备像素对齐。滚动条或奇数宽度容器可能让自动居中产生半像素偏移；“2 倍显示”本身不能排除这类问题。截图时固定视口并保持布局不变，优先让画布完整处于视口内，避免扩大页面捕获时重新居中。以实际显示截图复核，不只检查 Canvas 导出。

本例的 768×432、树和人物尺寸是可复现参数，不是全项目永远不能变的常量。变更尺度时更新清单、对照画面与相关动画，先证明比例和细节仍然协调。

## 验收：视觉、像素、操作分别判断

### 视觉检查

- 同镜头下，人物/入口/道路在实际显示尺寸仍容易找到。
- 地面不会抢走人物和关键物件的注意力；树叶不是圆球、筛网或均匀噪点。
- 房屋、树、灌木、地面光照互相衔接，物件不显得浮在地毯上。
- 前中后景有层次；阴影与同屏物件光向一致，暖色不铺满全屏。
- 动作中头身比例、服饰和脚底基线稳定，没有忽胖忽瘦、闪边或滑步。
- 对照认可基线指出具体改进与退步；不能用“更高级”“更有氛围”代替观察。

### 技术与操作检查

参考样例 [README](../../tools/art-lab/README.md) 的复现命令。它分别提供：源图哈希检查、道路运动测试、浏览器操作截图和整数倍像素检查。

像素检查脚本会逐块比较原生图与显示图，能发现非整数缩放、平滑重采样和截图偏移。它不能证明素材风格统一、构图好看或游戏已完成。原生图和显示图必须来自同一次静止捕获；动态帧错位时先固定条件，不修改比较阈值掩盖问题。

面向玩家的功能仍走入口→条件/代价→行动→可观察结果→返回或恢复。截图、规则测试、桌面模拟、真机操作分别报告。未运行正式服务的小样，不能写成已接入 OpenLife。

## 交付与接手

一次交付至少包含：

```text
认可基线 / 当前候选版本：
允许修改范围 / 本轮具体问题：
同镜头改前图 / 改后图 / 原生图 / 动态入口：
源素材与清单位置 / 修改的资产 ID：
实际检查命令、结果与截图条件：
视觉上的改进、退步、未覆盖项：
小样与正式客户端的接入边界：
下一位可以直接执行的第一项工作：
```

优先复用完整样例而不是从一张截图猜实现。交接应使他人能在新检出目录中重建预览；避免只引用某个人电脑的临时路径。新版本保留旧基线，通过用户反馈决定是否提升，不以作者自评覆盖已认可画面。

## 通行与默认界面（2026-10-25 修订）

- 道路覆盖仅决定地表外观，不能直接充当可行走掩码。草坪、裸土和树冠下的空地默认可通行。
- 碰撞采用相对脚底锚点的真实占地：房屋基底、树干、围栏，并给人物留出宽度。树冠、直立花草不因图片大小挡路。独立小样参数在清单 `colliders`，正式客户端以权威地图规则为准。
- 正常点击空地即行走，包括树冠遮住的地面；植物点击可展示短操作。不能要求玩家按 Shift 才走进草地。
- 默认只显示场景与小设置入口；说明、参数、检查图、摆放等留在按需展开的工具或独立文档中。
- 验证要包含实际点击草地到达、绕过障碍、拒绝墙内目标、树冠透明、采摘，以及整倍截图。单测通过不等于美术贴近参考图。
