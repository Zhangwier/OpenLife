「乱」不是审美问题，是**六个具体的实现缺陷**叠在一起：状态压在标题上、一屏四条起跑线、三处赭石竖条、禁用按钮在深色下读不出、两套色板各写各的、死人 CSS 还在覆盖活样式。这一轮把这六件都修了。

## 1. 修掉的六个真实缺陷

### 1.1 此刻页的阅读顺序是错的

**现象**：打开「此刻」，先看到的是「今日指引」卡片，然后是一排状态，再往下才是"你在哪"，动作按钮又在三段文字之后。

**根因**：`order` 散落在 6 条规则里（状态条 `-1`、dock `1`、叙事 `2`、心愿 `3`、明细 `4`），彼此冲突，谁也说不清最终顺序。

**改法**：在 `theme.css` 一处定义整条阅读顺序：

```css
#screen-activities .scene-header      { order: -5; }  /* 你在哪 */
#screen-activities .scene-summary     { order: -4; }  /* 肚子 / 今天 / 身上 */
#screen-activities .scene-theater     { order: -3; }  /* 画 */
#screen-activities .interaction-dock  { order: -2; }  /* 能做什么 */
#screen-activities #lifeLog           { order: -1; }  /* 人生纪事 */
#screen-activities #communityFeed     { order:  0; }  /* 身边的事 */
#screen-activities #hopes             { order:  1; }  /* 心里记着的事 */
#screen-activities .scene-ledger      { order:  2; }  /* 明细 */
```

并删掉那 6 处零散的 `order`。**规则：以后 order 只在这一个块里写。**

### 1.2 一屏出现四条"起跑线"

**现象**：桌面上今日指引左边缘在 371、卡片在 388、正文在 420、动作区又回到 388。

**根因**：三个块分别用 `max-width: 760 + margin: auto`、正文用 `max-width: 640 + margin: auto`、另两个满宽，各自居中。

**改法**：只在 `.life-stage` 这一层定宽 760 并居中；正文类块（纪事/身边的事/心愿）保持 640 但**靠左对齐**，不再二次居中：

```css
@media (min-width: 900px) {
  #screen-activities .life-stage { max-width: 760px; margin-inline: auto; }
  #screen-activities > .daily-guide { max-width: 760px; margin-inline: auto; }
  #screen-activities .life-log,
  #screen-activities #communityFeed,
  #screen-activities #hopes { margin-inline: 0 auto; }
}
```

顺带给 `.page-container` 加了 `max-width: 1000px`——原来一张行囊卡横跨 947px，一行 90 多个汉字。

### 1.3 叙事被关进卡片

**现象**：「身边的事」「人生纪事」「心里记着的事」是三张带边框、圆角、阴影、左侧 3px 彩色条的卡片；一屏三段竖条。

**改法**：三段全部改成**软底**（上下渐隐、无边框、无圆角、无阴影），只有「人生纪事」是话本主体：

```css
.life-log {
  background: linear-gradient(180deg, var(--bg-fade-0) 0%, var(--bg-fade-55) 12%,
                                       var(--bg-fade-55) 88%, var(--bg-fade-0) 100%);
  border: 0; border-radius: 0; box-shadow: none;
  max-width: var(--measure); margin-inline: auto;
}
```

依据：Disco Elysium / 80 Days / Pentille / Sunless Sea 四款文字游戏，没有一款把阅读区放进带边框的卡片。

### 1.4 HUD 违反自家规范（最重要）

**现象**：`饥饿 0/10 · 今日活动 8/8 格`，还有 6px 进度条、8 个格子、红色警示。

**根因**：`settlement.js` 的 `hudMeter()` 把数值、进度条、颜色一起渲染出来，与 DESIGN.md 的三条规则正面冲突（不看数字 / 不用进度条 / 一屏朱砂 ≤1 处）。

**改法**：删掉 `hudMeter`，改成"一句话"：

| 状态 | 0–2 | 3–5 | 6–7 | 8–9 | 10+ |
| --- | --- | --- | --- | --- | --- |
| 肚子 | 吃得饱 | 有点饿 | 空着肚子 | 饿得发慌 | 眼前发黑 / 饿病了 |
| 今天 | 一整天都在 | 还能做几件事 | 还能做一点 | 今天做不动了 | — |
| 身上 | 背得动 | 背得动 | 有点沉 | 背不动了 | — |

颜色只在 `watch`（赭石）与 `warn`（朱砂）两档出现；完整数值（`饥饿 3/10`、`还剩 5 格`）保留在 `.sr-only` 里给读屏，也保留在 `title` 里给悬停。

同样处理了「行囊」：`随身 装得下` / `负重 背得动`，不再写 `2/6 件`。

### 1.5 「故事」页和「图鉴」页各用一套色板

**现象**：
- `stories.css` 写死 `#b4483b`、`#c99a2e`、`#3e7a6b` 三个**新色相**，标签像贴纸；
- `codex.css` 写死 9 个色值，还引用了**根本不存在的 `var(--gold)`**，深色模式下白底黑字。

**改法**：两个文件重写，只走令牌；禁用态从 `opacity: .5`（深色下直接读不出）改成**虚线边 + 灰字 + 下方原因**；标签只用 primary / accent / danger 三档语义色。

### 1.6 死人 CSS 与缺失样式

- **`revamp.css` 从没被任何文件引用**（`git log` 显示是两次改版的叠加产物），里面还有一套深蓝 HUD。已删除。
- **职位面板 `office-panel.js` 的 `.office-*`、`.choice-list` 六个类名在任何 CSS 里都不存在**，"断事"的按钮直接挤成一团。已在 `scene.css` 补齐（含印章在位时禁用动画）。

## 2. 视觉令牌的收敛

| 项 | 改前 | 改后 |
| --- | --- | --- |
| `font-size: Npx` 种类 | 17 种（含 9/10/11/15/18/21/22/27） | **9 种，全在 10 档阶梯内** |
| `var(--fs-*)` 使用 | 7 处 | **74 处** |
| 非 theme/stage 硬编码颜色 | 26 处 | **0 处** |
| 新增令牌 | — | `--fs-fine`(13) `--fs-card`(28) `--glass-solid`(.98) `--glass-soft`(.82) `--scrim-deep`(.58) `--hairline` `--scene-dim` / `--scene-dim-night` / `--scene-dim-behind` |
| 死代码 | `revamp.css` 4172 字节 | 删除 |
| 图标 | 顶栏音乐用文字 `♪` | 换成与其他按钮同一套 `music` 线性图标 |
| 导航 | 手机底栏 `repeat(4)`，但实际 5 个按钮 | `repeat(5)`；缺图标的「故事」补上图标 |

**场景压暗**也进了令牌：常亮 `brightness(.94)`、夜间 `.82`、抽屉打开时 `.72`，都在 `--scene-dim*` 里，不再各处写死。

## 3. 新增的自动检查

`scripts/design-check.ts` + `npm run design:check`，并挂进 CI：

```bash
npm run design:check
# 字号分布：12px×57  13px×44  14px×33  16px×20  17px×1  20px×6  24px×13  28px×4  44px×2
# var(--fs-*) 使用：74 处
# 唯一 box-shadow：23 种
# 设计令牌检查通过
```

三条规则：字号必须在阶梯内；theme/stage 之外不许写死颜色；注释里保留的历史色号不算违规（脚本会先抹掉块注释）。
