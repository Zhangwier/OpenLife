# 01 · A 组：桌面模拟 / 经营 / 人生类逐款拆解（14 款）

> 这一组是与 OpenLife 同品类的主力借鉴对象。每款按统一字段记录，末尾给出「可迁移做法」与「不学什么」。
> 所有评价区分「官方/开发者可确认」与「观察推断」，推断部分标 `(推断)`。

## A01 · Crusader Kings III 十字军之王 3（PC｜大战略/角色模拟｜2020）

**一句话**：把「解释」做成了一种界面语言——一切词都能再展开。

- **屏幕清单**：主地图视图（常驻）、角色视图、家系树、议会议题、事件弹窗、派系、宗教/文化、地图模式、百科全书。
- **L1 信息架构**
  - 常驻入口：地图顶部资源条 + 左侧角色卡 + 底部 8 个图标入口。视觉极简，但可点的东西极多。
  - 层级深度：最深约 4 层，但**主要靠"弹层嵌套"而不是"页面跳转"**。
  - 归档方式：**按对象归档**——一切都是"某一个角色/某一块地"的属性，同一对象在任何入口点开都是同一张卡。
  - 渐进展开：新手被"建议"引导，系统全量存在但用提示框降温。
- **L2 布局**：主视图可见面积最大化；面板都是"浮"在地图上的半透明深色块，边框用金属/羊皮纸质感。
- **L3 颜色**：**主色只有深棕底 + 金色强调两种色系**；正/负向修正用绿/红；文字基本是米白。中性色阶极多（堆叠面板需要）。
- **L4 字体**：衬线衬底的古典字体（近似 Trajan 风格大写）+ 高可读无衬线正文；数字用小型装饰。
- **L5 透明度与融合**：**深色面板 + 0 模糊（不毛玻璃）**，靠黑色半透明（约 0.85–0.92）+ 细金线描边压住复杂地图。地图本身不加暗角，靠面板"贴"上去。嵌套提示框每次出现都**略微缩小并右移**，形成"俄罗斯套娃"的层次感。
- **L6 动效**：几乎没有转场动画；弹框 150ms 淡入；重点是"静态可读"。地图缩放用滚轮 + 惯性。
- **L7 可访问性**：可缩放 UI；文本尺寸可调；社区长期抱怨"信息密度过高"，官方通过"新手提示框"和"简化地图模式"缓解。
- **可迁移做法**
  1. **词条嵌套最多 3 层**，每层缩进 + 描边变浅(→ `Glossary` 组件已有此规则，可对齐层级视觉)。
  2. **同一对象在任何入口点开都是同一张卡**（→ 人物志 / 人物头像牌的统一数据源）。
  3. **正/负修正双编码**：颜色 + 箭头/文字，不只靠色。
  4. 面板"贴"在场景上而不是"推走"场景（→ 抽屉覆盖层，不做页面整体跳转）。
- **不学什么**：全暴露的巨量信息；金属描边与羊皮纸纹理（与我们的「纸墨木陶」冲突）；它的数字体系。

> 参考：[Tooltips in tooltips（Philip Kilby 的界面分析）](https://philip.design/blog/tooltips-in-tooltips/)、[CK3 Wiki · Interface](https://ck3.paradoxwikis.com/Interface)

## A02 · Victoria 3 维多利亚 3（PC｜大战略/社会模拟｜2022）

**一句话**：提示框不只是解释词，还用来**拆解一个数字是怎么算出来的**。

- **屏幕清单**：地图主视图、国家面板、市场、政治（派系/法律）、人口、科技树、外交、事件弹窗、结算/历史。
- **L1 信息架构**：左侧固定 8 个一级标签；每个标签内部是"列表 + 详情双栏"。层级 3 层。
- **L2 布局**：左列表（宽约 380）+ 右详情（弹性）；地图作为背景保留，永远不完全消失。
- **L3 颜色**：深灰蓝底 + 橙/黄强调（维多利亚时代印刷感）；绿/红表示涨跌 + 箭头。
- **L4 字体**：衬线标题（报纸感）+ 无衬线正文；数字用等宽感字体便于竖排比较。
- **L5 透明度与融合**：**面板底部渐隐到地图**（顶部实、底部虚），让"列表不是一个盒子而是从地图里长出来的"；模态时地图压到 0.4 亮度。
- **L6 动效**：列表换页 160ms 交叉淡入；数据变化用数字滚动（≤400ms）。
- **L7**：UI 缩放；文字大小三档；大量悬浮提示降低记忆负担。
- **可迁移做法**
  1. **"为什么"分解面板**：点击任意一句话里的数值/判断，展开 2–4 条成因（→ 村史「为什么」、行动失败的「因为它饿了三天」）。
  2. **面板底部渐隐接地**（→ 手机底部抽屉顶端加 24px 渐隐，去掉"盒子感"）。
  3. 地图/场景永不消失，只被压暗（→ 抽屉打开时场景 `brightness(.7)` 而非替换）。
- **不学什么**：表格化的数据密度；报纸拼贴风（可以借鉴"纸"，但不要印刷噪点满屏）。

## A03 · RimWorld 环世界（PC｜殖民地模拟/叙事生成｜2018）

**一句话**：**"一瞥即知"（at-a-glance）**——用最小的面积传递最多的状态。

- **屏幕清单**：殖民地地图（常驻）、殖民者条、需求/社交/健康三页、工作优先级、研究、世界地图、事件信、故事讲述者设置。
- **L1 信息架构**
  - 常驻入口：底部 20+ 个图标（建筑、区域、研究、囚犯、动物…）+ 顶部殖民者头像条 + 左上资源列表 + 右上警报。
  - **归档方式：按动词**（建、划区、研究、派工），而不是按对象。
  - 渐进展开：**全暴露**，靠「学习助手」（右上黄色提示）逐步教育。
- **L2 布局**：地图占满；所有面板都是**贴边的小浮层**，不遮挡中心视野。
- **L3 颜色**：**土黄/橄榄底 + 朱红警报 + 蓝心情条**；中性色阶很少，靠材质纹理（粗糙纸质）区分。
- **L4 字体**：全无衬线（Arial 类），**字号偏小**——这是它被批评最多的一点（中文版尤其）；社区长期靠 mod 改字号。
- **L5 透明度与融合**：左上资源列表**透明**（直接压在地图草地上，无底板），文字加 1px 深色描边保证可读——这是"低干扰"的经典做法；面板 0.92 半透明 + 1px 亮边。
- **L6 动效**：几乎无转场；警报图标轻微脉动（周期约 1s）；心情变化用条缓慢移动而非数字跳变。
- **L7**：UI 缩放可调（但默认偏小）；无屏幕阅读器；颜色区分心情（糟糕设计，社区靠 color-coded mood bar mod 补）。
- **可迁移做法**
  1. **无底板 + 描边文字**：把"时间/地点/天气"这类常驻信息直接压在场景上，只加 1px `rgba(0,0,0,.35)` 文字描边（→ 手机顶部信息条）。
  2. **殖民者条**：头像 + 名字 + 一个状态小方块，点击定位（→ `PersonChip` 头像牌：名字 + 一个文字状态「在忙/生气」）。
  3. **心情条 + 目标三角**：真实值缓慢追赶目标值，让玩家看到"正在变好"（→ 用"仓里的粟在少"这类文字，加一个缓慢的渐变底色表示走势）。
  4. **警报集中在右上**，按严重度排序（→ 手机改为"心事条"列表）。
- **不学什么**：底部 20 个图标平铺（手机绝不可行）；小字号；只靠颜色编码。

> 参考：[RimWorld Wiki · User interface](https://rimworldwiki.com/wiki/User_interface)、[Mood](https://rimworldwiki.com/wiki/Mood)

## A04 · Dwarf Fortress 矮人要塞（Steam 版）（PC｜深度模拟｜2022）

**一句话**：一个 20 年 ASCII 游戏怎么做"可视化改造"——**保信息、换皮、不换结构**。

- **屏幕清单**：要塞地图（多 Z 层）、单位列表、物品/库存、工作订单、军事、 nobility、传说模式（Legends）、世界生成。
- **L1 信息架构**：底部固定标签栏 + 左侧上下文面板 + 右侧通知；**同一屏里"看/做/查"三种模式并存**。
- **L2 布局**：地图居中，四边"框"起来（上下左右都有条），像一张被纸框住的画——**这是文字/模拟游戏里"框式布局"的典范**。
- **L3 颜色**：暗棕灰 + 少量高饱和（魔法/危险）；界面几乎全部低饱和，让地图成为唯一色彩来源。
- **L4 字体**：**像素化点阵字体 + 少量装饰大写**；Steam 版为可读性把字号整体放大，并保留"传统 ASCII"开关。
- **L5 透明度与融合**：面板基本**不透明**（这是它"看起来像个工具"的原因）；地图边缘有强暗角，把视线压到中心。
- **L6 动效**：几乎没有；全靠文字与图标静态更新。
- **L7**：提供"现代 UI / 经典 UI"开关；但键盘快捷键重排被玩家批评"不符合人体工学"。
- **可迁移做法**
  1. **"框式布局"**：四边各一条功能带，中间是画（→ 电脑三栏可理解为左右框 + 中间画，比"浮窗"更稳）。
  2. **保留"传统/现代"双呈现开关**（→ 文字版 / 场景版双模，我们已有 `view-mode.js`，可作为既有资产强化）。
  3. **暗角把视线压到中心**（→ 场景舞台的 vignette 层）。
- **不学什么**：不透明面板（我们场景要透出来）；ASCII 隐喻（我们的纸墨感更合适）。

> 参考：[RPS · Dwarf Fortress's new UI](https://www.rockpapershotgun.com/dwarf-fortresss-new-ui-looks-so-beautiful-i-could-cry-despite-still-looking-like-this)、[社区对快捷键的批评](https://www.reddit.com/r/dwarffortress/comments/1b2zite/ill_be_honest_theres_a_lot_of_problems_with_the/)

## A05 · Stardew Valley 星露谷物语（PC/主机/手机｜农场生活模拟｜2016）

**一句话**：**同一套"木质框 + 羊皮纸"皮肤，覆盖所有界面**——一致性靠"材质"而不是"组件库"。

- **屏幕清单**：农场（常驻）、背包（Tab）、技能、社交（关系）、地图、任务日志、日历、商店、对话、节日、结算、设置、语言。
- **L1 信息架构**：常驻只有时间/金钱/日期（右上）+ 快捷栏（底部）；**所有功能收进一个"背包 Tab"里的 6 个页签**。
- **L2 布局**：背包页采用"左人物立绘 + 右内容"的固定两栏；格子 12×3。
- **L3 颜色**：木棕 + 米黄 + 草绿，**暖色为主，无冷色强调**；价值/品质用星星颜色区分。
- **L4 字体**：**像素字体**贯穿全部（包括中文汉化后换成的点阵），字号基本只有 1–2 档。
- **L5 透明度与融合**：**不透明纸面**，但纸面有手绘边框和不规则边缘（不是圆角矩形）；打开背包时**世界停住并被整个盖住**（全屏模态），而不是浮窗。
- **L6 动效**：页签切换 100ms；工具挥动反馈；动画极短（100–200ms），几乎没有"转场"。
- **L7**：手机版加了虚拟摇杆与更大按钮；中文换字体导致"像廉价游戏"的社区吐槽，说明**字体与美术风格必须同代**。
- **可迁移做法**
  1. **"一个入口装所有东西"**：手机底部 5 个里，「我」这一页装技能/家庭/作品/设置（→ 精简一级导航）。
  2. **纸张/木牌的"不规则边"** 比圆角更像手工物（→ `ChoiceCard` 木牌）。
  3. **材质统一优先于组件统一**：所有面板都用同一种纸/木，即使布局不同也像一家人。
- **不学什么**：全屏不透明模态（我们要求叙事可见）；像素字体（中文像素字可读性差）。

> 参考：[Interface In Game · Stardew Valley](https://interfaceingame.com/games/stardew-valley/)

## A06 · Against the Storm 风暴之城（PC｜城市建造 + Roguelite｜2021）

**一句话**：把"你需要的所有信息"压在**一屏可读的角落**，且每条都能点开追问。

- **屏幕清单**：定居点视图、建造面板（分类树）、资源条、订单/指令、商人、女王急躁度、蓝图选择（三选一）、结算、升级树。
- **L1 信息架构**：顶部资源条（不可折叠）+ 底部建造标签（分类）+ 右侧事件堆。**蓝图三选一是全屏模态**，其余都是侧栏/浮层。
- **L2 布局**：视口尽量大；UI 元素**全部贴边**，中间留出空地，玩家点哪里都行。
- **L3 颜色**：深青灰底 + 琥珀橙强调；资源图标**每个都有独立色相**，但面板极暗以压住冲突。
- **L4 字体**：全无衬线（高可读），字号 3 档；标题用小型大写 + 字距。
- **L5 透明度与融合**：面板 0.9 深色 + 细亮边；**资源条半透明压在天空上**，天空颜色随昼夜变，资源条自动加深——UI 随场景自适应。
- **L6 动效**：三选一卡片 250ms 弹入；资源变化闪烁一次（≤300ms）；不循环闪烁。
- **L7**：UI 缩放；色盲友好（资源图标形状不同）；大量"hover 解释"。
- **可迁移做法**
  1. **"三选一"模态**：把重大抉择做成全屏三张卡片（→ 选项木牌的全屏变体）。
  2. **UI 随场景明暗自适应**：夜间自动加深面板（→ 我们的 `[data-theme=dark]` 已具备，可加"随时间自动切换"）。
  3. **贴边原则**：所有常驻 UI 离屏幕边缘 ≥55px 的安全边距。
- **不学什么**：资源图标的高饱和色相（我们只留 2 个色系）。

> 参考：[Interface In Game · Against the Storm](https://interfaceingame.com/games/against-the-storm/)

## A07 · The Sims 4 模拟人生 4（PC/主机｜生活模拟｜2014）

**一句话**：**同一屏内切换"生活/建造/捏人"三种工作模式**，靠底部大抽屉区分。

- **屏幕清单**：生活模式（3D 场景 + 底部需求条 + 角色头像条）、建造/购买模式（分类侧栏 + 物品格）、CAS 捏人（左侧分类 + 中间人物 + 底部色板）、关系面板、日历、手机（游戏内）。
- **L1 信息架构**：**左下角"三模式切换"是全局唯一的高层入口**；所有功能都在当前模式的侧栏。
- **L2 布局**：生活模式中，场景全屏，UI 只占下沿 1/5；**玩家可以折叠整个 UI 条**（按 Tab）。
- **L3 颜色**：白 + 蓝（主）+ 少量绿/红（需求）；**中性色靠大量白色层级**；本作被玩家做成"暗色 UI mod"（Chalk'd UI）说明色板可替换性很重要。
- **L4 字体**：全无衬线，圆润；CAS 用较大字号（拇指操作）。
- **L5 透明度与融合**：底部条为**纯白半透明（约 0.94）+ 上方 1px 分隔**；模式切换时场景**不消失，只轻微压暗**。
- **L6 动效**：面板滑入 220ms；模式切换 300ms（相机移动）；**"需求条"用图形而非数字**。
- **L7**：缩放 UI；高对比模式；文字大小可调。
- **可迁移做法**
  1. **三模式切换**（→ 我们的"场景/行人/做事"可以做成一条模式栏，而非三个页面）。
  2. **需求用图标 + 条**，悬停才出数字（→ 我们的"心事"完全不用数字，但可以借"条"表达强弱——注意：规范里禁止进度条，需改用高度/浓淡）。
  3. **可整体折叠的界面**（→ 阅读模式：一键隐藏所有非叙事元素，对应无障碍"隐藏非交互元素"）。
- **不学什么**：白色系主导（与我们暖纸色冲突）；需求条的数字。

## A08 · Frostpunk 冰汽时代（PC｜社会生存模拟｜2018）

**一句话**：**UI 就是世界观**——一张"蒸汽朋克仪表盘"盖住了整座城市。

- **屏幕清单**：城市视图、法典（Book of Laws）、科技树、资源条（煤/木/钢/食物）、温度计、民怨/希望双条、事件弹窗、暴风雪预警、结局。
- **L1 信息架构**：资源条在最底部（一条粗带），温度计在右下角，**法典与科技树是两个巨大的全屏"书册"**。
- **L2 布局**：城市是圆的（环形城市），**所有 UI 沿画面边缘环绕**，中心永远是城市——这与我们"画卷居中"同构。
- **L3 颜色**：**冷灰蓝 + 琥珀橙**（火），主色仅 2 系；民怨用红、希望用暖黄。
- **L4 字体**：**工业风衬线 + 小型大写**，标题字距大，有铆钉/铭牌感。
- **L5 透明度与融合**：面板**不透明金属**，但边缘有**霜花与冰晶遮罩**从画面上沿侵蚀下来——"环境侵蚀界面"是本作最有启发的一点。
- **L6 动效**：温度条结霜动画；法典翻页 400ms；风暴来临时**整个屏幕轻微冻结/降饱和**。
- **L7**：可读性较差（小字+低对比），被广泛批评；后加"色盲模式"。
- **可迁移做法**
  1. **资源沿画面边缘环绕**（→ 手机顶部一条"饥饿/时间"薄带，不占中心）。
  2. **环境侵蚀 UI**：季节/天气可以轻微影响界面（秋叶飘过面板、雨季纸边微潮）——**极其适合我们"氛围在动"**。
  3. **节奏性全局效果**：大事件来临时整屏降饱和 0.2、加一层薄雾（≤1.5s 过渡）。
- **不学什么**：金属质感、低对比小字。

## A09 · Wildermyth 漫野奇谭（PC｜叙事策略 RPG｜2021）

**一句话**：**漫画分格式叙事**——把"选择"画成一张张画框。

- **屏幕清单**：战略地图、事件（漫画分格 + 选项）、战斗（网格）、角色卡、关系图、遗产/世代、结局。
- **L1 信息架构**：地图是主界面；事件以"分格漫画"全屏覆盖；角色卡从任何地方点开都是同一张。
- **L2 布局**：事件界面 = **2–3 个画格 + 下方选项条**，画格之间有留白；选项 1–3 个，文本框在格下。
- **L3 颜色**：**低饱和米白纸 + 墨线 + 少量水彩点色**（与我们非常接近）；每个角色有"主题色"。
- **L4 字体**：手写感衬线（叙述）+ 无衬线（UI）；**同一套字体贯穿叙事与非叙事**。
- **L5 透明度与融合**：**纸张是不透明的**，但纸的边缘是**撕边/水彩晕开**，与背景融合；选项条是纸上一块淡色底。
- **L6 动效**：画格**逐个出现**（每格 200–300ms）；选完选项后画格**依次淡出**再回地图（转场语义明确）。
- **L7**：字号可调；文本可朗读（部分）；无强对比问题。
- **可迁移做法**
  1. **分格式叙事**：一段故事 = 1 张大画格 + 1–2 张小格（→ `StoryBeat` 加"格子"变体）。
  2. **纸边撕边/晕染**代替圆角（→ 卡片边缘处理）。
  3. **选完依次淡出**（→ 选择后的转场，避免"啪"一下跳走）。
  4. **角色的主题色**用在名字与头像牌边（→ 人物卡片，但需控制在 2 处赭石内）。
- **不学什么**：漫画分格若过多，会与"叙事文字为主体"冲突；我们只借"节奏"，不借"分格数量"。

> 参考：[《漫野奇谭》系统拆解（知乎）](https://zhuanlan.zhihu.com/p/669346166)

## A10 · RimWorld 的邻居：Norland 诺兰德（PC｜中世纪家族模拟｜2024）

**一句话**：用**"家族树"作为主界面**——把人际网络本身变成可操作的画布。

- **屏幕清单**：城堡/领地视图、家族树（Dynasty Tree）、知识面板、政治（领主关系）、事件日志、战斗。
- **L1 信息架构**：底部一条主菜单；**家族树是全屏可缩放画布**，节点是人物头像，连线是关系。
- **L2 布局**：树状图横向铺开，玩家可拖拽缩放；节点卡为"头像 + 3 行小字"。
- **L3 颜色**：暗棕 + 米色 + 少量金色；**关系线用颜色+线型双编码**（实线=血缘，虚线=婚姻）。
- **L4 字体**：衬线标题 + 无衬线正文；节点内文字极小（批评点）。
- **L5 透明度**：面板 0.9 深色；家族树画布**有羊皮纸底纹**，节点卡是"贴上去的卡片"（有轻微投影，模拟纸叠纸）。
- **L6 动效**：节点展开 200ms；连线生长动画（400ms）。
- **可迁移做法**
  1. **家族树可缩放画布 + 纸片卡片**（→ 家谱视图，手机改竖向单列 + 左右滑）。
  2. **关系线型编码**（→ 亲属/婚姻/敌对，用线型区分而非只靠颜色）。
  3. **卡片投影 1–2px** 模拟"纸叠纸"（→ 层级用极浅阴影而非大阴影）。
- **不学什么**：节点内小字；过密连线。

## A11 · This War of Mine 这是我的战争（PC/手机｜生存模拟｜2014）

**一句话**：**炭笔手绘界面**——界面本身是"这个世界里的某个人画的"。

- **屏幕清单**：避难所（白天）、每晚外出（地图选点 → 场景）、角色卡、背包（Backpad）、日志、事件弹窗、结算（每晚结束）、结局。
- **L1 信息架构**：**昼夜两套界面**：白天是"俯瞰剖面房 + 角色头像"；夜晚是"横版场景 + 极简 HUD"。切换即转场。
- **L2 布局**：白天：左侧角色列 + 中间房屋剖面 + 右侧背包；夜晚：全屏场景，只在左下角留一个小状态栏。
- **L3 颜色**：**黑白灰炭笔 + 单一暖光色（烛火/月光）**；这是"低色彩预算"的极致示范。
- **L4 字体**：手写体标题 + 打字机感正文；**文字有"墨迹渗透"质感**。
- **L5 透明度与融合**：面板是**纸上炭笔**，不透明；但**边缘用炭笔涂抹过渡**到画面；夜间 HUD 几乎透明（0.75）。
- **L6 动效**：翻页/擦拭转场（600ms）；每个"今天发生的事"用**手写逐字出现**。
- **L7**：手机上按钮放大、可点区域明显；文字偏小是批评点。
- **可迁移做法**
  1. **昼夜两套布局**（→ 我们的"日子/夜"可以有轻微布局变化：夜里抽屉变暗、字体变暖）。
  2. **手写逐字出现的叙事**（→ 关键对白可逐字，普通叙述整段淡入，避免拖慢）。
  3. **炭笔涂抹边缘**代替阴影（→ 卡片边缘可用"墨边"而非投影）。
- **不学什么**：黑白灰（我们已有暖纸色体系）；过小的正文。

> 参考：[Interface In Game · This War of Mine](https://interfaceingame.com/games/this-war-of-mine/)

## A12 · Oxygen Not Included 缺氧（PC｜殖民地模拟｜2019）

**一句话**：**同一屏上的"图层切换"**——用覆盖层表达温度、气体、电力、病菌。

- **屏幕清单**：殖民地视图、覆盖层（Overlay）切换栏（右上）、建造菜单（底部）、研究、日程、技能、报告、通知。
- **L1 信息架构**：右上"覆盖层"是核心创新；建造按"类别 → 子类 → 物件"三级。
- **L2 布局**：地图占满；建造菜单是**底部横向大条**；覆盖层只是给地图换配色，不加面板。
- **L3 颜色**：**每个覆盖层一套独立配色**（温度红蓝、气体绿蓝），**切换时整个地图换色**——这是"信息层次"的另一种解法。
- **L4 字体**：无衬线，圆润；字号偏小（批评点）。
- **L5 透明度**：面板 0.88 深蓝 + 发光描边（科技感），与我们的国风冲突。
- **L6 动效**：覆盖层切换 250ms 淡入淡出；资源条变化数字滚动。
- **L7**：UI 缩放；"新资源 UI 被批为 god awful"说明**改版必须保留旧版信息结构**。
- **可迁移做法**
  1. **覆盖层思路**：不做新页面，只给场景叠一层"信息色"（→ 可以做一个"看人情"模式：场景变淡、人物头上浮出文字气泡）。
  2. **建造三级分类**（→ 制作/琢磨的分类）。
  3. **改版保留旧结构**（→ 我们改 UI 保存旧版入口的教训）。
- **不学什么**：发光描边、深蓝科技色。

## A13 · Roots of Pacha 帕夏之根（PC/主机｜史前聚落模拟｜2023）

**一句话**：**题材同源的可借鉴对象**——史前聚落如何做出"不土也不现代"的界面。

- **屏幕清单**：村落（常驻）、工具轮、背包、氏族（Clan）关系、发现（Ideas）树、节日、日历、商店/交易、建造。
- **L1 信息架构**：常驻只有时间/季节 + 快捷栏；**"发现（Ideas）"是核心界面**：一个"灵感卡片墙"，按类别分组。
- **L2 布局**：Ideas 墙为**网格卡片**（4–6 列），每卡 = 图标 + 名称 + 一句"为什么需要它"。
- **L3 颜色**：**大地色（赭石、陶土、苔绿、木棕）**，几乎无冷色；与 OpenLife 的 `--accent #b6733b` 非常接近。
- **L4 字体**：圆润无衬线（UI）+ 略手写感的标题；不依赖像素。
- **L5 透明度与融合**：面板为**皮革/陶土质感的不透明块**；打开时场景压暗 0.45。
- **L6 动效**：卡片"啪"地翻出（180ms）；发现新想法时**图标弹一下 + 一圈涟漪**。
- **L7**：可调 UI 比例；颜色对比良好。
- **可迁移做法**
  1. **"发现/琢磨"用卡片墙**，每卡写"为什么需要它"（→ 我们的「琢磨与试做」左侧"我注意到的难处"）。
  2. **大地色单色系**（→ 校验我们的色板是否够"土"）。
  3. **新发现的涟漪反馈**（→ 印章/木牌的反馈基调）。
- **不学什么**：不透明皮革面板（我们要让场景透出来）。

## A14 · Cozy Grove 温馨的树丛（PC/手机/主机｜生活模拟｜2021）

**一句话**：**手绘线条 + 空白纸面**——界面像一本速写本。

- **屏幕清单**：岛屿、背包、任务日志、商店、角色对话、装饰模式、日历。
- **L1 信息架构**：极简；常驻只有时间与背包入口；**任务以"对话气泡"直接出现在世界里**。
- **L2 布局**：UI 元素**不规则地贴在画面边缘**（像贴在速写本四角），不是整齐的矩形。
- **L3 颜色**：**米白纸 + 彩铅线条 + 少量水彩**；颜色数量极少，靠笔触区分。
- **L4 字体**：手写体（全部界面文字都是手写），**可读性靠字重与字号**。
- **L5 透明度与融合**：**面板几乎是透明纸**（约 0.9），能透出底下的线稿；边缘是"毛边纸"。
- **L6 动效**：物体"轻微呼吸"（缩放 1↔1.01，周期 4s）；翻页/纸滑入 250ms。
- **L7**：字号偏小（批评点）；手机上点按区域尚可。
- **可迁移做法**
  1. **透明纸 + 毛边**（→ 叙事卡片的"纸"可以透出场景的 5–10%）。
  2. **呼吸式微动**（→ 场景里的炊烟、火光，正好对应我们"氛围在动"）。
  3. **任务直接出现在世界里**（→ 心事不用单独列表，直接贴在场景人物头上）。
- **不学什么**：全手写体界面（中文手写字体可读性风险极高，只用于标题/印章）。

## A 组小结（横向）

| 维度 | A 组共同规律 | OpenLife 现状 | 结论 |
| --- | --- | --- | --- |
| 常驻入口 | 3–8 个，贴边 | 手机 4–5、电脑 4 + 更多资料 | 合理，只需收敛文案 |
| 归档方式 | 按对象（CK3/Sims/Stardew）或按动词（RimWorld/ONI） | 按对象（人/物） | 保持对象化，动词丢进上下文 |
| 面板形态 | 贴边浮层 ＞ 全屏模态 | 抽屉/底部面板 | 方向正确 |
| 透明度 | 0.88–0.94 深色，或 0.9 浅纸 | `--glass .92` | 已达标，缺"渐隐接地" |
| 明度关系 | 特效 ≥ UI > 角色 > 场景 | 场景偏亮、UI 偏暗 | **需调整**（见规范 v2 §4） |
| 字号 | 普遍偏小（被批评） | 手机正文 16 | 已达标，保持 |
| 文字游戏特例 | Pentiment/Wildermyth/Roadwarden 用字体与纸面承担"叙事" | 已有纸墨体系 | 可再进一步（见 C 组） |
