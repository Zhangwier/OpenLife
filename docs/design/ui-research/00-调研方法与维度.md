# 00 · 调研方法与维度框架

> 调研时间：2026-10-18　｜　范围：32 款游戏（模拟为主，含 PC / 手机 / 主机）+ 4 份行业方法论
> 用途：为 OpenLife「画卷加话本」UI 改进提供**可直接对照的典范库**与**可量化要素**
> 本文只做「看什么、怎么量、怎么记」，具体结论在 [10-横向提炼规范](10-横向提炼与UI设计要素规范.md)

## 0. 先定问题：我们要从别人的界面里偷什么

OpenLife 的界面约束很特殊，调研必须先对齐我们的约束，否则会抄到不能用的东西：

| 我们的约束 | 因此必须重点调研 | 因此可以跳过 |
| --- | --- | --- |
| 文字是主体，阅读区在视觉中心 | 阅读版心、行高、对白排版、逐段出现节奏 | 战斗 HUD、准心、血条 |
| 场景是静态插画，只有氛围动效 | 光照/天气/昼夜调色层、氛围粒子、转场 | 骨骼动画、走动、寻路、粒子战斗 |
| 不给玩家看数字，用文字和画面表达 | 用图形/文字替代数值的做法、隐喻式反馈 | 数值面板、雷达图、经验条 |
| 国风但不堆砌（纸/墨/木/陶） | 材质克制用法、印章、木牌、纸张层叠 | 金属质感、霓虹科技、紫蓝渐变 |
| 手机优先，也要电脑三栏 | 竖屏单手、底部抽屉、触控热区、横屏左图右文 | 手柄专属交互、VR |

> 一句话：**我们不是要一个「最像游戏的界面」，而是要一个「能不打断阅读、又把世界讲清楚的界面」**。所以调研重点是「低干扰信息呈现」与「界面如何融入场景」。

## 1. 调研维度（七层 × 32 个字段）

行业里常用的拆法有几种，这里把它们合成一张表。每个游戏都按同样字段填，横向才可比。

### L1 信息架构（IA）
- **屏幕清单**：这个游戏一共几类屏（主场景 / 列表 / 详情 / 模态 / 结算 / 空地）
- **常驻入口数**：始终在屏幕上的导航项数量（电脑 ≤6，手机 ≤5 是业界舒适区）
- **层级深度**：从主场景到"最深的功能"，需要几次点击（Civ VI 常被批评为 5+ 层）
- **信息归档方式**：按对象（人物/物品）还是按动词（做/看/去）
- **渐进展开**：第一次进入时隐藏了多少东西（对比 RimWorld 全暴露 vs Wildermyth 分批解锁）

### L2 布局与版心
- **版心宽度**：叙事正文单行多少字（中文 28–40 字为舒适区）
- **栅格**：单栏 / 两栏 / 三栏，各栏职责
- **安全区与边距**：屏幕边缘留白（腾讯《无限法则》实测从 30px 调到 55px）
- **垂直节奏**：标题 → 正文 → 行动条的间距阶梯
- **空状态**：没内容时显示什么（「这一年没什么大事」式）

### L3 颜色系统
- **主色系数量**：主张「主色 ≤2 个色系，辅助 ≤3 个色系」
- **语义色**：警告色 / 危险色 / 成功色 / 中性阶梯（中性色要 5–7 阶才能撑住层级）
- **明度关系**：`特效 ≥ UI > 角色 > 场景`——这条决定了界面能不能"跳出来"
- **一屏用量**：强调色出现次数上限（我们定 2 处）
- **对比度**：正文 ≥4.5:1，大字号 ≥3:1（WCAG 2.1 AA）

### L4 字体与排版
- **族别分工**：衬线=叙事/标题，无衬线=界面（或反过来）
- **字号阶梯**：几档、档间比例（1.25 或 1.33）
- **行高与字距**：中文正文 1.6–1.8；标题加字距 0.05–0.1em
- **数字与西文**：等宽 / 小型大写 / 装饰字
- **字体的"角色化"**：Pentiment 用 5 套字体区分"谁在写"，这是文字游戏最高级的做法

### L5 层次、透明度与背景融合（本次重点）
- **面板底**：实色 / 半透明纸 / 毛玻璃 / 纯色 + 遮罩
- **透明度区间**：常见 0.88–0.96（低于 0.85 就伤可读性）
- **融合手法**：边缘渐隐（fade）、底部渐隐接地、混合模式、纸纹叠加、暗角（vignette）
- **遮罩（scrim）**：打开模态时压暗多少（0.35–0.55）
- **层级表达**：阴影 / 描边 / 抬升 / 失焦（backdrop-blur）四选一为主

### L6 动效与反馈
- **时长档**：微交互 100–150ms，面板 200–250ms，场景转场 400–700ms
- **缓动**：统一一条（如 `cubic-bezier(.2,.7,.2,1)`），不要一条一个
- **氛围循环**：周期 ≥6s、透明度变化 ≤0.3、不闪烁
- **页面切换语义**：淡出=系统隔离，zoom=有逻辑关联（明日方舟的做法）
- **操作反馈**：一个动作只给一次确认，失败必须说原因

### L7 可访问性与一致性
- **触控热区**：≥44×44（WCAG）/ 48×48（我们手机壳标准）
- **文字缩放**：200% 不破版
- **减少动效**：`prefers-reduced-motion` 全停氛围
- **不只靠颜色**：状态必须"颜色+文字/图标"双编码
- **一致性检验**：所有图标是否同线宽、同光源、同朝向（腾讯总结的「五统一」）

## 2. 取样方式

1. **逐款读界面清单**：用 [Interface In Game](https://interfaceingame.com/) 的逐游戏截图目录，先确认「有哪些屏」，再评价「每屏怎么做」。
2. **读开发者/设计者一手材料**：设计复盘、字体厂商案例（如 Pentiment × Lettermatic）、官方 Wiki 的界面说明。
3. **读批评**：评价两极时，负面声音往往更能指出界面边界（RimWorld 的「有风格但难读」、Dwarf Fortress 的「可读性」、Civ VI 的「信息过载」）。
4. **不抄美术、不抄文案**：只提取可迁移的**结构、节奏、令牌与规则**。

### 资料来源分级
- **A 级（一手/可直接核对）**：官方 Wiki、开发者访谈、字体厂商案例、行业设计复盘文章
- **B 级（界面截图目录）**：Interface In Game / Game UI Database 的逐屏清单
- **C 级（二手评论）**：媒体评测、社区讨论——只用来补充"玩家实际怎么感知"

```text
### NN · 游戏名（平台｜类型｜年代）
- 一句话：它在 UI 上最值得学的一件事
- 屏幕清单：…
- L1 信息架构：常驻入口 N 个；最深 N 层；归档方式…
- L2 布局：版心/栅格/边距…
- L3 颜色：主色系 N；语义色…；明度关系…
- L4 字体：族别分工；字号阶梯；…
- L5 透明度与融合：面板底…；透明度…；融合手法…
- L6 动效：…ms；缓动…；转场语义…
- L7 可访问性：热区/缩放/减少动效…
- 可迁移做法：3–5 条，括号里标注落到 OpenLife 的哪个组件
- 不学什么：它的哪一点我们不能照搬（避免"抄错"）
```
