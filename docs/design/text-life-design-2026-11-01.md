# 文字人生：开放互动小说式的玩法设计

日期：2026-11-01。用户决定：先不做画面，改为文字游戏；核心感受是“自己参与创造、改造一个会记住我的世界”，或者“一部非常开放的互动小说”。现有的各项拟真系统都为这个感受服务。

## 1. 调研：市面上的文字游戏怎么做（摘要）

| 作品 | 值得学的 | 要避开的 |
| --- | --- | --- |
| 人生重开模拟器 | 开局抽天赋/分属性；一生几十秒；事件有年龄与属性门槛，天赋改写事件；结局打分并带一个天赋进下一局 | 文本重复度高，数值不够时大量事件触发不了 |
| BitLife | 一个“长一岁”按钮推进；随机事件 + 主动活动菜单 + 人际；“如果当初……”驱动重开 | 选择浅，事件与人物缺少前后呼应 |
| 未来人生系列 | 出生随机（性别、体质、身份、社会关系），在城市里成长、做选择；经营与人生阶段（学业、工作、成家） | 一局时间长、信息密，入口重 |
| Reigns | 一张卡、两个选择；四项相互牵制的量，偏任何一边都会结束；点选前只提示“会影响哪几项” | 牌池有限，久了重复 |
| A Dark Room | 从一个动作开始，逐步揭开系统与世界，界面随世界一起长大；目标不明说，靠暗示 | 后期重复 |
| Fallen London（storylet/资源叙事） | 一段段短故事由“属性/状态”解锁；风险公开，故事里写进挫折；短故事可以自由拼接 | 需要严格设计推进节奏，否则变成刷 |
| King of Dragon Pass | 季节回合 + 每季少数关键决策；事件来自数百个池且受过往决定影响，后果跨季跨年；数值藏在选择之后；全部写进“部族史诗” | 上手难 |
| 80 Days | 用世界观代替主线；路线由与人交谈逐步发现；选择的后果落在世界里而不是善恶条 | — |
| 矮人要塞 / Wildermyth / 太吾绘卷 | 模拟日志生成故事；人物会变老、留疤、有后代并进入“传承”；世界与人物跨局延续 | 太吾：世界大而空、交互难懂；矮人要塞：传说只是干巴巴的年表 |

归纳出六条对 OpenLife 最有用的原则：

1. **读起来像一本书**：主界面是连续的叙事，而不是仪表盘。每件事落成一段文字，按日、季、年分章，一生就是一本可回看的书（KoDP 的史诗、DF 的传说，但用人话写）。
2. **此刻有人有事**：每一页先告诉你在哪、谁在、他们在做什么、天气和日子，再给你能做的事（storylet：由处境解锁）。
3. **选择是一句话，代价写清楚，后果留在世界里**：不做善恶条；后果落到物、人、村子上，以后还会被提起（80 Days、KoDP）。
4. **开放：想做什么就说**：玩家可以直接说“我想……”，游戏用真实规则告诉你现在能做什么、做不到的差什么、下一步去哪里（已有的“暂时做不成 + 下一步”数据）。
5. **节奏可快可慢**：要细就一件件做，要快就“过几天看看”，有事自然停下（BitLife 的“长一岁”，但碰到人和事会停）。
6. **改造世界看得见、可累积、可传承**：村子的成长阶梯、你做的器物、你帮过的人、你开的先例都写进村史；你死后下一代接手的是被你改过的村子（Wildermyth 的传承）。

## 2. OpenLife 已有的、正好能用的

- 处境：所在地点与空间、天气、季节、日子、饥饿、今日活动格、屋顶、负重（`settlement`）。
- 人：在场的人（按认知过滤的称呼）、他们的忙碌、对话树（`stories.dialogues`，选项带好感门槛）、请求、愿望。
- 事：任务章节（`stories.quests`，带步骤与交付）、节庆与集市（`stories.events`，带可选项）、突发事件（`stories.incident`）、今日指引（`guide.focus/suggestions`）。
- 做不成的事与“下一步”：`guide.blocked`（原因 + 下一步 + 可直接执行的前置动作）。
- 时间：一天 8 格；“让这一天过去”；`autosim continuous-batch`（1–5 天，有事停）；这一季打算（`season.begin`）。
- 世界与传承：村落成长阶梯（`outlook.goals`）、农历（`outlook.calendar`）、村史/历史实验室、家族与下一代、思想学派、发明、盖房。

所以本轮不需要新的模拟规则，主要是把这些东西用“互动小说”的方式呈现与串起来。

## 3. 玩法与界面（不做画面，只有文字与排版）

单栏阅读排版（手机竖屏优先，电脑居中 720px），三部分：

1. **顶栏一行**：`冬 · 一月初一 · 雪　启禾，十六岁　今天 ▮▮▮▮▮▮▮▮　吃得饱`。
2. **书页（主体，可上下翻）**
   - 章：季节或年份开头一行大字“第一章　冬 · 初到河岸”；
   - 日：“一月初一，雪。”；
   - 景：到新地方或新的一天时，写一段“此刻”（地点、天气、谁在做什么、身边的东西、村里刚发生的事）；
   - 事：你做的每件事落成一段（服务端叙事原文 + 变化小注，如“得到 粟 1”）；
   - 话：对话树里对方说的话，用引号与人名呈现；
   - 闻：村里的消息、季节节令；
   - 痕：改变世界的时刻（村子升阶、完成任务、关系变成朋友、成就）用“✦”单独成段，同时记入“人生之书”。
3. **此刻能做的（书页下方，跟着书走）**
   - **对话**：在场有人搭话时，直接给出他的那句话和可选回答（就是对话树）；
   - **眼前**：这里能做的事（劳动、取用、做东西、休息），按“人 / 手边 / 去处”分组；每条都是一句话 + 代价；
   - **心里记着**：当前任务步骤、找上门的请求、今日指引的头一件；
   - **我想……**：输入或点选一个念头（如“做陶罐”“娶亲”“修屋顶”），列出现在能做的相关动作；做不到的显示差什么、下一步，并能一键走第一步；
   - **日子**：“让这一天过去”“过几天看看（有事就停）”“这一季打算……”；
   - 暂时做不成的事收起来，展开能看原因与下一步。

其他页面（行囊、熟人、人生、家族、村史、图鉴）沿用现有页面，以面板打开；菜单里可切换“文字人生 / 地图 / 经典页面”。

## 4. 本轮交付范围

- 新增文字人生主界面（默认），复用现有 API 与动作，不改模拟规则；
- 书页持久化（按人物保存在本机，保留最近若干段，按章节可折叠）；
- 景物描写、对话树、任务、节庆、突发事件、指引、“我想……”、时间推进全部接通；
- 自动化检查：单元测试覆盖叙事拼装与“我想……”检索；浏览器检查覆盖新人生→读景→对话→做事→过几天→读档。

暂不做：AI 生成文本（保持确定性与可复现）、新的事件内容（先把已有内容呈现好，再评估缺口）、画面。

## 5. 实现记录（2026-11-01）

- 入口：`apps/web/public/life-story.js`（书页、此刻、过日子、按人物把书存在本机）、`life-story-text.js`（景物、对话分组、我想……检索、消息与停下的理由，纯函数）、`life-story.css`、`play-mode.js`（文字人生 / 地图 / 经典页面，默认文字人生）。服务端规则未改。
- 检查：`tests/integration/life-story-web.test.ts`（每个可做的动作都在页面上、陌生人不露真名、“做个陶罐”能找到捏坯的路、对话选项是服务端接受的真实动作、过几天会推进时间）；全量测试、类型、设计令牌通过；地图与经典页面两条浏览器路径仍通过。
- 已知：对话树里的人会直接显示真名（如陶婶），而景物描写按认知只说“不认识的老人”——这是故事模块原有的认知口径不一致，留待内容侧统一。
- 下一步建议：用一局完整人生试玩，记下哪些时刻无聊/卡住，再补事件内容；考虑“每季开篇摘要”和“一生结束的人生之书”。
