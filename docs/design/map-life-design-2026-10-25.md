# OpenLife 俯视地图生活化改造策划书

日期：2026-10-25。版本：v1，供产品评审。角色：玩法策划与体验整合。

用户已确定：**单人生活探索＋NPC 自主生活**。本文其余规模、交互、节奏与里程碑为建议，不表示已批准实施。基线：`integrate/history-lab@2b63728`；检查时工作区干净。本轮读取源码与设计文档，未启动游戏、未运行测试或真人试玩，未修改游戏代码。

## 1. 产品结论

把 OpenLife 做成一款可以在聚落里走动、认识人、经营生活并留下跨代痕迹的俯视人生模拟游戏。地图应让玩家看见生活发生在哪里：屋顶漏了、工坊有人忙、河岸有人等你、自己做的罐子摆进别人家里。

借鉴《星露谷物语》的个人生活与地方熟悉感，借鉴 RimWorld 的人物需要、关系和环境共同产生故事；继续保留 OpenLife 的认知边界、真实物品、因果历史与传承。玩家控制自己，能够请求、协商、帮助和委托，不直接给全体村民下工作指令。

首版继续以手机为重点，兼容桌面。推荐二维俯视瓦片地图，人物侧面可辨认，建筑可见立面；先不引入可旋转镜头、3D、战斗、全村调度或自由造城。网格用于地图制作、碰撞和寻路，不等于向玩家开放网格建造。

### 三种可选路线

| 路线 | 玩家获得什么 | 主要代价 | 判断 |
| --- | --- | --- | --- |
| 只给现有文字玩法换场景图 | 更直观地看人和地点 | 空间仍不参与选择，容易成为装饰背景 | 可作过渡，不能作为最终交付 |
| 小地图行走、对象互动、行动驱动模拟 | 探索、偶遇、空间用途和个人生活连在一起 | 需补权威位置、寻路、时间协调与动画接线 | **推荐** |
| 全时实时世界、多人调度、自由建造 | 更强的聚落经营与生产组织 | 时间、自治、权限、经济和 UI 大幅改造 | 偏离本次已选方向，首版不做 |

## 3. 地图如何组织

### 3.1 三层尺度

1. **地区图**：村子、渡口、近邻聚落。玩家选择目的地并查看已知路程、准备和风险；无需步行穿越大量空白地形。
2. **聚落局部图**：家、公共灶、工坊、田地、河岸之间可以真实走动。首版推荐一张约 64×64 格的手工地图，具体格数以路线密度调整。
3. **室内小图**：主屋、公共屋、工坊等独立空间，约 12×12 至 24×24 格。门口切换场景，进入仍校验许可；不提供俯视透视全部房屋内部的能力。

首版局部图建议 6–8 个功能区、3–4 个可进入室内、6–8 位重点人物。其余已存在居民保留真实状态，不因策划指标删人。尺寸和人数是制作预算，不是现状统计。

### 3.2 河岸聚落示意

```text
                 林缘与采集地
                      │
        住处──公共屋──编织棚
         │      │       │
        菜地──公共灶──陶作场
                │       │
              河岸────旧渡口 → 地区图
```

这只是功能邻接示意，不覆盖现有地点 ID；实际场景先映射已有内容。河流、栅栏、建筑占地形成清楚的路线，不能画出可走道路却没有有效出口。

| 场所 | 玩家来这里的理由 | 必须看得见的变化 |
| --- | --- | --- |
| 家 | 休息、储藏、修缮、照料 | 漏雨修复、物品摆入、家庭成员活动 |
| 公共灶 | 食物、合作、求助 | 食材来源、正在做事的人、分享后的库存变化 |
| 田地与林缘 | 留种、食物、材料 | 成长/耗用状态、季节差异、资源恢复提示 |
| 编织棚与陶作场 | 学艺、制作、履约 | 材料、工作占用、加工阶段、成品去向 |
| 河岸与渡口 | 取水、采集、遇人、远行 | 安全通路、已知天气影响、来客与出行状态 |
| 公共屋 | 协商、节庆、共同工程 | 谁参与、谁出材料、设施改善后的用途 |

首版优先手工地图；资源分布、事件参与者和人物处境可由种子产生变化。程序随机地图放后续，避免先得到大而空的世界。

## 4. 核心操作与时间

### 4.1 地图交互

点击空地：显示目标并走到可达点。点击人物/物件：先选中并显示简短身份与可做事项，再选择“走近交谈”“取用”等动作。点击私人物品不能默认拿走，点击远处 NPC 不能直接交易。拖动镜头不触发行走；返回键先关面板、再取消路线、最后打开退出菜单。

寻路目标是合法交互点，不是对象中心。门、河岸、工位需要有效入口；人物遮挡或道路变化时重新规划，无法到达给出原因和取消入口。首版普通 NPC 不作为永久硬障碍，避免门口排队卡死；占用工位仍按规则排他。

移动与互动分两步校验：出发时确认路线；到达时重新检查对象、权限、材料、距离和当日额度。人物离开、物品被取走或玩家取消时，不扣尚未执行的制作/交易费用。

### 4.2 推荐采用“行动推进、画面连续”

保留既有日级 tick 和日内行动额度。阅读、打开行囊、拖动镜头、查看地图均暂停模拟；关闭游戏默认不推进。人物走路可以平滑播放，但动画帧不增加年龄、成熟度或生产次数。

首版同一语义空间内短距离移动不单独扣生活额度，跨 Place 的路线沿用所属动作的权威成本。界面如实显示“本地短距离移动无额外消耗”或具体消耗，不伪装成精确分钟制。首版不设计追逐、抢秒等依赖实时速度的收益；否则免费移动会破坏平衡。

为了让村民在一天内有可观察变化，新增有限日内行为节点：仅在有效、消耗额度的生活行动完成后触发，或由明确的“等待一段”行动触发。节点上 NPC 可以决定移步、开始工作或回应；产出与消耗必须交给原规则，不能和日边界自治各结算一次。节点进度须保存，读档不重复执行。日边界继续承担每日结算，实施前明确每类行为唯一结算责任。

首版不用虚构的 08:00、09:00 表示尚未实现的小时制。晨/昼/暮只在有一致日内状态时展示。以后若需要分钟级日程，另作时间兼容设计和旧档迁移，不直接修改 tick 长度。

“安排平常生活”继续承担跨日/跨季推进，遇到重大承诺、危险、关系转折和交棒停下来。禁止玩家为看完一生手动走数万次回家路。

## 5. NPC 自主生活如何落到地图上

已有自治、需要和关系逻辑继续作基础。新增表现链为：当前处境→选定目标→可达地点→移动→实际行动→可见后果。移动动画只播放已经确认的行动，不能前端随机让 NPC 进工坊，再由后端说他始终在家。

每位重点人物补一份内容卡：常见活动地点、家庭与手艺、当前实际需要、可能改变安排的原因、两位重要关系、可协商事项、玩家不介入时的选择。活动倾向不等于固定死板时间表，生病、缺料、承诺等应改变安排。

- 工作中可以简短回应、拒绝或约稍后；不会被玩家不断点击无限中断。
- 只对当前可观察人物显示位置。熟人页可显示“上次在河岸见到”，不得显示全村实时 GPS。
- 陌生人用稳定外观和已知称呼辨认；不因切换地图自动知道真名、生日或秘密。
- 村民工作占用真实材料、工位和产物。表现层可省略搬运细节，但不能制造另一份库存。
- 远场 NPC 使用已有粗粒度模拟；回来时恢复合理位置与正在进行的活动，不必计算全村每一格的脚步。

## 6. 地图必须改善的玩法

### 6.1 三条生计都有空间价值

务农饮食关注采集/田地、储藏与公共灶的往返和留种选择；纤维修补关注取材、工位、上门查看与交付；制陶交换关注材料、加工阶段、成品用途与交接。先让三条现有链各完成一个地图闭环，再增加钓鱼、矿洞等新系统。

日常动线应短，探索路线应有新发现。首轮校准目标：家到最近生活设施约 5–15 秒动画，村内横穿约 20–40 秒；需要实机测量，不能用刻意拖慢脚步制造内容。熟悉路线允许自动走路、取消和减少动画；跨区域依然付出同样规则成本。

### 6.2 环境变化留下后果

首版选择少量可持续状态：屋顶是否修好、公共灶是否可用、田地生长阶段、作品放在哪里、某处是否留下纪念。这些变化绑定真实实体或事件。装饰性雨雪可先实现；若雨雪改变通路或产量，必须由模拟规则产生并保存。

公共建设继续采用既有抽象工程＋预设位置。玩家提出、供料、参与和协商，完工后替换场景状态并提供新用途。首版不做拆全村房屋、逐格摆家具、自动流水线或区域工作优先级。

### 6.3 探索与信息发现

看见一座屋不代表知道里面的人与物。地图区分未探索、曾见地形、当前可见对象；前端不得收到无权知晓的实体再靠隐藏图标保护秘密。首版可用房间/区域规则处理遮挡，不强求复杂逐格光照模拟。

村外先选一个已有目的地做“准备→出发→落脚→做事→返回”。第二个目的地在第一条旅途有不同于村内生活的取舍后再扩。新地点至少提供一种独有材料、人物关系、做法或环境条件。

## 7. 第一段可玩的经历

以下是新内容提案，人物名与道具接入时从现有内容选取，不声称已经实现。

**主题：雨前的一只储粮罐。** 玩家起床发现家里的储粮器需要更换，邻人正在把粮食搬到屋檐下。玩家可以去工坊制作、用修补劳动交换、借用容器并约定归还，或先减少储存、推迟解决。

| 游玩阶段 | 玩家实际操作 | 世界应该回应 |
| --- | --- | --- |
| 0–3 分钟 | 出门、点击邻人、看到一项处境 | 学会行走与交谈，知道下一步去哪里 |
| 3–10 分钟 | 到工坊看材料/工位，比较制作与交换 | 明确成本、占用和不可用原因；至少两条合法路径 |
| 10–20 分钟 | 自行解决或请求帮助，完成交付 | 物品实际转移，人物记住合作或拒绝 |
| 下一次见面 | 回访、履约或解释延期 | 对话与行为因选择不同；不只弹“关系＋1” |
| 换季或继承后 | 查看器物与家中变化 | 器物来源、曾经帮助者或未了承诺仍可追溯 |

不介入也要有结果，但提供修复路径。正式文案与数值需检查已有物品容量、天气与储藏规则；若没有潮湿损耗规则，先以明确的储藏需求呈现，不用剧情强扣粮食。

## 8. 手机界面与美术

保留“此刻、行囊、熟人、人生”四个主要入口；此刻页升级为地图主场景。地图、文字行动列表消费同一投影，低性能或无障碍模式仍可完成相同动作。

竖屏上方显示日期、地点与关键需要；中间地图占主要空间；底部对象行动面板默认收起。详细对话时面板展开并暂停，地图不强行保留很大面积。横屏允许宽地图＋侧栏；桌面键鼠作为补充。点击寻路为手机首选，摇杆留到原型证明确有需要再加入。

触控区至少 48 CSS px；正文约 16–18px；对象过小时扩大命中区、提供附近对象列表。必须能回到角色、停止行走、关闭面板；不依赖双击、右键或悬停完成关键动作。长对话、输入法、字体放大和安全区均列入后续真机验收。

美术建议温暖、清楚的低分辨率像素风：土、木、草、陶的色彩延续项目气质，文字面板保留克制的纸感。采用统一瓦片与人物比例，前后遮挡按脚底位置排序，屋顶进屋后隐藏；减少细碎装饰，优先让门、路、可互动对象可辨认。

首轮资产预算：一套地表与道路、一套河岸、一套建筑/室内、6–8 个重点人物外观、三条生产路线必需物件、走路/待机/工作基础动画。季节先替换关键地表与植被，不把四季全套重画作为第一阶段门槛。记录素材授权与来源，不复制参考游戏素材。

## 9. 技术接入与旧档策略

本节规定设计边界，不是已经确认的接口签名。

| 部分 | 建议责任 | 关键限制 |
| --- | --- | --- |
| 地图内容 | 地形、阻挡、入口、交互点、场景到 Place/Space 的映射、版本 | 静态内容不能直接改库存与关系 |
| 空间运行时 | 校验位置、路径、入口权限与交互距离 | 优先扩展模块能力；不把格子和引擎画布塞进 Kernel |
| 玩家投影 | 已知地形、当前可见对象、可用动作与成本 | 不返回全村秘密或完整内心状态 |
| 表现层 | 镜头、输入、人物动画、遮挡、反馈 | 不裁定交易、产出和时间，不另存一套事实位置 |
| 应用协调 | 移动请求、到达后动作、取消、重复提交、存档 | 一个操作链不能重复扣料/推进 |

局部位置建议记录 sceneId、格坐标、朝向；同时维护既有语义空间归属。跨门操作必须原子更新两者，禁止画面已进屋而规则仍在屋外。位置写入由一个模块负责，不能由前后端各自修正。

移动初版采用短路径分段确认：每段通过命令更新权威位置，前端只在确认位置间插值。分段不自动产生世界日 tick；跨地点成本按完整动作唯一结算。重载回到最后已确认格，不重复执行到达动作。路径被阻挡时取消余下段，给出原因；有生活成本的路线按规则记已完成部分，不依赖动画完成回调收取费用。

NPC 远近场切换保持同一实体与物品账；进入场景根据其真实 Place/Space 和活动安排确定性落位。场景外可只保留语义位置，进入时在合法锚点落位。具体坐标是否持久化按其是否影响玩法确定，不能读档后掉进河里或跳进锁门房间。

存档增加地图内容版本和空间数据版本。旧档按已有 Place/Space 映射到合法锚点；不存在映射时保留原档并说明问题，不静默重建人生。地图修改导致格子失效时移动到同一合法区域的安全锚点并留迁移记录。升级前保留备份，加载缺少地图模块的存档时提供清晰恢复说明。

继续在现有 TypeScript/Web 架构上验证。Canvas 原型可以沿用表现经验；是否引入专门 2D 渲染库，在小地图资产、镜头、命中测试和手机性能原型后决定。本轮不指定未评估的引擎迁移，也不宣称 PWA 或当前服务已实现个人离线存档。

## 10. 实施顺序与交付门槛

按阶段放行，不承诺日期；先完成 M1–M2 计时，再根据实际产能估算完整周期。每阶段分别记录代码、自动检查、浏览器路径、真机和真人体验状态。

| 阶段 | 主要交付 | 可操作验收 |
| --- | --- | --- |
| M0 设计收口 | 时间与空间接口决定、旧档样本、现有动作映射、首张地图布局 | 每个关键决定有唯一责任与失败处理；明确哪些提案被采用 |
| M1 一个家与一条路 | 可操控人物、家/河岸连接、阻挡/门/镜头/保存恢复 | 从正式入口进入→走路→进入屋内→退出→读档位置正确；不可穿墙或越权 |
| M2 一条完整生活链 | 一位 NPC、一个工位、一次真实制作/交换、统一行动面板 | 选人→走近→比较代价→行动→看到物资/时间变化→存退恢复；取消不多扣 |
| M3 会生活的聚落 | 日内节点、6–8 位重点人物表现、三条生计、可观察后果 | NPC 确实改变位置和工作；跨日不重复产出；别人拒绝/离开有可理解反馈 |
| M4 第一个季节 | 少量环境变化、承诺、12–18 段已有/新增经历整合 | 试玩者记住至少两个人和一件自己的选择造成的变化；缺粮/失约可恢复 |
| M5 远行与传承 | 一个村外目的地、返回、跨代痕迹、兼容与设备收口 | 出行期间的托付有结果；下一代见到前代留下的具体物件/设施/记录 |

M1–M2 是第一份值得投入的可玩切片。在它们成立之前，不先铺全地图、全人物动画或复杂地图编辑器。M3 若时间协调成本超出预算，可以先交付正确的日边界自治并清楚标注；不能用随机游走伪装日内生活已经完成。

## 11. 后续验收与风险

### 规则和实际路径

- 固定种子与相同命令得到相同结果；改变帧率、减少动画不改变世界。
- 走近后才能执行需要当面的操作；无法进入的房屋不泄露内部人物和物品。
- 取消、连点、重载、跨日、换季不重复扣料或产出；移动完成不自动再次触发原行动。
- 存读档保留位置、当日额度、NPC 已执行标记、工位占用和版本信息；新档不混入旧档人物。
- 360/390/430px 视口完成真实操作链；桌面模拟与 Android/iOS 真机结果分别记录。
- 性能先在选定中端手机建立基线，再以常规场景稳定约 30fps、操作反馈约 100ms 内作为优化目标；这不是本轮测量结果。
- 三名首次试玩者不受指导，至少两人两分钟内完成有效行动，能解释一种成本并说出下次目标。未达到时先改入口、路线和反馈。

### 优先处理的风险

| 风险 | 早期信号 | 应对 |
| --- | --- | --- |
| 地图只是更慢的菜单 | 大量时间走路，行动与原文字版完全同质 | 缩短日常路，增加偶遇、工位与可见痕迹，提供自动走路 |
| 时间改造破坏原系统 | 对话导致过日、NPC 重复结算 | 保留日级契约，日内节点独立记账，先做一人一日切片 |
| 美术压过玩法 | 地图很好看，仍不能真正制作/交换 | M2 前限制资产量，每个区域必须有真实动作 |
| NPC 看似忙碌但没有后果 | 动画在工作，物品与目标没有变化 | 从命令结果驱动表现，分别记录动作与收益 |
| 全知地图破坏认知 | 不认识的人全都有名字和位置 | 投影层过滤，熟人位置注明消息时间和来源 |
| 规模失控 | 同时增加战斗、农场、造城与多人调度 | 首轮只实现既有三条生计和个人探索 |

## 12. 与旧规划的关系和下一步

本提案建议把旧规划的“默认文字与轻场景”升级为“地图为主要生活入口，文字用于叙事、详情与辅助操作”。此项仍待评审；原定位中个人生活优先、无战斗、非全知、抽象建设、手机可用、跨代连续等约束继续保留。新地图不自动授权增加自由建造。

下一步先评审 M0 的三项决定：行动驱动时间是否符合预期；竖屏点击寻路是否作为首发交互；是否接受首版仅一张密集聚落图。确认后进入具体实现计划，先做 M1–M2。未完成：可操作地图、场景资产定稿、接口与迁移实施、性能/真机/真人验收。本轮交付是策划方案。
