# OpenLife 拓展规划书

日期：2026-10-17
依据：《OpenLife 与国内外模拟游戏对比调查》（2026-10-17）+ 对 `codex/knowledge-and-hazard-merge` 分支代码的实地检查 + 《插件 / Mod 规范 v1》（`docs/PLUGINS.md`）
适用分支：`fix/hazard-ratchet`（cf7a708 修复 + 54e2064 插件规范）

---

## 0. 一页结论

**定位一句话**：一个河岸村落里，几十个"你得慢慢认识"的人，被天时和彼此推着过完几代人。

**这份规划只做三件事**：

1. **让事情找上门**：把故事从"描述"改成"抉择"，再加一个按戏剧节奏投放事件的叙事者。
2. **让玩家知道在玩什么**：给一条看得见进度的长期目标（村子活下去并长大），加今天 / 这一季 / 这一生三档目标和每日反馈。
3. **把独有的东西做深**：认知系统 → 秘密系统；确定性 → 可分享的"我这一生"。

**所有新东西都按插件规范做**：新规则是独立系统模块，可在 `openlife.modules.json` 里关掉；新内容是数据包，放进目录即生效。这样内容作者和系统开发可以并行，互不阻塞。

**明确不做**：战斗、自由建造、百人以上规模、内购。理由见第 2 节。

### 路线总览

| 阶段 | 时长（估） | 主题 | 交付 | 解决的问题 |
| --- | --- | --- | --- | --- |
| 阶段 0 | 1–2 周 | 打地基 | 定位文档、内容包格式 v2、拆 settlement-locations 的前三刀、CI 上 Node 24 | 后续每个方向都依赖它 |
| 阶段 1 | 3 周 | 事情找上门 | 抉择事件系统 + 首批 30 个抉择事件 + 每日反馈 | "所有事都要我主动""事件太温柔""不知道自己干了什么" |
| 阶段 2 | 3 周 | 知道在玩什么 | 叙事者模块 + 村落成长目标 + 三档目标 + 日历 | "不知道在追求什么""节奏平" |
| 阶段 3 | 4 周 | 人有心事 | 秘密系统 + 愿望/恐惧 + 人生阶段 | 人物没有内在张力 |
| 阶段 4 | 4 周+ | 村外与社区 | 地图包接入玩法（远行、集市、外乡人）、Mod 工具链、"我这一生"分享 | 世界小、没有生态 |

每个阶段结束都要能玩、能存档、全量测试通过。

### 1.2 必须先处理的问题

| 问题 | 影响 | 处理阶段 |
| --- | --- | --- |
| `settlement-locations/src/module.ts` 约 5000 行，建村、饮食、婚姻、制作、季节、搭话、送礼混在一起 | 新系统只能继续往里塞；冻结上限阻止增长 | 阶段 0 开始拆，贯穿全程 |
| 故事分两套：`settlement-locations` 的描述型故事 + `village-stories` 的抉择型事件，格式不同 | 内容作者不知道写哪里 | 阶段 1 统一 |
| 内容包 v1 只能加物品和配方 | 写事件、人物、秘密的人没法用内容包 | 阶段 0 升级到 v2 |
| 生日送礼测试失败（照顾病人挤掉送礼） | 说明 NPC 一天只能做一件"好事"，日程容量是真问题 | 阶段 0 决定规则 |
| 存档不记录装了哪些内容包 | 删包后读档可能引用不存在的物品 | 阶段 0 |
| 沙箱 Node 22、仓库要求 24 | 验证不完整 | 阶段 0 CI 固定 24 |

## 2. 定位决策（阶段 0 写进 `docs/POSITIONING.md`）

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 深度还是规模？ | **深度**。村子 10 → 50 人，上限 80 | 认知系统只在小规模成立；80 人以内每个人都能被认识 |
| 要不要战斗？ | **不要**。冲突用关系、名声、资源、灾情表达 | 对比报告里"硬缺口"都是别人的核心，不是我们的；做半吊子战斗不如不做 |
| 要不要建造？ | **只做"修缮/加盖"这类抽象动作**，不做自由摆放 | 文字界面做自由建造没有优势 |
| 主线？ | **没有剧情主线，有一条成长线**（村子活下去并长大） | 目标感来自进度，不来自剧本 |
| 信息呈现 | **不全知**是底线：任何新界面不能绕过认知层 | 这是唯一没有对手的特色 |
| 节奏 | 季节大结算保留，**每天必须有一条可见反馈** | 星露谷的教训 |

所有后续方向用这张表做取舍：违背其中一条的需求，需要先改这张表。

## 3. 阶段 0：打地基（1–2 周）

### 3.1 内容包格式 v2

在 v1（物品、资源名、初始物品、配方）基础上扩展，仍然"只增不改"，仍然强制命名空间：

| 新增文件 | 内容 | 校验 |
| --- | --- | --- |
| `incidents.json` | 抉择事件（格式见 4.1） | 引用的居民、地点、资源、旗标都存在；每个选项至少一个后果 |
| `residents.json` | 新居民（含 people 性格、喜好、愿望、恐惧） | 住处空间存在，喜好资源存在 |
| `dialogue.json` | 对话片段，按关系层级/话题挂到已有居民 | 居民存在 |
| `secrets.json` | 秘密（阶段 3 启用，格式见 6.1） | 归属人存在 |
| `places.json` | 新地点 + 空间 + 产出点 | 与已有地点连接合法 |

另加两条规则：

- **存档记录内容包**：开局时把 `ACTIVE_CONTENT_PACKS`（`id@version`）写进世界状态；读档时缺包给出明确提示（"这份存档用到了内容包 xxx，当前未安装"），而不是报错。
- **覆盖（override）仍不开放**。需要改基础数值的，走系统模块的配置项。

验收：示例包能同时加一个居民、两个抉择事件、一条对话；`settlement-extensions.test.ts` 覆盖每种文件的正反用例。

### 3.2 拆 settlement-locations 的前三刀

按 `docs/PLUGINS.md` §5 的方法，优先拆和本规划直接相关的部分：

| 新模块 | 能力名 | 拆出内容 | 为什么先拆它 |
| --- | --- | --- | --- |
| `settlement-stories` | `settlement.stories-legacy` → 合并入 4.1 | 换季故事池（`story-pick.ts`、storyteller 数据） | 阶段 1 要统一故事系统 |
| `settlement-gifts` | `settlement.gifting` | 送礼、生日、谢礼 | 生日测试冲突就在这里；阶段 3 愿望系统要用 |
| `settlement-marriage` | `settlement.marriage` | 婚配、生育 | 已有 `marriage.ts`，最容易拆；阶段 3 人生阶段要用 |

每拆一个：旧命令保留转发一个版本，组件写迁移，`module.ts` 行数上限同步下调。

### 3.3 其他

- **生日送礼规则**：建议采用"照顾病人后仍可送礼，但礼物降级为口头祝福"，既保留优先级又不吞掉生日。改测试断言为"生日当天至少有一条祝福或礼物"。这是一个玩法决定，需要你拍板。
- CI 固定 Node 24；全量测试、typecheck、catalog 检查进 CI。
- `docs/POSITIONING.md` 落地第 2 节。

## 4. 阶段 1：事情找上门（3 周）

### 4.1 统一的抉择事件系统

**模块**：扩展 `village-stories`（它已有 incident 和选项执行），把 `settlement-locations` 的换季故事迁过来，成为同一种数据。

**数据格式（IncidentSpec v2）**：

```json
{
  "id": "incident:base.share-winter-grain",
  "title": "分不分冬粮",
  "tier": "conflict",
  "seasons": ["秋", "冬"],
  "weight": 3,
  "cooldownYears": 2,
  "requires": {
    "stockBelow": [{ "resourceId": "resource:grain", "amount": 12 }],
    "population": { "min": 6 },
    "hazard": { "kind": "drought", "stage": ["active", "aftermath"] }
  },
  "cast": {
    "asker": { "pick": "resident", "where": { "role": "cook" } },
    "needy": { "pick": "household", "where": { "poorest": true } }
  },
  "text": "收成不好。{asker}说，可以把留给冬天的粟分给{needy}，但你们自己可能撑不到春天。",
  "choices": [
    {
      "id": "share",
      "label": "分一半给{needy}",
      "cost": { "resource:grain": 6 },
      "effects": [
        { "bond": { "who": "needy", "trust": 2 } },
        { "flag": "shared-winter-grain" },
        { "followUp": { "id": "incident:base.hungry-spring", "afterSeasons": 1, "chance": 0.6 } }
      ],
      "line": "{needy}一家人站在门口，半天没说出话。"
    },
    {
      "id": "refuse",
      "label": "先顾自家",
      "effects": [
        { "bond": { "who": "needy", "grudge": 1 } },
        { "reputation": { "delta": -1, "tag": "stingy" } }
      ],
      "line": "{asker}叹了口气，没再提。"
    },
    {
      "id": "ask-elder",
      "label": "请埴公评理",
      "requires": { "knows": "trader-elder" },
      "effects": [{ "followUp": { "id": "incident:base.elder-judges", "afterDays": 1 } }],
      "line": "你去找了埴公。"
    }
  ]
}
```

关键设计点：

| 设计点 | 说明 |
| --- | --- |
| `tier` | `ambient`（氛围）/ `minor`（小事）/ `conflict`（冲突）/ `crisis`（危机），给阶段 2 的叙事者用 |
| `cast` | 按条件从村民里选角色，同一个事件每次落在不同人身上；选角受认知层约束：玩家不认识的人显示为"一个妇人"而非名字 |
| `cost` / `requires` | 选项有门槛（资源、手艺、认识某人、旗标），不满足时显示但灰掉并说明原因 |
| `effects` | 统一的后果词表：交情/信任/怨气、资源、旗标、名声、后续事件（延迟 N 天/季）、触发争执、揭示秘密（阶段 3） |
| `followUp` | **延迟后果**是 KoDP 的核心，必须支持；后续事件进入叙事者的待办队列 |
| 旧格式兼容 | 现有 14 条描述型故事自动转换为 `tier: ambient`、无选项的事件；`hazard`/`excludes`/`yields` 语义不变 |

**内容投放**：抉择事件可以放在任何内容包的 `incidents.json` 里。

**首批内容（30 个，分给内容作者）**：

| 类别 | 数量 | 例子 |
| --- | --- | --- |
| 分配稀缺 | 8 | 分冬粮、谁先用窑、草药只够一个病人、洪水后先修谁家屋顶 |
| 忠诚冲突 | 8 | 两个朋友争地界、替人作证、婚事被家里反对、外乡人被怀疑偷东西 |
| 代价选择 | 8 | 涨水时救羊还是救罐、冒险去对岸找药、收留逃难的人、把手艺教给对手家孩子 |
| 小事与氛围（带选项） | 6 | 野猪拱田、孩子走丢、狗叼走鱼干、老人讲古 |

每个事件写作标准：至少两个选项都"有道理"；至少一个选项带延迟后果；文本不超过 80 字；不出现玩家不认识的人名。

**验收**：
- 30 个事件全部通过数据校验和覆盖测试（每个选项至少被一个种子走到过）。
- 一局 3 年的自动对局中，玩家平均每季遇到 ≥ 2 个抉择事件。
- 旧 14 条故事在新系统下行为不变（金色测试）。

### 4.2 每日反馈

**位置**：`apps/web/src/day-summary.ts`（投影层，不进 `server.ts`）。

| 内容 | 来源 | 规则 |
| --- | --- | --- |
| 今天你做了什么、得了什么 | 当天玩家命令的历史记录 | 一句话，最多三项 |
| 今天村里发生了什么 | NPC 日程记录、事件、灾情阶段变化 | 只说玩家看得见或听说的 |
| 谁对你的看法变了 | 交情/信任/怨气变化超过阈值的人 | 不认识的人用描述代替名字 |
| 离这一季的目标还差多少 | 4.3 / 5.2 | 一个进度数字 |

每个动作执行后的提示文案补"可见结果"（"罐里的水满了一半"而不是"打水成功"）。

**验收**：每一天推进后都有小结；小结不泄露认知层之外的信息（测试：陌生人的名字不会出现在小结里）。

## 5. 阶段 2：知道在玩什么（3 周）

### 5.1 叙事者模块 `story-director`

**能力**：`story.director`；`optional`: `world.hazard-state`、`social.conflict`、`settlement.secrets`。关掉它时退回现在的固定概率抽取。

**状态**：

```
tension: 0–100
calmDays: 连续无冲突事件的天数
recent: 最近 8 个事件的 tier 和 id
pending: 后续事件队列（来自 followUp）
mode: gentle | rhythmic | chaotic
```

**张力计算（每天）**：

| 输入 | 作用 |
| --- | --- |
| 连续平静天数 | 每天 +1~3（视模式） |
| 灾情 omen / active | +10 / +20 |
| 存粮低于人头 × 天数 | +5~15 |
| 村里未解决的怨气总量、世仇数 | 按比例加 |
| 刚发生 conflict / crisis | 清零到 10~30（"喘息"） |

**投放规则**：

| 张力 | 本日可投放的 tier | 概率 |
| --- | --- | --- |
| < 25 | ambient、minor | 低 |
| 25–60 | minor、conflict | 中 |
| 60–85 | conflict | 高 |
| > 85 | crisis（必投一个） | 100% |

后续事件优先于新事件；同一居民 10 天内最多被选角 2 次；所有随机都走世界种子，保证可重放。

**三种模式**（开局可选，存档记录）：

| 模式 | 对标 | 特点 |
| --- | --- | --- |
| 细水长流 | Phoebe | 张力涨得慢，喘息期长，几乎不出 crisis |
| 起起落落 | Cassandra | 标准曲线，默认 |
| 天意难测 | Randy | 张力权重小，随机性大 |

**验收**：
- 10 个种子 × 3 年自动对局，统计事件间隔分布：起起落落模式下不出现连续 30 天无事件，也不出现 5 天内 2 个 crisis。
- 模块关闭时，所有现有测试结果不变。

### 5.2 长期目标：村子活下去并长大

**模块**：`settlement-goals`，能力 `settlement.goals`。

**阶梯**（数据驱动，写在 `goals.json`，内容包可替换整套阶梯）：

| 阶段 | 名称 | 达成条件（示例） | 解锁 |
| --- | --- | --- | --- |
| 1 | 落脚 | 熬过第一个冬天，无人饿死 | 第二季的目标 |
| 2 | 安顿 | 每户屋顶完好，存粮够全村 60 天 | 外乡人开始来投奔 |
| 3 | 添丁 | 人口 ≥ 15，有 2 个孩子出生 | 新地点开垦 |
| 4 | 有名 | 渡口集市主动来人，南岸有人知道这个村 | 远行（阶段 4） |
| 5 | 兴旺 | 人口 ≥ 30，三代同堂的人家 ≥ 2 | 村史篇章 |
| 6 | 传承 | 你的家族传满五代 | 结局评语 |

**失败条件**：人口降到 3 以下或连续两冬饿死人 → "村子散了"结局，可以由后代在别处重新开始（继承保留）。

**三档目标**（与 `village-stories/guide.ts` 合并）：

| 档 | 来源 | 显示 |
| --- | --- | --- |
| 今天 | 当前最紧迫的需要（饿、病、灾情、未处理事件） | 1–3 条建议 |
| 这一季 | 当前阶梯的子目标 + 季节专属任务 | 进度条 |
| 这一生 | 阶梯阶段 + 个人愿望（阶段 3） | 阶段名 + 下一步 |

### 5.3 日历

`apps/web/src/calendar.ts`：显示本月和下月的节庆、限时活动、农时、已知生日。

**认知规则**：认识的人显示"阿予的生日"；只见过的人显示"有人过生日"；完全陌生的不显示。打听到生日后日历立刻更新。

**验收（阶段 2 整体）**：新玩家试玩 30 分钟后能说出"我现在要干什么、为什么"（内测问卷，目标 ≥ 80%）。

## 6. 阶段 3：人有心事（4 周）

### 6.1 秘密系统 `village-secrets`

**能力**：`settlement.secrets`；`requires`: `cognition.epistemic-state`；`optional`: `social.conflict`、`story.director`。

**数据**：

```json
{
  "id": "secret:base.stolen-grain",
  "owner": "{cast}",
  "kind": "misdeed",
  "severity": 2,
  "text": "去年冬天公灶少的那袋粟，是{owner}拿的。",
  "hints": ["{owner}家去年冬天好像没断过粮。", "有人看见{owner}半夜去过公灶。"],
  "requires": { "personality": { "generosity": { "max": 40 } } }
}
```

**知晓状态**：不知 → 听说（有线索）→ 确知。每个居民对每个秘密都有自己的知晓状态（复用 epistemic-state）。

**获知途径**：

| 途径 | 规则 |
| --- | --- |
| 打听 | `ask_about` 新增"最近有什么事"话题；被问者信任你且知情时透露线索 |
| 日久相处 | 同住、同工的人随时间获得线索 |
| 目击 | 事件选项里安排"你看见了……" |
| 闲话传播 | NPC 之间按交情传播"听说"级别的信息，越传越走样（可选） |

**使用秘密**（作为事件选项和独立动作）：

| 动作 | 后果 |
| --- | --- |
| 替人保密 | 秘密主人信任大涨，形成"欠你的" |
| 私下劝 | 视脾性：改过 / 恼羞成怒 |
| 当众揭发 | 秘密主人名声大跌、对你怨气大涨；可能触发 `social-conflict` 争执 |
| 拿来要挟 | 换资源或帮忙；被要挟者怨气持续累积，叙事者张力上升 |

**数量**：首批每位基础村民 1–2 个，共 15–20 个，按 `misdeed`（过错）/ `origin`（身世）/ `feeling`（暗恋、旧怨）/ `ailment`（隐疾）四类。

**验收**：秘密只能通过上述途径获知（测试：没有任何投影在"不知"状态下泄露秘密文本）；一局 5 年里至少有一个秘密自然被揭发并产生后续。

### 6.2 愿望与恐惧

在现有 `wish` 基础上加 `fear`：

| 字段 | 例子 | 触发 |
| --- | --- | --- |
| `fear` | 怕水、怕孤老、怕被人看不起、怕挨饿 | 对应情境出现时心情下降，NPC 大脑回避相关行为，严重时拒绝工作或离村 |
| 短期愿望 | 每季从 3 个候选里生成一个（想要一件新披、想学一门手艺） | 满足后交情上升，未满足无惩罚 |

对玩家角色同样适用：开局出身决定一个恐惧，影响可选动作的文案和代价。

### 6.3 人生阶段

把"出生 → 成年 → 生育 → 继承"细化为：童年（0–7）、少年（8–15）、成年、壮年、老年（55+）。每段有专属动作和事件：

| 阶段 | 专属内容 |
| --- | --- |
| 童年 | 跟着大人看、玩伴、闯祸事件 |
| 少年 | 拜师学手艺、第一次独立干活、心上人 |
| 壮年 | 当家、调解纠纷、带徒弟 |
| 老年 | 讲古、传手艺（加速后辈学习）、交代后事、立遗愿 |

继承交接时，老一代未完成的愿望和知道的秘密以"遗言"形式部分传给继承人。

## 7. 阶段 4：村外与社区（4 周+）

### 7.1 地图包接入玩法

| 功能 | 用到的数据 | 说明 |
| --- | --- | --- |
| 远行 | `xia_south_hills_v0_1`、`xia_east_extension_v0_1` 的区域与连接 | 以"出门 N 天"的旅程事件呈现，不做自由探索；地形难度影响天数和风险 |
| 盐泉交易 | 南丘包的盐泉、盐滩 | 带陶器换盐，盐让鱼干/肉能存过冬 |
| 外乡人来源 | 地图包的边界锚点 | 新居民的来历从真实地点生成 |
| 事件点 | `map/event_points.yaml` | 远行途中按季节触发 |

规模仍然控制：外部地点不长期模拟人口，只作为事件和交易来源。

### 7.2 Mod 工具链

| 工具 | 作用 |
| --- | --- |
| `npm run pack:new <id>` | 生成内容包骨架（manifest + 空文件 + README） |
| `npm run pack:check [dir]` | 单独校验一个包，输出所有问题，内容作者不用跑全量测试 |
| `npm run pack:preview <id>` | 用该包开一局，自动跑 1 年，输出该包内容被触发的统计 |
| 图鉴自动收录 | 包里的物品、配方、居民、事件自动出现在图鉴，标注来源包 |
| 加载外部代码模块（后续） | `mods/<id>/` 目录下的系统模块按 manifest 动态 import；先只对本地开放，不做在线分发 |

### 7.3 "我这一生"

利用确定性：导出 `种子 + 开局选项 + 指令日志 + 内容包列表`（几 KB 的文本），别人导入后可以完整重放；附一份自动生成的生平（基于 `historical-memory` 和事件记录）。也是调试和回归测试的利器。

## 10. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 事件变多后 NPC 日程挤占（生日测试已暴露） | 阶段 0 定日程容量规则；事件选角时检查当天是否已被占用 |
| 叙事者调参陷入无底洞 | 先用统计验收（事件间隔分布），不追求"手感"；三种模式只调一个参数表 |
| 秘密系统泄露信息、破坏认知层 | 所有投影加"不泄露"测试；秘密文本只在确知后出现 |
| 拆模块破坏存档 | 每次拆分带迁移 + 旧存档回归测试（用现有存档样本） |
| 内容作者写出"只有一个正确答案"的事件 | 写作标准 + 评审清单；覆盖测试统计每个选项被选比例，长期 < 10% 的选项要改 |
| 范围蔓延到战斗/建造 | 回到第 2 节定位表，先改表再改代码 |
| 确定性被新系统破坏 | 所有新模块只用世界随机数；"同种子同指纹"测试覆盖新模块全开的配置 |
