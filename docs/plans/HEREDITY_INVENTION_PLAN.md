# 禀赋、发明与学问：设计书

日期：2026-10-17
范围：科技、政治两个大插件 + 天命扰动 + 时代识别，以及配套内容包格式
- `heredity`（禀赋 / 遗传）：基因决定外貌和各项能力的**上限**
- `invention`（发明）：村民因需要而造出新工具、新做法
- `village-learning`（学问）：村民从现象里总结道理，道理有对有错，能被检验、传授、失传

依据：现有 `packages/contracts/src/knowledge.ts`（知识图谱）、`science-research`（观察→体会）、`knowledge-transmission`（传授）、`modern-science`（"世界真相"与"文明所知"分离）、`intellectual-history`（观点、追随者、学派）、`family`（婚育、世系）、`settlement-locations` 的手艺与配方。

---

## 0. 先说结论

### 0.1 你的三个想法分别怎么落地

| 你的想法 | 判断 | 落地方式 |
| --- | --- | --- |
| 基因只决定上限 | **很对**，而且是最关键的一条 | 基因给"天花板"，实际水平由吃得饱不饱、练得多不多、有没有人教决定。绝大多数人一辈子碰不到天花板 |
| 靠物竞天择推进科技 | **要改一下** | 生物进化太慢：80 人的村子几百年里基因几乎不变。真正推动科技的是**文化上的物竞天择**：好用的做法和道理传开，没用的被淘汰，没人教的失传。基因只影响"谁更可能想出来" |
| 村民想要工具 → 记录 → 下次更新做出来 | **作为开发流程很好，作为游戏内机制不够** | 拆成两层：游戏内从"已写好但藏着的发明图"里自己发现（玩家不用等更新）；游戏外把村民反复卡住的需要记成《需要簿》，开发者据此写新的发明内容包 |
| 理论不知道怎么设计才有用 | 见 0.2 | 理论必须有**机械效果**，否则就是图鉴 |

### 0.2 理论怎么才"有用"

一条道理在游戏里只做四件事，每件都有具体数值效果：

| 用处 | 例子 | 效果 |
| --- | --- | --- |
| **预测** | 懂"水候"：知道某颗星黄昏出现后二十来天河要涨 | 灾情的"征兆"提前出现；可以提前筑堤、搬罐 |
| **举一反三** | 懂"撬"的道理（杠杆） | 撬棍、桔槔、踏碓这一类发明的门槛大降；不懂就只能一个个碰运气 |
| **提高上限** | 懂"火候"：慢火升温不裂 | 陶器成品率、可达品质上限提高 |
| **定规矩** | 懂"脏水致病" | 村里形成"喝开水"的习惯，疫病概率下降 |

而且**道理可以是错的**。错的道理（"河神发怒才涨水"）也会有人信、也有效果（祭祀让人心齐），但预测不准，久了会被事实推翻，或者一直错下去。这是整个系统最有戏的地方。

### 0.3 模块关系

```
family（婚育）──出生──▶ heredity（禀赋）──上限──▶ 手艺 / 学习 / 体力 / 抗病
                                     │
                          悟性、手巧、眼力
                                     ▼
需要（饥饿、灾情、失败的动作）──▶ invention（发明）◀── 道理降低门槛 ── village-learning（学问）
                                     │                                   ▲
                                     ▼                                   │
                           新配方 / 新工具 / 新做法            现象与观察（灾情、收成、病）
                                     │                                   │
                                     └──── knowledge-transmission（传授）─┘
                                                 │
                                         没人教 → 失传
```

三个模块都可以单独关掉：
- 关 `heredity`：所有人上限相同，其他系统照常。
- 关 `invention`：只有内容里写死的配方，和现在一样。
- 关 `village-learning`：发明只能靠反复试，没有"举一反三"和预测。

## 1. 禀赋系统 `heredity`

### 1.1 设计原则

1. **只定上限，不定结果**。上限之下，营养、练习、师承决定一切。
2. **看不见基因**。玩家只能通过观察知道"这孩子手巧""长得像他娘"，与现有认知层一致。
3. **外貌只是外貌**。外貌基因与任何能力无关联，避免"长相决定本事"。
4. **没有"更好的人"**。每项禀赋都有代价或适用场景（个子大吃得多、记性好的人不一定手巧），不提供综合评分。
5. **确定性**。所有遗传随机都走世界随机数，同种子同结果。

### 1.2 基因组

每人 14 个位点，每个位点两份（父母各给一份）。每份是一个 0–4 的小整数或一个字母（外貌）。

| 类别 | 位点 | 表现 | 影响的上限 |
| --- | --- | --- | --- |
| 身体 | 体格 ×2 | 高矮壮瘦 | 力气上限、负重；**吃得更多** |
| | 耐力 ×1 | — | 连续干活时长上限 |
| | 体质 ×2 | — | 抗病、抗饥、寿命倾向 |
| | 耐寒 / 耐热 ×1 | — | 冬夏的体力消耗 |
| 手眼 | 手巧 ×2 | — | 手艺品质上限、发明中"做出来"的概率 |
| | 眼力 ×1 | — | 观察质量（学问系统里积累观察的速度） |
| 心智 | 悟性 ×2 | — | 学会一门手艺/道理的速度上限、能理解的道理深度 |
| | 记性 ×1 | — | 记住的人、事、道理数量；传授时的保真度 |
| 外貌 | 发色、肤色深浅、眉眼、脸型、个子（与体格联动的外观描述） | 纯描述 | 无 |

刻意不设"智力"这个总数：悟性、记性、眼力、手巧分开，一个人很少样样都高。

### 1.3 从基因到人

```
基因 ──遗传──▶ 禀赋上限（0–100）
                    │
童年营养（0–7 岁吃不饱的天数）──折损──▶ 实际可达上限（最多折 25%）
                    │
练习 / 师承 / 年龄 ──成长──▶ 当前水平（永远 ≤ 实际可达上限）
```

- **上限值** = 两份等位基因的平均 + 小幅随机（±5）。体质类取较高者（显性），外貌按显隐性。
- **营养折损**：童年挨饿会永久压低上限。这让饥荒有跨代后果，也和现有 `hunger` 系统接上。
- **成长曲线**：现有手艺学习照旧，只是在接近上限时变慢，到上限停止。
- **老年衰退**：55 岁后体力类上限每年下降，心智类基本不降（记性可能下降）。

### 1.4 自然选择从哪来（诚实地说）

在 10–80 人、几代人的尺度上，选择压力确实存在，但主要表现为：

| 机制 | 来源 | 玩家感受到的 |
| --- | --- | --- |
| 饥荒、疫病、灾情中体质差的人更容易死 | 现有 hunger、illness、hazard 读取体质上限 | "那年冬天走的多是本来就弱的" |
| **近亲通婚** | 小村子必然出现 | 后代体质下降、夭折增加；促使和外乡人通婚（接阶段 4 远行和外乡人） |
| 婚配偏好 | NPC 择偶时看外貌和本事（可配置） | 某些特征在村里慢慢变多 |
| 随机漂变 | 人少 | 几代后村里"都长得有点像" |
| 地方适应（长期） | 冬季耐寒、夏季耐热 | 只在编年快进（几百年）中可见 |

**结论**：自然选择给的是"家族相似、近亲的代价、灾年的残酷"，不给科技进步。科技进步交给第 2、3 节的文化选择。

### 1.5 玩家怎么看到

全部经过认知层：

| 认识程度 | 能看到的 |
| --- | --- |
| 陌生 | 外貌描述（"一个高个子、黑脸膛的汉子"） |
| 见过 | 外貌 + 明显体格（"力气大"） |
| 相识 | 你观察到的本事（"手巧""学东西快"），基于他实际做过的事 |
| 很熟 / 亲人 | "这孩子像他爷爷，是块做陶的料" —— 对上限的模糊判断 |

数值上限永远不直接显示（调试面板除外）。

### 1.6 数据与组件

```
heredity.genome       { loci: Record<locusId, [allele, allele]>, mutated?: locusId[] }
heredity.potential    { [traitId]: number }   // 出生时算定
heredity.development  { stuntedBy: number, ... } // 童年营养折损
heredity.lineage-coef { inbreeding: number }   // 近交系数
```

内容包可新增位点和性状（`genes.json`），例如魔法世界加"灵根"；不可改基础位点。

```json
{
  "id": "locus:base.dexterity",
  "label": "手巧",
  "copies": 2,
  "alleles": { "min": 0, "max": 4 },
  "expression": "mean",
  "affects": [{ "trait": "trait:base.craft-ceiling", "weight": 25 }],
  "mutationRate": 0.002
}
```

能力：`provides: ["life.heredity"]`，`requires: ["family.relationship_provider"]`，`optional: ["settlement.hunger", "life.illness"]`。其他模块用 `getCapability("life.heredity")?.ceiling(personId, traitId) ?? 100` 读取，关掉模块时自动退回无上限。

### 1.7 初代怎么来

开局村民没有父母，按"起始人群"数据生成基因（`founders.json`），可指定某人"体格好""悟性高"，与现有人物设定保持一致。外乡人的基因按来源地的人群参数生成，带来新的等位基因。

## 2. 发明系统 `invention`

### 2.1 核心思路

发明 = **需要 × 材料 × 道理 × 人 × 时间 × 运气**。

所有可能的发明事先写在数据里（发明图），但对玩家和村民都是藏着的。村民在生活里被需要推着，满足条件时有概率"想到"，再经过反复试做真正"做出来"，然后靠传授扩散或失传。

### 2.2 需要从哪来：需要簿

系统自动记录村里反复出现的"不方便"：

| 来源 | 例子 | 记录为 |
| --- | --- | --- |
| 动作失败或代价高 | 打水来回十趟、扛石头扛不动 | `need:lift-water`、`need:move-heavy` |
| 资源损失 | 鲜鱼两天就坏 | `need:preserve-food` |
| 灾情 | 涨水淹了罐子 | `need:protect-from-flood` |
| NPC 抱怨（自主大脑里目标受阻） | "要是有个东西能……" | 对应的 need |
| 玩家输入（可选） | 玩家对村民说"要是能……就好了" | 自由文本 + 最接近的 need |

每个需要有**强度**（最近一年累计受阻次数，随时间衰减）。

需要簿有两个用途：

1. **游戏内**：强度高的需要提高相关发明被想到的概率。
2. **游戏外（你的想法）**：`npm run needs:report` 导出所有存档里"强度高但没有对应发明"的需要，以及玩家输入的自由文本。开发者和内容作者据此写新的发明内容包，下次更新加入。已有的存档读到新内容包后，这些需要就有了出路。

这样玩家不用等更新也有发明可做，而更新又是由真实玩法数据驱动的。

### 2.3 发明数据格式

```json
{
  "id": "invention:base.shadoof",
  "name": "桔槔",
  "kind": "tool",
  "blurb": "一根长杆架在木桩上，一头绑石，一头挂桶，打水省一半力。",
  "answers": ["need:lift-water"],
  "requires": {
    "materials": ["resource:timber", "resource:rope", "resource:stone"],
    "tools": ["prototype:stone-axe"],
    "knowsAny": ["prototype:pry-bar"],
    "place": "place:river"
  },
  "principles": ["theory:base.leverage"],
  "difficulty": 60,
  "aptitude": { "insight": 0.5, "dexterity": 0.5 },
  "trials": { "attempts": 4, "materialsPerAttempt": { "resource:rope": 1 } },
  "unlocks": {
    "prototypes": ["prototype:base.shadoof"],
    "recipes": ["recipe:base.shadoof"],
    "effects": [{ "action": "fetch-water", "costMultiplier": 0.5 }]
  },
  "naming": ["桔槔", "吊杆", "{inventor}家的杆子"]
}
```

| 字段 | 含义 |
| --- | --- |
| `kind` | `tool`（工具）/ `technique`（做法，如腌制、轮作）/ `structure`（构筑，如土堤、粮窖）/ `custom`（规矩，如轮值看水） |
| `answers` | 回应哪些需要 |
| `requires` | 硬条件：材料见过、工具有、知道某个前置发明、在某地 |
| `principles` | 懂这些道理时难度大幅下降（见 3.4） |
| `difficulty` | 0–100 |
| `aptitude` | 哪些禀赋影响成功率（关掉 heredity 时视为中等） |
| `trials` | 想到之后要试几次、每次消耗多少材料（用现有 `practice-runtime` 的检查点机制） |
| `unlocks` | 做出来之后开放的原型、配方、动作效果 |
| `naming` | 名字可随发明者变化（"阿石家的杆子"），增加归属感 |

### 2.4 一次发明的生命周期

```
需要积累 ─▶ 灵光（想到）─▶ 试做（Practice，多次检查点）─▶ 做成 ─▶ 传开 / 失传
              │                  │
              │            失败消耗材料，可能放弃
         概率由下式决定
```

**每季一次的"灵光"判定**（每个成年村民、每个满足硬条件的候选发明）：

```
p = 基础 0.5%
  × 需要强度系数（0–3）
  × 禀赋系数（悟性、手巧相对上限，0.5–2）
  × 道理系数（懂对应道理 ×5；懂错误道理 ×0.5–1）
  × 接触系数（亲眼见过类似东西 ×2，例如见过外乡人的工具）
  × 闲暇系数（饿着、病着、灾中 ×0.2）
```

- 同时满足的候选可能有好几个，一季最多一人想到一个。
- 玩家角色同样判定；玩家也可以主动"琢磨"某个需要，提高自己的概率但占用时间。
- 想到后，发明者获得"想法"（个人认知状态），开始试做。

**试做**：每次尝试消耗材料和时间，成功率由手巧和道理决定。失败会给"心得"（下次成功率上升）。连续失败太多，脾性急的人会放弃，想法留在记忆里，可能被教给别人。

### 2.5 扩散与失传

这是"文化上的物竞天择"的核心：

| 规则 | 说明 |
| --- | --- |
| 发明属于人，不属于村 | 做出来后只有发明者会做；别人要靠看（慢、走样）或被教（`knowledge-transmission`） |
| 好用就传得快 | 每次使用节省的成本越大，旁人越想学（学的意愿 = 收益 × 与发明者的交情） |
| 没人教就失传 | 会做的人都死了、实物也坏了 → 该发明回到"藏着"状态；村史里留下"从前有人会做……"，后人重新发明时难度降低 |
| 人少更容易失传 | 自然出现"人口越多、技术越稳"的效果（塔斯马尼亚效应），把村落成长目标和科技绑在一起 |
| 实物可以被"拆着学" | 留下的工具能让后人倒推做法，降低重新发明难度 |

### 2.6 组合式发明（远期，可选）

预写的发明图终究有限。远期可以加一层"功能原语"：

```
功能：盛、切、绑、撬、滚、烧、晒、挡、引水、计数 ……
材料：陶、木、石、皮、绳、苇 ……
```

村民的需要映射到功能，功能 × 可用材料生成一个"无名器物"（例如"盛 + 苇 = 苇编的盛器"），效果按功能和材料属性计算，名字由命名规则生成。好用的组合被需要簿记录，开发者可以把它"转正"为正式发明。先不做，等预写发明图跑通再评估。

## 3. 学问系统 `village-learning`

### 3.1 为什么要有"世界真相"和"村民以为"两层

现有 `modern-science` 已经把"世界规律"（隐藏，开局固定）和"文明所知"分开。学问系统沿用这一点：

- **世界真相**：数据里写死。例如"涨水跟随季节与上游降雨"。
- **村民的道理**：可以对、可以错、可以半对。效果按"道理与真相的吻合度"计算。

### 3.2 一条道理的生命周期

完全对应合约里已有的知识节点类型：

| 阶段 | 节点类型 | 例子（水候） | 怎么推进 |
| --- | --- | --- | --- |
| 现象 | `phenomenon` | 河水每年涨落 | 世界本来就有 |
| 观察 | `observation` | 阿石刻木记下每次涨水的日子 | 村民亲历现象且眼力够时自动积累；可被引导去"记" |
| 猜想 | `theory` | A：河神发怒；B：涨水跟着星象走 | 观察够多时，悟性高的人提出猜想；**同一现象可以同时出现多个竞争猜想** |
| 证据 | `evidence` | 按 B 预测涨水，三年准了两年 | 每次猜想做出预测，事实来了就记一次准或不准 |
| 学问 | `knowledge` | 水候成为村里公认的道理 | 证据够多、信的人够多 |
| 能力 | `capability` | 提前筑堤；水退后在淤泥地抢种 | 解锁动作、提高发明效率 |

### 3.3 道理数据格式

```json
{
  "id": "theory:base.flood-follows-stars",
  "label": "水候",
  "explains": "phenomenon:base.river-rise",
  "claim": "黄昏时{star}出现后二十来天，河就要涨。",
  "truth": 0.85,
  "needsObservations": 6,
  "aptitude": { "insight": 0.6, "memory": 0.4 },
  "predicts": { "event": "hazard:flood", "leadDays": 20, "accuracy": "truth" },
  "effects": [
    { "type": "hazard-forewarning", "hazard": "flood", "leadDays": 20 },
    { "type": "principle-for", "inventions": ["invention:base.flood-calendar-stick"] }
  ],
  "rivals": ["theory:base.river-god"]
}
```

```json
{
  "id": "theory:base.river-god",
  "label": "河神发怒",
  "explains": "phenomenon:base.river-rise",
  "claim": "村里有人做了亏心事，河神就发怒涨水。",
  "truth": 0.05,
  "needsObservations": 2,
  "effects": [
    { "type": "custom", "unlocks": "custom:base.river-offering" },
    { "type": "social", "cohesion": 0.2 },
    { "type": "blame", "onEvent": "hazard:flood", "target": "someone-with-grudge" }
  ]
}
```

关键点：

| 设计 | 说明 |
| --- | --- |
| `truth` 0–1 | 决定预测准确率与实际效果；玩家看不到这个数 |
| 错误道理更容易出现 | `needsObservations` 低：两次就能"总结"出河神。真实世界里也是这样 |
| 错误道理也有效果 | 祭祀让人心齐（交情 +），但会找替罪羊（与秘密系统、争执系统咬合） |
| 竞争 | 同一现象的多个道理互为 `rivals`；每次预测之后信的人重新分配 |
| 信谁看人 | 信一个道理的意愿 = 证据 × 提出者的威望 × 交情。埴公说错了，大家也会信一阵 |

### 3.4 道理怎么作用于发明

这是"理论有用"的核心：

| 关系 | 规则 |
| --- | --- |
| 原理覆盖一族发明 | 懂"撬"（杠杆）→ 撬棍、桔槔、踏碓、杵的难度全部 ×0.3，灵光概率 ×5 |
| 不懂原理也能发明 | 只是靠碰运气，概率低、试做次数多；做出来后可能反过来启发出原理（"为什么长杆省力？"） |
| 错误原理会带偏 | 例如"东西坏是因为沾了晦气" → 发明方向偏向驱邪做法，而不是盐渍晾晒 |
| 原理提高品质上限 | 懂"火候" → 陶器成品率和品质上限上升；人的手巧上限仍然起作用 |

### 3.5 首批道理与发明（河岸台地，约 12 条道理 + 20 项发明）

| 现象 | 对的道理 | 错的/半对的道理 | 带出的发明 / 能力 |
| --- | --- | --- | --- |
| 河水涨落 | 水候（星象、物候） | 河神发怒 | 刻木记日、提前筑堤、淤泥抢种 |
| 东西会坏 | 湿热则腐，干、盐、烟可止 | 沾了晦气 | 鱼干架改良、盐腌、烟熏、粮窖 |
| 陶器烧裂 | 火候：慢升温、坯要干透 | 窑神不喜 | 二次烧、封窑、匣钵 |
| 重物难移 | 撬（杠杆）与滚 | — | 撬棍、滚木、桔槔、踏碓 |
| 喝生水生病 | 脏水致病 | 中邪 | 煮水、井、滤水罐 |
| 地越种越薄 | 地要歇、要喂 | 地气被人吸走 | 轮作、休耕、草木灰肥田 |
| 季节轮转 | 节令（二分二至） | — | 历法、按节播种（收成 +） |
| 伤口溃烂 | 伤口要净 | 伤者命薄 | 清洗、草药敷、缝合 |
| 狼群来去 | 狼跟着鹿群走 | — | 守夜轮值、陷阱位置 |
| 孩子像父母 | 种随根（遗传的朴素认识） | 胎中所见 | 择偶习俗、近亲禁婚（直接降低近交代价，连接第 1 节） |

最后一行把三个系统连成一圈：村民通过观察总结出朴素的遗传道理 → 形成近亲禁婚的规矩 → 改变自然选择的结果。

### 3.6 道理的传播与失传

- 道理和发明一样属于人，靠传授扩散（复用 `knowledge-transmission`，传授有保真度，记性差的学生会学走样，走样的版本 `truth` 下降）。
- 有了"刻木记日""结绳"一类记录发明后，观察可以存在实物上，不随人死而消失（为远期"文字"留接口）。
- `intellectual-history` 已有观点/追随者/学派：村里信水候的人和信河神的人可以形成两派，在灾年发生争执。

## 4. 玩家的位置

玩家不是"点科技树"的上帝，而是村里的一个人：

| 玩家能做 | 效果 |
| --- | --- |
| 自己去琢磨某个不方便 | 提高自己想到的概率，占用时间 |
| 去"记"（刻木、观察） | 加速观察积累 |
| 提出或支持某个道理 | 用自己的威望影响谁信什么 |
| 拜师 / 带徒 | 决定发明和道理传不传得下去 |
| 和外乡人交往 | 见到外来工具（接触系数），带来新基因 |
| 选择婚配 | 影响后代禀赋；近亲代价 |
| 对村民说"要是能……就好了" | 写入需要簿（游戏内提高强度，游戏外进开发者报告） |

界面：在现有文字界面里加一个"村里的学问"页（只显示玩家知道的）和"我的想法"页（自己正在琢磨/试做的东西），每日小结里提一句"阿石又在河边刻木头了"。

## 5. 节奏与平衡

### 5.1 目标节奏

| 时间尺度 | 期望 |
| --- | --- |
| 一年 | 村里出现 0–2 个新想法，0–1 个真正做成 |
| 一代人（约 25 年） | 6–12 项发明、2–4 条道理成为公认；至少一次失传或错误道理盛行 |
| 五代 | 村子的面貌明显不同：有了粮窖、桔槔、历法、近亲禁婚 |

### 5.2 编年快进

单局玩一代人只能看到一部分。提供"编年模式"：玩家角色去世后可选择快进 N 年（全自动模拟），结束时输出一份村史：谁发明了什么、哪些道理被推翻、哪些手艺失传。确定性保证快进可重放。需要先做性能预算（几十年 × 80 人的模拟耗时）。

### 5.3 防止玩家把它玩成"配种游戏"

- 上限很少成为瓶颈（大多数人一生只到上限的 50–80%）；营养和师承的作用远大于基因。
- 禀赋数值不显示，只有模糊描述。
- 择偶由 NPC 双方意愿决定，玩家只能影响自己和子女。

## 8. 测试清单

- 确定性：同种子 + 同指令，基因、发明、道理全部一致。
- 遗传：大样本下等位基因频率、显隐性、突变率符合配置。
- 上限：任何水平不超过实际可达上限；关闭 heredity 时上限为 100。
- 认知：任何投影都不泄露基因数值、道理的 `truth`、未发现的发明。
- 失传：会做的人全部死亡且无实物 → 发明回到隐藏，村史有记录。
- 兼容：三个模块任意组合关闭，都能开局、玩 3 年、存读档。
- 内容包：坏的 `inventions.json`（引用不存在的道理/材料）在启动时给出明确错误。

## 9. 从村落到工业革命：时代演进与天命扰动

### 9.1 总原则：时代是"认出来的"，不是"解锁的"

现有 `historical-era` 模块的注释已经定下规矩：时代只是背景，不负责解锁科技。这里沿用并强化：

- **没有"进入青铜时代"按钮**。世界状态满足条件时，系统**认出**"这已经是青铜时代了"，并记入村史。
- 推动时代的只有四样东西：**人口、剩余、发明与学问、制度**。它们彼此推动，形成正反馈或崩溃。
- 每个时代可以倒退（人口崩溃、技术失传、制度瓦解），不是单向阶梯。

### 9.2 拆成两个大插件：科技与政治

同意你的想法，拆成两个互不直接依赖的插件，通过能力和组件通信：

| 插件 | 包含 | 提供的能力 | 读取的能力（可选） |
| --- | --- | --- | --- |
| **科技** `tech`（前文的 invention + village-learning 合并为一个插件组） | 需要簿、发明、道理、扩散失传、能源与材料 | `tech.invention`、`tech.learning`、`tech.capabilities`（当前掌握的能力清单）、`tech.productivity`（每人产出系数） | `polity.labor`（谁在干活、被迫干活）、`polity.institutions`（有没有师承制度、作坊、书院） |
| **政治** `polity` | 财产、分工、等级、权威、法度、奴役、聚落间关系、国家 | `polity.institutions`、`polity.labor`、`polity.authority`、`polity.surplus-claims`（剩余归谁） | `tech.productivity`、`tech.capabilities`、`life.heredity`、`social.conflict` |
| **时代识别** `historical-era`（已有，扩展） | 只读两边状态，判断时代、写村史 | `era.current` | 两边全部 |
| **天命** `fate`（新） | 扰动工具，见 9.6 | `fate.perturbation` | 全部（只通过各模块公开的命令施加影响） |

只装科技：技术会进步，但社会永远是平等的小村子。只装政治：会出现等级和争权，但技术停在开局水平。两个都装，才有完整的历史。

### 9.3 驱动时代的四个量

| 量 | 来源 | 推动什么 |
| --- | --- | --- |
| **人口与密度** | 婚育、外乡人、死亡（heredity、family） | 人越多，想到新东西的人越多，失传越少；人太多而粮不够则崩溃 |
| **剩余** | 产出 − 消耗（科技提高产出） | 有剩余才养得起不种地的人（专门的陶匠、祭司、头人）；剩余可以被储存、被抢、被占有 |
| **能力** | 科技插件的已掌握能力 | 决定能做什么：储粮、冶炼、文字、轮、畜力、水力、蒸汽 |
| **制度** | 政治插件 | 决定剩余归谁、谁干活、知识怎么传：财产、师徒、作坊、奴役、法度、市场 |

关键的反馈环：

```
能力 ↑ ─▶ 剩余 ↑ ─▶ 可以养专门的人 ─▶ 分工 ─▶ 专门的人更快想到新东西 ─▶ 能力 ↑
                │
                └─▶ 剩余可以被占有 ─▶ 财产与等级 ─▶ 有人有动机强迫别人干活 ─▶ 奴役
                                                     │
                     劳动廉价 ─▶ 省力发明的动机下降 ◀─┘   （奴役会压低"需要"强度）
                     劳动昂贵 ─▶ 省力发明的动机上升 ─▶ 机械、畜力、水力、蒸汽
```

最后两行是工业革命的经典解释之一（劳动力贵、能源便宜时，才值得发明机器）。系统里它自然落在"需要簿"上：谁觉得累、谁在意累，决定需要的强度。被迫干活的人的辛苦，不进主人的需要簿。

### 9.4 时代识别表（示例，可由内容包替换）

| 时代 | 识别条件（全部满足并持续 N 年） | 典型新东西 |
| --- | --- | --- |
| 定居村落（开局） | 有固定住所、种粟 | 陶、鱼干、土堤 |
| 丰年村落 | 存粮能撑全村一冬以上 5 年；出现第一个不种地的专门手艺人 | 粮窖、历法、轮作 |
| 部落 / 联村 | 与 ≥2 个其他聚落有固定往来；出现跨村头人 | 集市、婚姻联盟、共同祭祀 |
| 铜石并用 | 有人掌握冶铜且持续使用 10 年 | 铜刃、铸范；矿石来自地图包 |
| 城邑 | 某聚落人口 ≥ 500（聚合层，见 9.5），有城墙或大型公共工程 | 夯土、徭役、仓廪 |
| 等级社会 | 剩余被少数家族长期占有；出现世袭身份 | 贵族、依附民、债役 |
| 奴役制度 | 见 9.4.1 | — |
| 文字与法度 | 有记录发明，且有成文规矩被引用 | 刻符、盟书、律令 |
| 铁器与帝国 | 冶铁；多城邑归于一个权威 | 铁犁、郡县、赋税 |
| 手工工场 | 一处集中 ≥ 20 名专门工匠，按工序分工 | 作坊、行会、雇佣 |
| 工业革命 | 非人畜动力占生产能源的多数；机器制造机器 | 水力、蒸汽、煤铁 |

#### 9.4.1 奴役：怎么严肃地做

奴役是历史上反复出现的制度，做历史模拟回避它会失真，但必须严肃处理：

| 设计 | 说明 |
| --- | --- |
| 自然生成，不预设 | 只在条件成立时出现：有可占有的剩余 + 劳动密集的产出 + 有人无力反抗（欠债、被俘、受罚、外来无依者）+ 权威能执行 |
| 来路 | 债役（借粮还不上）、刑罚、聚落冲突中被抓（冲突用抽象事件表达，不做战斗）、买卖 |
| 有代价 | 被奴役者怨气持续累积、逃亡、反抗；邻里之间的道德冲突事件；生产效率低于自愿劳动；压低省力发明的动机 |
| 有反对的可能 | 道理系统可以产生"人不该被当作牲口"这类观念（`intellectual-history` 的观点与学派），它会传播、会和既得利益冲突、可能导致废除 |
| 玩家立场自由但后果真实 | 玩家可以反对、解救、参与，各有后果；不提供"奴隶管理"式的优化界面 |
| 可关 | `polity` 插件内的独立子模块 `polity-bondage`，可单独关闭；开局时提示 |

### 9.5 规模问题：一个村子到不了工业革命

诚实地说：80 个人的村子，即使模拟几千年，也不可能独立走到工业革命。历史上的工业革命需要几百万人口、跨地区贸易和几千年的知识积累。

解决办法是**分层细节（LOD）模拟**：

| 层 | 对象 | 粒度 | 规模 |
| --- | --- | --- | --- |
| 个体层 | 玩家所在聚落 | 每个人：基因、关系、认知、日程 | 10–80 人 |
| 人群层 | 邻近聚落（地图包里的其他地点） | 按户 / 按年龄段：人口、存粮、掌握的能力、制度、与玩家村的关系 | 几个到几十个聚落，数千人 |
| 文明层 | 更远的地区 | 统计量：人口、能力集合、制度类型、传播速度 | 任意 |

- 发明和道理可以在任何一层产生，并沿着往来关系扩散。玩家村可能是发明者，也可能是接收者。
- 玩家关心的始终是个体层；当玩家所在村子被卷入城邑和国家时，个体层仍然是这个村子，外面的城与国在人群层和文明层运转。
- 编年快进（设计书 5.2）在快进期间可以把个体层也降到人群层，结束时再"展开"回个体（按统计重新生成具体的人和关系）。

### 9.6 天命扰动 `fate`

你说的"系统控制概率来影响走向"，做成一个独立插件。核心原则：**扰动只改概率和初始条件，不改规则，也不直接改结果**。

#### 9.6.1 扰动的种类

| 扰动 | 做什么 | 例子 | 解释 |
| --- | --- | --- | --- |
| 降生 | 指定某次出生的部分等位基因取到分布的尾部 | 让阿予的孙子悟性、记性都在前 1% | 本来就可能出生，只是概率很小 |
| 灵光 | 某个人或某个需要的灵光概率 × k，持续一段时间 | 未来十年冶铜的灵光 ×3 | 机缘 |
| 际遇 | 安排一次相遇或见闻 | 一个带着铜刀的外乡人路过 | 接触系数 |
| 天时 | 调整一段时间的气候、灾情概率 | 连续三年旱 | 环境压力推动储粮、灌溉的需要 |
| 人心 | 调整某个观念的传播意愿 | "人不该被当作牲口"的说法更容易被接受 | 风气 |

刻意**不提供**：直接给某人一项发明、直接改某人对某事的看法、直接让某人死。这些会破坏"是系统自己演出来的"这件事。

#### 9.6.2 天命点与模式

| 模式 | 扰动 | 适合 |
| --- | --- | --- |
| 旁观 | 不可用 | 纯粹看历史自己走 |
| 微调（默认关闭，开局选择） | 每个时代有少量天命点；尾部越极端花费越高 | 你说的"一点点人为扰动" |
| 实验室 | 无限制，并显示各项概率 | 设计调试、写内容包 |

每一次扰动都作为一条指令写进指令日志，所以**同种子 + 同指令（含扰动）= 同一段历史**，确定性不被破坏。村史里会标出"此处有天命"（可选择隐藏）。

#### 9.6.3 历史实验室

确定性带来的独特玩法：

1. 在任意时刻分叉存档。
2. 一边什么都不做，另一边降生一个天才 / 安排一次际遇。
3. 两边都快进 300 年，系统并排输出两份村史，并标出第一次分歧发生在哪里、哪项发明提早或推迟了多少年、哪些制度因此出现或没出现。

这回答了你最初的问题——"一个天才能不能改变历史"——而且答案是由模拟算出来的，不是写死的。很可能常见的结论是：天才生在没剩余、没人能教的年代，什么也留不下；生在对的时代，能把某项发明提前几十年。

### 9.7 内容规模与分期

| 期 | 内容 | 规模估计 |

### 9.8 新增测试

- 天命扰动只通过指令日志生效；去掉扰动指令重放，历史回到原样。
- 时代识别只读状态、不写状态（关掉 `historical-era` 时其他模块结果完全一致）。
- 只装科技、只装政治、两者都装三种配置都能连续快进 300 年不崩。
- 奴役子模块关闭时，任何路径都不会产生被奴役状态。
- LOD 展开 / 收拢前后，人口、能力、制度的统计量守恒。

## 10. 需要你拍板

1. 14 个位点和"不设智力总数"的方案是否认可。
2. 需要簿的"游戏外"用途：是否要收集玩家输入的自由文本（涉及隐私和存档上传方式）。
3. 错误道理是否要能"一直错下去"（更真实），还是保证长期会被纠正（更友好）。
4. 编年快进是否值得投入性能预算。
5. 这三个模块放在主规划的哪个阶段。
6. 科技 / 政治 / 天命 / 时代识别四个插件的划分是否认可。
7. 奴役子模块是否纳入首个政治版本，还是放到 T4。
8. 天命默认关闭、开局选择，是否合适。
