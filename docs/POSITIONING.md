# OpenLife 定位（POSITIONING）

> 本文是**取舍依据**，不是愿景。任何违背表中某一条的需求，先改这张表，再改代码。
> 依据：制作人与项目负责人 2026-10-18 评审（本地 `2b7f9c8`）。

## 一句话定位

**玩家扮演一个生活在河岸聚落里的人，通过手艺、关系和选择改变身边的世界；人生结束后，从下一代继续。**

## 三层的从属关系

三层可以共存，但必须有主次。**玩家的身份决定了能看到什么、能做什么。**

| 层级 | 呈现方式 | 玩家的位置 |
| --- | --- | --- |
| **个人生活** | 玩家直接行动的主体：今天做什么、和谁说话、把东西给谁 | 就是这个人 |
| **家庭与村落** | 行动发生后产生影响与反馈的环境 | 村里的一员，受它影响也影响它 |
| **文明与时代** | 长期变化的背景和结果 | 隔着一层，看到的是后果不是过程 |
| **历史实验室** | 独立推演入口，服务研究与调参 | 不在这个世界里，是工具 |

### 权限必须与社会身份一致

普通村民不能天然拥有村长才有的管理权。玩家当上头人后，才获得相应职责；远行回来，才能带回沿途见闻。

**操作权限、知情范围和社会身份三者要一致。** 任何"为了方便"而越权的界面，都在破坏这一条。

## 取舍表

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 深度还是规模？ | **深度**。村子 10 → 50 人，**上限 80** | 认知系统只在小规模成立；80 人以内每个人都能被认识 |
| 要不要战斗？ | **不要**。冲突用关系、名声、资源、灾情表达 | 做半吊子战斗不如不做 |
| 要不要建造？ | **要，但做抽象建造**：建房、加盖、修缮都是真实玩法，用材料、人天、进度表示；**不做沙盒摆放** | 文字界面拼摆放没有优势；但"给一家人盖起一间屋"是村落成长的核心 |
| 有没有主线？ | **没有剧情主线**，有一条成长线（村子活下去并长大） | 目标感来自进度，不来自剧本 |
| 信息呈现 | **不全知是底线**，但见下方「信息边界」 | 不知道带来探索欲，不该带来操作困惑 |
| 节奏 | 季节大结算保留，**每天必须有一条可见反馈** | 玩家需要每天看到自己变强了一点 |

## 信息边界（修订）

**不全知应该带来探索欲，不应该制造操作困惑。**

| 应当隐藏 | 应当明确展示 |
| --- | --- |
| 人物内心的精确数值（好感、虔诚、恐惧强度） | 玩家**能清点**的物品：我有几个罐子、多少粮 |
| 陌生人的秘密、准确生日、他人关系网 | 行动的**时间成本与期限** |
| 别人对第三方的评价 | 交出、消耗、获得的具体数量 |
| —— | 陌生人**可稳定辨认**的特征：衣着、身份线索、常出现的地点、此前遭遇 |

「一个人不知道叫什么」仍然可以通过外貌与处境稳定识别他——这是认知系统的用意，不是让人分不清两个陌生人。

## 什么值得经营

**玩家如何逐渐认识一个人，以及多年以后，这个人怎样记得玩家。**

具体到可验证的：
- 关系不只是"越来越喜欢你"——可能信任你的手艺却不愿讲家事，也可能与你有矛盾但仍愿履约。
- 玩家的选择要在**几天后、换季后**仍被记得：谁受了帮助、谁失望、谁承担了工作、东西去了哪里。

## 「不做」清单

- 不做战斗系统、不做武器伤害、不做战术
- 不做沙盒建造（没有网格摆放、没有旋转）；**做抽象建造**
- 不做百人以上规模、不做万人城邦
- 不做内购
- 不做全知视角的界面（包括"为了方便"而显示的 NPC 属性面板）

## 已知代价

诚实记录主动放弃的东西：

| 放弃 | 代价 |
| --- | --- |
| 战斗 | 无法吸引喜欢动作/策略对抗的玩家 |
| 大规模 | 无法提供"万人城邦"的宏观成就感 |
| 主线剧情 | 玩家可能不知道自己在追求什么 → 靠成长线与三档目标补上 |

## 近期产品目标

**让玩家记住几个人，牵挂一件事，并期待看见自己选择的后果。**

验证方式不是"新增了几个模块"，而是一段完整经历：处境 → 请求或机会 → 选择 → 成本 → 后果 → 下一步。
