# OpenLife 定位（POSITIONING）

> 本文是**取舍依据**，不是愿景。任何违背表中某一条的需求，先改这张表，再改代码。
> 来源：`OpenLife拓展规划书_2026-10.docx` 第 2 节；依据是《OpenLife 与国内外模拟游戏对比调查》（`docs/notes/OPENLIFE_SIM_GAME_COMPARISON_2026-10-17.md`）。

## 一句话定位

**一个河岸村落里，几十个"你得慢慢认识"的人，被天时和彼此推着过完几代人。**

## 定位表

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 深度还是规模？ | **深度**。村子 10 → 50 人，**上限 80** | 认知系统只在小规模成立；80 人以内每个人都能被认识 |
| 要不要战斗？ | **不要**。冲突用关系、名声、资源、灾情表达 | 对比报告里那些"硬缺口"都是别人的核心，不是我们的。做半吊子战斗不如不做 |
| 要不要建造？ | 只做"修缮/加盖"这类**抽象动作**，不做自由摆放 | 文字界面做自由建造没有优势 |
| 有没有主线？ | **没有剧情主线**，有一条成长线（村子活下去并长大） | 目标感来自进度，不来自剧本 |
| 信息呈现 | **不全知是底线**：任何新界面不能绕过认知层 | 这是唯一没有对手的特色 |
| 节奏 | 季节大结算保留，**每天必须有一条可见反馈** | 星露谷的教训：玩家需要每天看到自己变强了一点 |

## 这张表意味着什么

**明确的"不做"清单**。

- 不做战斗系统、不做武器伤害、不做战术
- 不做自由建造、不做摆放网格
- 不做百人以上规模、不做万人城邦
- 不做内购
- 不做全知视角的界面（包括"为了方便"而显示的 NPC 属性面板）

## 唯一的护城河

对比 15 款模拟游戏后，OpenLife 有三点是**没有对手的**：

1. **确定性重放**——同种子 + 同指令 = 同一世界（有测试保证）。所有对比游戏都不强调这一点。
2. **认知门槛**——没有任何一款把"你不知道别人叫什么"做成系统。Sims / CK3 / Stardew / 未来人生 全是全知视角。
3. **纯文字 + 移动优先**——无一相同。

其中第 2 条是**最该保护的**。任何"为了玩家方便"而泄露信息的改动，都是在拆护城河。

## 已知取舍的代价

诚实记录我们主动放弃的东西：

| 放弃 | 代价 |
| --- | --- |
| 战斗 | 无法吸引喜欢动作/策略对抗的玩家；冲突只能靠文本与关系表达 |
| 图形 | 没有视觉吸引力，获客全靠口碑与题材 |
| 大规模 | 无法提供"万人城邦"的宏观成就感 |
| 主线剧情 | 玩家可能不知道自己在追求什么 → **这是必须靠成长线与三档目标补上的** |
