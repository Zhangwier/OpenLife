# 02 · B 组：手机端 / 跨端逐款拆解（9 款）

> 重点：竖屏单手、底部抽屉、触控热区、信息降噪、跨端复用。
> 所有评价区分「可确认」与「观察推断」（推断标 `(推断)`）。

---

## B01 · Fallout Shelter 辐射：避难所（手机/PC｜避难所经营｜2015）

**一句话**：**剖面式竖屏**——把"一栋楼"竖着切开，手指上下滑动就能看完整座避难所。

- **屏幕清单**：避难所剖面（常驻）、房间详情（居民列表）、居民卡、任务/探索、建造菜单、升级/奖励、Pip-Boy（状态）。
- **L1 信息架构**：底部 3 个一级入口（避难所 / 任务 / 建造）；**居民是"房间里的人"，不是列表**。
- **L2 布局**：竖屏；顶部一条资源带（电力/水/食物/人口/瓶盖）；**资源带用图标 + 数字，一屏 5 个**。
- **L3 颜色**：**Vault-Tec 蓝黄**（主色 2 系），危险用红；房间用不同色相区分功能，但饱和度低。
- **L4 字体**：**复古未来主义无衬线（Vault-Tec 风格）+ 装饰大写**；数字用粗体。
- **L5 透明度与融合**：顶栏**半透明蓝色玻璃**（约 0.9），压在剖面上；房间卡片是不透明色块；**警示（火灾/辐射）用整层红色闪光覆盖**（meta UI）。
- **L6 动效**：房间"呼吸"；居民走路（本作是少数必须走路的手游，我们不用）；事件出现用**电梯井上下移动**做隐喻。
- **L7**：按钮大（≥48）；资源带数字小但图标大；文字全大写英文（中文版换成黑体）。
- **可迁移做法**
  1. **剖面竖屏**：手机端"场景"可以用"院落剖面"（房屋切开、人在里面）——比平面俯视更省宽度，也更有"生活"感。
  2. **一条顶栏 5 个资源，图标为主**（→ 手机顶栏：饥饿/时间/天气，**图标 + 一词**）。
  3. **Meta UI**：整层色闪表示"出事了"（→ 我们的 `danger` 层可以做成 1 次 300ms 淡入淡出的朱砂罩，不闪光）。
- **不学什么**：玻璃质感；数字直给（我们只给文字）。

## B02 · Animal Crossing: New Horizons 集合啦！动物森友会（Switch｜生活模拟｜2020）

**一句话**：**圆角 + 圆体 + 手绘图标**，把"界面"做成"生活用品"。

- **屏幕清单**：岛（常驻）、口袋（背包，底部半屏抽屉）、Nook 手机（全屏应用网格）、DIY 手册、地图（小地图 → 全屏）、对话（底部对话框）、商店/服装店、博物馆。
- **L1 信息架构**：**没有常驻导航按钮**——所有功能通过"物品/人/手机"进入；最关键的是**底部口袋抽屉**（按 X 键 / 点按钮，半屏弹出）。
- **L2 布局**：竖屏思维（以电视横屏呈现但版式紧凑）；对话**固定在底部**，占约 40% 高度，上方人物可见。
- **L3 颜色**：**奶油白/浅木色 + 柔和粉蓝绿**；几乎不用纯黑——所有"黑色"都是深棕/深灰绿（这是社区复刻该风格时的共识铁律，非任天堂公开规范）。
- **L4 字体**：**圆体**（中文版为圆润黑体）；标题字重更粗；字号档少但对比明显。
- **L5 透明度与融合**：口袋抽屉是**奶油白不透明圆角面板**（社区复刻版把最小圆角定为 12px、按钮 pill 形，可作参考值）；对话**在对话框中**，不是浮在场景上。
- **L6 动效**：按钮按下**缩小 0.96 + 回弹**；面板滑入 200ms；**对话文字逐字出现（打字机）**；选中框轻微弹跳。
- **L7**：触控区极大；颜色对比充足；文字圆润易读（适合儿童与老人）。
- **可迁移做法**
  1. **底部口袋抽屉**：手机"行囊"改成一拉即出的半屏抽屉，而不是整页（→ 已在规划中，可强化）。
  2. **对话固定在底部，上方保留人物/场景**（→ 对话页布局：立绘顶部或中部，对话底部，选项最底）。
  3. **逐字出现 + 可点击加速**（→ `StoryBeat` 的可访问性要求）。
  4. **不用纯黑**：我们的 `--ink #232f2a` 已是墨绿黑，符合这个方向。
- **不学什么**：全圆角可爱风（与我们国风克制冲突，只借"圆角档位"）。

> 参考：[参考组件库对动森的设计铁律总结](https://blog.csdn.net/shallwegzgdj/article/details/161934014)、[Interface In Game · ACNH](https://interfaceingame.com/games/animal-crossing-new-horizons/)

## B03 · 明日方舟 Arknights（手机｜塔防养成｜2019）

**一句话**：**"画内界面" + 背景失焦 + 同一画布内位移**，把 6 层养成压成 1 层。

- **屏幕清单**：主看板（PRTS 投影）、干员列表、干员详情（升级/升阶/技能/天赋/模组）、编队、基建、采购中心、寻访、作战章节 → 关卡选择、签到/邮件/设置（浮层）。
- **L1 信息架构**：左上角"罗德岛分区"导航（把系统包装成"岛上的房间"）；**大部分二级功能在原页面上以浮窗/位移展开，不跳页**。
- **L2 布局**：横屏；干员详情页**中央是立绘，所有操作按钮都在同一画布上横向移动**（升阶=位移、查看属性=向右展开、查看详情=毛玻璃弹窗）。
- **L3 颜色**：**黑白灰 + 警戒黄**（主色 2 系）；语义色只在状态用；背景图整体降饱和。
- **L4 字体**：**中文衬线（Source Han Serif 类）+ 装饰西文（Trajan 类）+ 工业等距字（Bender 类）**；三种字体各司其职，是"古典骑士+科幻军工"的关键。
- **L5 透明度与融合**：**大量背景模糊（backdrop blur）**——层级对比度极高；浮窗覆盖在原页上，让玩家"窥见"下面的页面；噪点/网点底纹统一所有卡片。
- **L6 动效**：页面转场分语义——系统切换=深色淡出；有逻辑关联=zoom-in/out；干员养成=位移淡入。
- **L7**：文字偏小（批评点）；无缩放；手机竖屏适配差（横屏为主）。
- **可迁移做法**
  1. **同一画布内位移**：升级/合成/看故事都在当前页展开，**绝不跳页**（→ 人物详情、物品详情的"展开"模式）。
  2. **背景模糊代替遮罩**：打开面板时把背后内容模糊 8–12px（→ 手机抽屉，用 `backdrop-filter: blur(10px)`，但要测性能）。
  3. **转场语义化**：不同关系用不同过渡（→ 见规范 v2 §7 动效表）。
  4. **统一的底纹**（→ 我们的纸纹只用于少数地方，需统一一张噪点/纸纹贴图）。
- **不学什么**：横屏为主、小字、高饱和警戒黄大面积使用。

> 参考：[腾讯游戏学院 · 《明日方舟》UI/UX 分析](http://gameinstitute.qq.com/article/10027)

## B04 · Sky: Children of the Light 光·遇（手机/主机｜社交冒险｜2019）

**一句话**：**几乎没有 UI**——用"光、声音、手势"代替按钮。

- **屏幕清单**：世界（常驻，无 HUD）、好友星座、表情轮盘、季卡/商店、设置。
- **L1 信息架构**：只有 1 个常驻按钮（菜单）+ 1 个动作（长按叫喊/飞）。
- **L2 布局**：UI 基本隐藏；**只有交互时才出现图标**。
- **L3 颜色**：**环境色主导**，UI 纯白 + 半透明。
- **L4 字体**：极简无衬线，字号小但只用于提示。
- **L5 透明度与融合**：**UI 元素是 0.7 白色，无底板**，完全融入画面；菜单是半透明深色薄纱。
- **L6 动效**：所有动效都"软"（1.2s 慢缓动）；**不是提示，而是"呼吸"**。
- **L7**：手势可替代点击（放宽了精细操作）；但无文字可读性设计（弱）。
- **可迁移做法**
  1. **无底板 UI**：只有文字 + 光晕（→ 场景级提示如"河边"）。
  2. **"叫一声"式动作**而非按钮（→ 我们的"登门/呼唤"可以有轻量手势反馈）。
  3. **慢缓动**（1.2s，`ease-in-out`）用于氛围，不要用于操作确认。
- **不学什么**：几乎零文字（我们是文字游戏，反过来）。

## B05 · Genshin Impact 原神（手机/PC/PS｜开放世界 RPG｜2020）

**一句话**：**"菜单即世界"**——每个功能页面都有一张"风景底图"，让切菜单像切地点。

- **屏幕清单**：原地（常驻 HUD）、背包、角色、任务、地图、派蒙菜单、祈愿、纪行、图鉴、设置、对话（底部）。
- **L1 信息架构**：**Esc 打开的是"派蒙菜单"（一个环）**，再进二级；手机端底部 5 个（背包/角色/任务/地图/派蒙）。
- **L2 布局**：多数页面为"左列表 + 右详情"；角色页是"左立绘 + 右属性"；手机端全部改为单栏 + 顶部标签。
- **L3 颜色**：**象牙白 + 金 + 深蓝**；品质用 5 种颜色（稀有度），**颜色只在稀有度上高饱和**。
- **L4 字体**：中文用思源黑体/苹方，标题用汉仪/字魂类圆润衬线；字号档多但层级清晰。
- **L5 透明度与融合**：每个菜单**背后是一张低饱和风景图**（不是纯色），面板为米白纸卡 + 金色细边；**页面顶部有一条渐隐到风景的过渡带**。
- **L6 动效**：页面切换用"从右侧推入 + 轻微视差"；元素出现有 0.15–0.25s 的缩放淡入；手机端为大按钮 + 大动效。
- **L7**：手机按钮大；文字有"缩放"但只影响对话气泡；有屏幕阅读器支持（部分）。
- **可迁移做法**
  1. **菜单底图**：每个功能页配一张低饱和的场景图（→ 我们的村史/人物页可以用"当前地点"的暗化插画作底）。
  2. **顶部渐隐过渡带**（→ 面板与场景衔接，正是 L5"融合"的核心手法）。
  3. **稀有度色独立于主题色**（→ 我们的物品品质可以用"墨色浓淡"而非新色相，避免破坏 2 色系）。
- **不学什么**：金色细边满屏（我们明确禁止）。

> 参考：[Comparative Analysis of UI Design in Genshin Impact](https://citeus.um.ac.id/cgi/viewcontent.cgi?article=1233&context=jolla)（该 PDF 直接抓取失败，结论取自其摘要：清晰简洁、语言简明、一致性、视觉层级、视觉美感五原则）

## B06 · Honkai: Star Rail 崩坏：星穹铁道（手机/PC/PS｜回合 RPG｜2023）

**一句话**：**"信息卡片"式的战斗与养成界面**，把大量数据塞进漂亮卡片而不显乱。

- **屏幕清单**：地图、战斗（回合）、角色、光锥、遗器、任务、短信（手机）、列车（主菜单）。
- **L1 信息架构**：**游戏内"手机"是重要入口**（短信、任务、地图、背包），把系统"日常化"。
- **L2 布局**：卡片式网格，每卡 1:1.6；详情页"左图右文"。
- **L3 颜色**：**深蓝紫 + 白 + 金色**（我们不可用紫蓝，但其"深底 + 单强调"的结构可借）。
- **L4 字体**：几何无衬线 + 装饰斜体；数字很大（战斗数字）。
- **L5 透明度与融合**：卡片为**半透明深蓝玻璃 + 发光边**；背景是渐变网格（科技感）。
- **L6 动效**：卡片进入是"翻转 + 展开"；切换用 wipe（擦除）转场。
- **L7**：手机优化好；有 UI 缩放；文字偏小。
- **可迁移做法**
  1. **"游戏内手机"作为入口**（→ 我们的"人生"页可做成"一本簿子"，把日志/家庭/作品收进去，符合"当时的说法"）。
  2. **卡片 1:1.6 的统一比例**（→ 物品/人物卡片统一比例）。
  3. **wipe 转场**（→ 季节/章节切换，可以做成"纸被揭开"）。
- **不学什么**：紫蓝渐变、发光边（我们明令禁止）。

> 参考：[Analysis of Interface Design in Honkai Star Rail](https://ojs.unimal.ac.id/game/article/view/19957)

## B07 · 皇帝成长计划 2（手机/H5｜古代帝王养成｜2014/重制）

**一句话**：**中文文字模拟的"手机化"样本**——如何在竖屏里塞下奏折、后宫、朝堂。

- **屏幕清单**：朝堂（常驻）、奏折（事件）、后宫、官员、国库、军事、科举、子嗣、事件弹窗、结局。
- **L1 信息架构**：竖屏首页是"宫殿剖面"（一栋楼的各殿入口），点进去是列表 + 详情。
- **L2 布局**：竖屏，**顶部状态栏（年号/国库/民心）+ 中间列表 + 底部主菜单**；大量使用"卡片列表"。
- **L3 颜色**：**中国红 + 金 + 米黄**，红金用得多（与我们"朱砂克制"相反）。
- **L4 字体**：楷体/宋体标题 + 黑体正文；**中文竖排偶尔出现**。
- **L5 透明度与融合**：面板不透明；背景为宫殿插画 + 半透明深红蒙版。
- **L6 动效**：翻页（奏折展开）动画；弹窗淡入。
- **L7**：字体偏小、对比不足是常见批评；老年玩家多，字号需求高。
- **可迁移做法**
  1. **"宫殿剖面"作为主界面**（→ 河岸台地的院落剖面，手机竖屏极合适）。
  2. **奏折式事件卡**（→ 我们的"事件/请求"卡：一折纸，展开看详情）。
  3. 反面教材：红金过饱和、字号小——**正是我们要避免的"游戏化古风"**。
- **不学什么**：红金堆砌；密集列表。

## B08 · 江南百景图（手机｜古代城市建设｜2020）

**一句话**：**工笔长卷 + 卷轴式横滑**——把"中国画"直接做成 UI 的滚动方式。

- **屏幕清单**：应天府（常驻）、居民、建筑、任务、仓库、地图（卷轴）、商店。
- **L1 信息架构**：底部 5 个（府邸/居民/营造/任务/仓库）；地图是**横滑长卷**。
- **L2 布局**：横滑长卷（宽度数倍于屏），**UI 元素附着在卷轴边缘**。
- **L3 颜色**：**绢本米黄 + 墨 + 少量石青石绿**；颜色极少但层次分明。
- **L4 字体**：楷体/手写标题 + 宋体正文；竖排用于标题。
- **L5 透明度与融合**：**面板是"绢/宣纸"半透明（0.93）**，边缘有卷轴轴头；打开面板时卷轴**不消失，只被压暗**。
- **L6 动效**：卷轴横向滑动带惯性；人物行走（我们不用）；**建筑出现时有一笔水墨晕开**。
- **L7**：字号偏小；竖屏操作密集（批评点）。
- **可迁移做法**
  1. **长卷横滑**（→ 电脑/横屏的"村史"或"河岸"可以做成长卷；手机改为竖滑）。
  2. **绢本半透明 + 轴头**（→ 我们 `--glass .92` + 纸纹，可加"轴头"装饰于页标题）。
  3. **水墨晕开的出现动效**（→ 新建筑/新作品出现，1 次 400ms，不循环）。
- **不学什么**：密集放置操作；字号。

## B09 · Rusty's Retirement 铁锈退休生活（PC 浮窗/Steam Deck｜放置农场｜2024）

**一句话**：**界面就是窗口**——游戏只占屏幕底部一条，随时可缩到最小。

- **屏幕清单**：底部横条（主）、侧边竖条（可切换）、展开面板、设置。
- **L1 信息架构**：**没有真正的"页面"**；所有交互在一条带里完成。
- **L2 布局**：高度约 200–300px 的横条；横向滚动的小农场；点击角色 → 弹出小卡片。
- **L3 颜色**：**柔和像素色 + 低饱和**；背景透明（透出桌面）。
- **L4 字体**：像素字体；字号小但只在卡片里。
- **L5 透明度与融合**：**窗口背景可以是完全透明的**（只显示游戏物），可选择"叠加模式"让像素与桌面共存。
- **L6 动效**：角色来回走（我们不用）；卡片弹出 150ms。
- **L7**：可调到极小但保持可点；有"减少动画"选项。
- **可迁移做法**
  1. **"条"式界面**：手机上可以做成"底部一条常驻的生活带"（时间/饥饿/一句近况），点击展开——**与我们的底部动作条同构**。
  2. **背景透明叠加**（→ 我们的场景层可以做"画中画"式透明，让桌面/系统壁纸透出，用于 PWA 桌面版）。
  3. **减少动画选项**（已有）。
- **不学什么**：像素风；没有叙事（我们是叙事为主）。

## B 组小结

| 维度 | B 组共同规律 | 对 OpenLife 的结论 |
| --- | --- | --- |
