> 前一轮见 [50 本轮UI改造记录](50-本轮UI改造记录.md)。这一轮修的是**功能层**问题，不是观感问题。

## 问题一：同一功能在多个位置出现

### 查出来的重复

用 `.tmp/audit-duplicates.mjs` 把 `index.html` 与全部前端 JS 里的 `data-route` / `data-control` / 事件绑定扫了一遍，重复集中在四个地方：

| 功能 | 修前出现在 | 修后 |
| --- | --- | --- |
| **模块管理** | 首页菜单、左侧「更多资料」、☰ 菜单 | 只剩 ☰ 菜单 |
| **家族谱** | 首页菜单、左侧导航、☰ 菜单 | 左侧导航 + ☰ 菜单（两种版式各一份，合理） |
| **人生概述** | 独立路由 `life`、`character` 页里的「人生手账」 | 并入「人生」页开头，`life` 路由删除 |
| **此刻/行囊/熟人/人生** | 底部导航、`life` 页的「目的地卡片」、`character` 页的「人生手账」 | 只剩底部导航 |

### 具体删了什么

- 首页 `home-menu` 里的「模块管理」「家族谱」两条——首页现在只有「继续 / 新开 / 存档」三件事。
- 「人生概述」页整块 `destination-grid`（四张卡片复刻了底部导航）。
- 「人生」页里那块 `personal-links`（「人生手账」，再做一遍家族谱/记忆/世界的入口）。
- `TITLES` 里的 `life` 路由。它没有入口却会建出一个空页面。

### 顺带修掉的一处"反向重复"

`sceneTimeButton` 被绑了两次：

- `shell.js`：`onclick = () => autoButton.click()` —— 钉死成"打开日程编辑"；
- `app.js` 的 `updateContinuousControls()`：按"正在推进/已暂停"在「暂停推进」与「时间安排」之间切换。

因为 `shell.js` 在 `app.js` 之后执行，**赢的总是它**——于是按钮永远显示「时间安排」，时间推进中也不能在这里暂停。删掉 `shell.js` 那行，交回 `app.js` 一处管理。

> 结论：**同一件事只允许一处绑定。** 判断标准不是"有没有重复代码"，而是"用户能不能在两个地方做同一件事"。

## 问题二：版式切换点了没反应

### 根因（三层，缺一不可）

1. 菜单里写的是 `<button data-control="layoutButton">`，靠一个全局转发器 `$("layoutButton")?.click()` 转过去；
2. **但页面里从来没有 `id="layoutButton"` 的节点**——转发到一个空对象，监听器也挂在 `null` 上；
3. 就算前两步都对，`html.is-phone` 也要等**刷新**才重算，点完屏幕没变化。

### 改法

- 按钮自己带 `id="layoutButton"`，监听器直接挂它；
- 点一下立刻 `setLayoutMode()` + `applyLayoutMode()`，**不刷新就换版式**；
- 补发一次 `resize`，让依赖尺寸的模块重算；
- 按钮文字显示当前值（跟随窗口 / 手机 / 电脑），`title` 说明点一下会变成什么。

### 验证

```
before: { mode: "auto",  isPhone: false, navPos: "sticky" }
after:  { mode: "phone", isPhone: true,  navPos: "fixed",  label: "手机" }
```

在 1280 宽的窗口里点一下，左侧导航立刻从"吸顶侧栏"变成"底部固定栏"——就是用户想要的"网页里用手机模式"。

## 问题三：插件开关用不了

### 根因（两个，第二个更严重）

1. `markModuleOff()` 与 `loadModules()` 都没 `await`，UI 在写入落盘前就重新读了目录，看起来"点了没反应"；
2. **关掉之后就开不回来**：分组写的是 `on = 已加载 / offList = 未加载`。一个模块被关掉后不再 `loaded`，于是掉进"未接入"那一堆——而那一堆的卡片**根本不渲染开关**。`switchBtn` 里那个"开"的分支是死代码，永远走不到。

### 改法

- 分组依据改成 `markedOff`，新增独立的「**下次启动时关掉**」分组，里面每个模块都有「开」按钮；
- 两处操作都 `await`，并在等待期间禁用按钮；
- `.module-switch` 之前**没有任何样式**（是个裸按钮），补成明确的两态（开=绿边浅底，关=中性边）；
- 关闭的卡片左侧加一道朱砂，与"已加载"区分。

### 验证

```
OPENED:    核心·10 / 已加载·24 / 关按钮 24 个
点「关」后：核心·10 / 已加载·23 / 下次启动时关掉·1 / 该模块出现「开」按钮
点「开」后：markedOff 从 true 变回 false
```

## 问题四（验证时发现的）：画面模式打开是空的

切到「画面」后只有一个色块——因为 `settlement.js` 引用的 **9 张场景图 `/art/scene-*.webp` 全都不存在**（`git log --diff-filter=D` 也查不到删除记录，从未提交过）。

### 改法

新增 `apps/web/public/scene-placeholder.js`：

- 按 DESIGN.md 的分层要求（远景天空/远山、中景房屋/河、近景窑/柴堆/陶罐）用 SVG 画**占位插画**；
- 9 个地点各一套构图（院子、灶台、芦苇滩、田、河、渡口、窑、陶土坑）；
- 四个时辰一套配色、四季一套地面色偏——只改颜色不改构图，方便日后做交叉淡入；
- 用**固定种子的伪随机**，同一地点每次画得一样，不会一刷新就变样；
- `resolveSceneArt()` 先探测真图，能加载就用真图，加载不到才用占位——**真插画到位后不用改代码**。

## 顺手做的两件事

### `theme.css` 拆分

`source-size-budget.test.ts` 有 1200 行的硬预算，我的改动把它推到 1226 行。没有抬高上限，而是把「与页面结构无关」的部分切出去：

- `theme.css` 1047 行：令牌 + 页面骨架 + 各页布局
- `panels.css` 177 行：声音面板、质感与动效、纯文字模式、人生纪事、心事、图标细节

### `package.json` 的 BOM

上一轮用 PowerShell `Set-Content` 写 `package.json`，带进了 UTF-8 BOM，导致 `typecheck-ratchet.test.ts` 里 `JSON.parse` 报 `Unexpected token '﻿'`。已去掉 BOM。**教训：改 JSON 一律用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`。**
