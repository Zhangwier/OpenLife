# 11 · 视觉特效与风格统一专题

> 这一篇补 [10 规范](10-横向提炼与UI设计要素规范.md) 里"动效表"之外的部分：**特效怎么分类、预算多少、怎么不互相打架**。
> 所有参数都是"可执行区间"，不是"唯一正确值"。

---

## 1. 特效五类（先分类，再谈参数）

| 类 | 作用 | 例子 | 时长 | 频率 | 我们能不能用 |
| --- | --- | --- | --- | --- | --- |
| **S1 氛围** | 让静画"活着" | 炊烟、火光、水波、落叶、飞鸟、萤火（A Short Hike / Cozy Grove） | 周期 6–60s | 常驻循环 | ✅ 核心 |
| **S2 反馈** | 确认一次操作 | 按钮回弹、木牌抬起、资源+1 浮字（RimWorld / 动森） | 80–300ms | 每次操作 1 次 | ✅ 核心 |
| **S3 转场** | 说明"我到了哪" | 交叉淡入、zoom、翻页、擦除（明日方舟 / 星铁 / Wildermyth） | 220–600ms | 每次切换 1 次 | ✅ 核心 |
| **S4 状态** | 长期提示"有事" | 警报脉动、心情条缓慢移动（RimWorld）、图标情绪化（Reigns） | 1–2s 或 ∞ | 有条件 | ⚠️ 克制 |
| **S5 仪式** | 一次性的高光 | 印章、当选、传承、结局 | 300–1200ms | 一生几次 | ✅ 极少 |

**规则**：**同一时刻，S1 可以有多个（不同周期），S4 最多 1 个，S2/S3/S5 互斥。**

---

## 2. 氛围特效（S1）：分层与周期

A Short Hike 的做法可以量化成一张表——**层与层的周期必须互质**，否则会"一起呼吸"被看出来。

| 层 | 元素 | 周期 | 透明度变化 | 备注 |
| --- | --- | --- | --- | --- |
| 远景 | 云 | 60s | .10 → .18 | 线性、不来回 |
| 远景 | 飞鸟 | 18–26s | 0 → .9 → 0 | 单向飞过 |
| 中景 | 炊烟 | 8.5s | 0 → .35 → 0 | 向上飘散 + 模糊 |
| 中景 | 水波 | 7s | .12 → .22 | 横向位移 |
| 近景 | 火光 | 2.3s | .55 → .75 | 只抖动亮度，不位移 |
| 近景 | 落叶/雪 | 11–14s | 0 → .8 → 0 | 带旋转，风向可调 |
| 夜 | 萤火 | 6–9s | 0 → .7 → 0 | 带 `drop-shadow` 光晕 |
| 夜 | 星 | 3.5s | .5 → .9 | 只改透明度 |

**约束（写进 CI 或 review checklist）**
- 任何氛围层的 **透明度变化幅度 ≤0.3**（防止闪烁）
- **不允许 `animation-direction: alternate` 用于位移**（会看出"来回"），位移用 linear + 循环
- 屏幕上的氛围元素总数 **≤12 个**（低端手机 ≤8）
- `prefers-reduced-motion` 下 **全部停止**，但保留静态光影（用 `opacity` 定格）

> 现有 `scene-fx.js` 已经做了大部分；缺的是**周期互质检查**和**元素数量上限**。

## 3. 反馈特效（S2）：一次操作只给一次确认

| 动作 | 表现 | 时长 | 缓动 |
| --- | --- | --- | --- |
| 按下按钮 | `translateY(1px)` + 内阴影 | 80ms | ease-out |
| 选中木牌 | 抬起 2px + 阴影升一档 | 120ms | `--ease-soft` |
| 提交成功 | 目标物轻微"弹"一下（1 → 1.02 → 1） | 220ms | 回弹 |
| 失败 | 文本框轻微左右 2px（1 次）+ 原因出现 | 180ms | ease-out |
| 获得物品 | 图标从中心浮出 + 上移 12px 淡出 | 900ms | ease-out |

**反例**：RimWorld 的资源列表变化会闪烁；明日方舟的粒子**不响应操作**（被自家分析文章点名为"像看电影"）。**反馈必须由玩家的动作触发**，否则只是装饰。

---

## 4. 转场特效（S3）：语义化，不是炫技

吸收了明日方舟的"转场语义"和星铁的 wipe：

| 语义 | 表现 | 时长 | 用在哪 |
| --- | --- | --- | --- |
| **同层级切换**（地点→地点） | 交叉淡入 + 1.02→1 缩放 | 600ms | 场景移动 |
| **进入子层**（→详情） | 从右侧推入 24px + 淡入 | 240ms | 抽屉、面板 |
| **返回父层** | 反向推入 + 淡出 | 200ms | 关闭 |
| **系统隔离**（→设置/村史） | 深色淡出（先黑一下再进） | 320ms | 大页面 |
| **有逻辑关联**（升级/合成） | zoom 1.04→1 + 淡入 | 240ms | 制作、成长 |
| **章节/季节** | 纸被揭开（wipe，从左到右） | 700ms | 换季、换年 |
| **重大事件** | 整屏降饱和 .2 + 薄雾层 | 1200ms | 灾、死亡、当选 |

**禁止**：同一屏内两种转场混用；转场期间可交互（必须 `pointer-events: none`）。

---

## 5. 状态特效（S4）：最多一个

| 状态 | 表现 | 约束 |
| --- | --- | --- |
| 有急事 | 一个图标 1.8s 呼吸（缩放 1→1.06） | 全屏只允许 1 个 |
| 人物生气 | 头像牌边缘 300ms 明暗一次，不循环 | 只一次 |
| 危险 | 朱砂竖条 + 文字，不闪 | 不用闪烁 |
| 加载 | 一条 1.2s 的"墨线"横向生长 | 不用 spinner |

**Reigns 的启示**：顾问生气时只是"悄悄闪一下"。**状态提示的最高级形态是"你不看也能感觉到"，而不是"你必须看"。**

---

## 6. 仪式特效（S5）：只给三个时刻

See [10 §6.5](10-横向提炼与UI设计要素规范.md) 的印章规范。补充：

- **当选**：印章 + 场景轻微定格 0.2s + 一次低频震动（可选）
- **立规矩**：印章 + 木牌落下（240ms）
- **重大传承**：印章 + 老照片去饱和 → 彩色（1.2s）
- 用完之后 **30 秒内不再触发任何 S5**（防止连续轰炸）

## 7. 风格统一：六个抓手

一个界面"像不像一家人"，取决于这六件事是否各自只有一个答案。

### 7.1 材质（Material）
我们只有四种：**纸、墨、木、陶**。每种只允许一种表现：

| 材质 | 用在哪 | 禁止 |
| --- | --- | --- |
| 纸 | 叙事底、卡片、村史 | 不做撕裂边（除非是"撕下来的便笺"这一种特例） |
| 墨 | 文字、线、印章边 | 不用纯黑，不用外发光 |
| 木 | 选项木牌、按钮边 | 不做木纹贴图，只用颜色 + 1px 暗边 |
| 陶 | 物品图标、容器 | 不做高光反射 |

### 7.2 线宽（Stroke）
- 图标：**24 网格、1.8 线宽、圆头**（以 `icons.js` 实际实现为准）
- 分隔线：1px
- 卡片边：1px
- 强调边（危险）：3px
- **不允许出现 0.5px / 2px 的线**（除大标题装饰）

### 7.3 光源（Light）
- 全局光：**左上 → 右下**（与场景插画一致）
- 高光只在左上，阴影只在右下
- 界面元素不发光（禁用 `box-shadow` 带颜色的大扩散）
- 夜间模式的"光"来自火光/月亮，颜色偏暖

### 7.4 形状语言（Shape）
- 卡片：**矩形 + 8–20px 圆角**，不做斜切
- 按钮：pill 或 12px 圆角
- 头像：3:4 矩形（不是圆形）
- 印章：**方形**（不是圆形）
- **全站只有一个圆形**：状态点（6px）

### 7.5 字体（Type）
见 [10 §2.1](10-横向提炼与UI设计要素规范.md) 的五角色。**同一角色永远同一字体**，不允许"这个页面用楷体那个页面用宋体"。

### 7.6 色彩预算（Color）
见 [10 §1.1](10-横向提炼与UI设计要素规范.md)。补一条**跨屏预算**：

> **一个流程（如"登门送礼"）跨 3 个屏，赭石总共出现 ≤4 次。**

## 8. 背景处理：三种背景，三套规则

我们其实有三种背景，规则必须分开写，否则一定打架。

### 8.1 纸底（Paper）——列表、村史、设置
- 底：`--bg`
- 卡片：`--surface` + 1px `--line`
- 纹理：全局纸纹（2–3% 不透明度，`multiply`）
- **不需要渐隐**（本来就是平的）

### 8.2 场景（Scene）——此刻、对话、事件
- 底：插画（远/中/近三层）
- UI：**必须渐隐接地**（见 §9）
- 压暗：常亮 `brightness(.94)`，夜间 `brightness(.82)`
- 暗角：`radial-gradient` 压边，中心保留

### 8.3 深色（Night）——夜晚、模态背后
- 底：`--bg #121a17`
- 卡片：`--surface #1a2420`
- **场景仍可见**（不替换成纯色）

**规则**：**一个页面只能是一种背景**。不允许"纸底页面上叠一个场景缩略图"这种混合（除非是卡片里的插图，且加 1px 边）。

## 9. 透明度与融合：量化表

### 9.1 面板透明度（按背景亮度选）

| 背景 | 面板不透明度 | 理由 |
| --- | --- | --- |
| 纸底（浅） | .98 | 几乎不透明，避免"脏" |
| 场景·白天（中亮） | .92 | 能透出 8%，有"纸在画上"的感觉 |
| 场景·夜晚（暗） | .90 | 暗底更宽容 |
| 场景·高对比（日落/火光） | .96 | 必须压住，否则文字读不清 |

**自动规则**：可以用 `@supports` + CSS 变量在切换时辰时改 `--glass` 的值（我们已有 `data-theme`，再加一个 `data-time`）。

### 9.2 融合六法的适用边界

| 手法 | 适用 | 不适用 | 参数 |
| --- | --- | --- | --- |
| 边缘渐隐接地 | 抽屉、面板朝场景的一侧 | 纸底页面 | 24px，`--bg-fade-0 → --glass` |
| 侧边软渐变 | 叙事区左右 | 卡片内部 | 40px |
| 压暗不替换 | 打开抽屉/模态 | 换季/换地点 | `.72`–`.78` |
| 纸纹叠加 | 全局 | 图标内部 | 2–3%，`multiply` |
| 暗角 | 场景舞台 | 列表页 | 中心 60% 保留 |
| 毛玻璃 | 面板背后仍有场景且需保留层次 | 低端机、文字密集区 | `blur(10px)`，配 `.92` 底 |

### 9.3 融合的"三不要"

1. **不要在同一屏用两种融合**（既渐隐又毛玻璃 = 脏）
2. **不要给渐隐层加边框**（边框会把"融合"变回"盒子"）
3. **不要在文字正后方做高斯模糊**（中文字笔画会被吃掉，尤其小字号）

## 10. 特效预算（防止"看起来像 2010 年页游"）

| 项 | 上限 |
| --- | --- |
| 同屏氛围元素 | 12（手机 8） |
| 同屏循环动画 | 6 |
| 同屏状态动画 | 1 |
| 一次操作触发的动画 | 2（反馈 + 数值变化） |
| 单次转场涉及元素 | 3 |
| 屏幕变化面积 | ≤40%（超过就是"换页"，应走 S3） |
| 一屏内不同缓动曲线 | 1（全站统一 `--ease-soft`） |
| 一屏内不同时长档 | ≤3 |

## 11. 走查：把两张图并排看

评审时不要只看新图，**必须旧图 / 新图并排**，回答四个问题：

1. **哪一处最先吸引眼睛？**（应该是叙事或标题，不是装饰）
2. **闭眼三秒再睁开，还记得几个元素？**（应 ≤5）
3. **把图转成灰度，层级还在吗？**（如果不在，说明只靠颜色分层）
4. **这一屏里有几个"圆角矩形"？**（>6 个说明该合并信息块）
