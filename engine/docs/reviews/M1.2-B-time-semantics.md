日期：2026-10-08
范围：仅时间语义与由此暴露的单位失配，不新增玩法。
基线：M1.2-A 快照 `D:\MG\backups\OpenLife\m1.2-a-2026-10-08T1930`（HEAD `797cf3e`）
结果：`352/352` 测试通过；时代漂移 **29 年/年 → 0**。

---

## 1. 修的是什么

M1.1 审查发现：同一个 `Kernel.tick` 被两套刻度同时读取，且玩家可见。

```text
world-clock      按日刻度读：360 tick = 1 年   → 正确
life-contracts   按月刻度读： 12 tick = 1 年   → 差 30 倍
apps/web         按月刻度读：tick % 12 + 1 当月 → 年龄与时代都算错
```

修复前实测（日刻度世界推进 360 天）：

| 读数 | 值 | 应该 |
| --- | --- | --- |
| `clock.yearsElapsed` | 1 | 1 ✅ |
| `yearOfTick` 推出的年 | 30 | 1 ❌ |
| `ageInYears(0, 360)` | 30 岁 | 1 岁 ❌ |
| 时代 | 公元前 2040 年 | 公元前 2069 年 ❌ |

漂移随年数线性增长：1 年 → 29 年，5 年 → 145 年，100 年 → 2900 年。

**这不是 M1 引入的 bug**，而是 M1 之前「12 tick = 1 年」的约定在日刻度下不再成立，而 M1 只改了玩家可见那一层。

## 2. 定案的修法

严格按你的裁决执行：**不改 Kernel 语义、不把世界退回月刻度**。

| 你的要求 | 实现 |
| --- | --- |
| Kernel 的 Tick 是中性推进单位 | `packages/kernel` 未改 tick 语义。仅修一处：`TaskOutcome.command` 分支原先直接 `return`，会吞掉同一次返回里的 `rescheduleAt`（见 §4） |
| `ClockProfile` 决定 Tick 对应的模拟时间 | `WorldClockProfile`：`moment`(1) / `day`(1) / `month`(30) / `year`(360) |
| 当前生活场景采用每日推进 | `LIFE_TIME_SCALE = "day"`；存在 `world-clock.clock` 组件即声明日刻度 |
| 年龄、季节、年度事件统一从世界时钟取得 | 新增 `reading()`、`readingAtTick()`、`monthsOfTick()`、`eraYearAt()`、`ageAt()`、`declaredScale()`；`life-contracts` 新增 `TimeScale`、`TICKS_PER_UNIT`、`ticksPerYearOfScale()`、`unitsElapsed()`、`ageInYearsAt()`、`yearsToTicksAt()`、`monthsToTicksAt()` |
| 历史存档保留原时间语义，不静默转换 | 无时钟组件的世界即 `legacyScale`，继续按 12 tick/年读取；加载旧档**不注入时钟** |

### 2.1 月刻度常量保留但改名语义

`TICKS_PER_YEAR = 12` 保留（旧档与旧模块仍需要），但语义明确为「月聚合刻度」。新的代码路径一律不再使用它，改为读世界刻度。旧的 `yearOfTick` / `ageInYears` 仍是月刻度专用，且不再被日刻度路径调用。

## 4. 关键发现：年度任务不能信任初始化时的间隔

`modern.initialize_world` 的 resolve 在 `world-clock` 创建组件**之前**运行，因此它拿不到世界刻度，只能读到旧值 12。若把 `everyTicks` 在此冻结，日刻度世界每年会跑 **30 次**老化。

修复前实测：4 年推进产生 **120** 次年事件（应 4 次）；角色 3 年就到 84 岁死亡。

### 修法

1. 初始只定**第一次**到期时间（`afterTicks: TICKS_PER_YEAR`，随后会被实时世界纠正）。
2. `modern.annual_tick` 的 handler 每次从**实时世界**重算并 `rescheduleAt: c.at + ticksPerYear(c.world)`。

这要求 Kernel 允许「既派发命令又改期」。原先实现：

```ts
if (outcome.command) {
  this.dispatch({...});
  return;                      // ← rescheduleAt 被吞掉，任务只触发一次
}
if (outcome.rescheduleAt !== undefined) { ... }
```

已改为在 `command` 分支内一并处理 `rescheduleAt`。这是 `packages/kernel` 的**唯一改动**，属契约已声明能力的实现补齐（`TaskOutcome` 本就同时声明了 `command` 与 `rescheduleAt`），不改变 tick 语义。

修复后实测：

```text
day scale:  1 年 → age 1, events 1;  4 年 → age 4, events 4
legacy:     tick 264 → age 22（12 tick/年，语义不变）
```
