# 河岸的第一个季节

> 后续阶段、具体任务与试玩放行条件见 [长期游戏设计与完善计划（2026-10-22）](long-term-game-design-2026-10-22.md)。本文继续作为产品定义与代表经历依据，下面的状态日期和“两周”目标保留为原记录。

> 当前产品定义与代表经历。状态截至 `2b7f9c8`。
> 用途：所有新系统接入前，先问「它让玩家多了什么**理解**、**选择**或**牵挂**」。
> 只要答不出这三样中的一样，就不进这一轮。

## 一、玩家是谁

**一个生活在河岸聚落里的人，通过手艺、关系和选择改变身边的世界；人生结束后，从下一代继续。**

三层必须有主次：

| 层级 | 玩家在里面做什么 | 不在这一层做什么 |
| --- | --- | --- |
| **个人生活** | 直接行动：干活、说话、送东西、答应事情 | —— |
| **家庭与村落** | 承受与施加影响：谁记着你、谁失望、屋顶修没修 | 不直接下命令管理全村（除非当上头人） |
| **文明与时代** | 隔着看结果：时代变了、某项手艺传开了 | 不操作文明层 |

**权限与社会身份一致**：普通村民不能天然拥有村长的管理权。当上头人才有职责；
远行回来才带回见闻。

## 二、近期目标（两周）

> **做出一段具有统一 UI、几位可记住的人、几次有代价的选择，并能看到后续变化的
> 「河岸第一个季节」。**

它要成为以后所有新系统接入的共同标准：**玩家能从中感受到什么**，而不是仓库里
又增加了什么。

## 三、代表经历（验收这条故事的完成度）

> **秋雨将至，自家的屋顶需要修补，阿灶又来借柴。你原本答应跟陶叔烧窑，而去邻村
> 换材料会耽误几天。**

四种合理路线，**没有一条是明显最优**：

| 路线 | 你付出什么 | 谁受影响 |
| --- | --- | --- |
| 留下修屋，拒绝借柴 | 阿灶失望；陶叔那边失约 | 自己的屋顶好了 |
| 借出柴草，找熟人一起修屋 | 欠一个人情；柴少了 | 阿灶记你的情；帮忙的人也在等回报 |
| 履行烧窑约定，用作品换材料 | 屋顶再漏几天；作品可能成也可能废 | 陶叔满意；家里人受罪 |
| 外出换材料，把家事托付给别人 | 离开几天；托付的人要担责任 | 回来时家里可能已经变了 |

### 后续必须来自这些选择，而不是随机

- 谁受了帮助、谁失望、谁承担了工作
- 物品去了哪里（柴、罐子、换回来的材料）
- 回来时家里有什么变化
- **几天后、换季后，谁还记得**

### 内容生产的验收问题

每写一个事件，先答这六个问题：

1. 什么日常状态让它发生？
2. 为什么这件事与玩家有关？
3. 至少两个选择是否都说得通？
4. 当下会付出什么？
5. 几天后、换季后，谁还记得？
6. **玩家不介入时，其他人会怎么处理？**

两条硬要求：

- **不要让所有困难都等待玩家解决。**
- **不要让善意选择总是获得最大收益。**

## 四、四个主页面

手机上一屏完成一个决定。阅读顺序固定：**处境 → 请求或机会 → 选择 → 成本 →
后果 → 下一步。**

| 页面 | 玩家来这里解决什么问题 | 主要内容 |
| --- | --- | --- |
| **此刻** | 我现在身处什么情况，可以做什么？ | 地点、时间、眼前的人与事、当前决定 |
| **行囊** | 我有什么，能拿它做什么？ | 携带物、归属、借用、用途、交换 |
| **熟人** | 我认识谁，最近与他发生了什么？ | 人物识别、共同经历、约定、可观察态度 |
| **人生** | 我成为了怎样的人，留下了什么？ | 手艺、家庭、愿望、作品、生涯与传承 |

### 「故事」不作为第五个一级入口

它有内容，但不该让玩家到单独页面去领取本应发生在眼前的事。
故事是**这四个页面里的内容组织方式**：此刻里发生的事、熟人里共同的经历、
人生里回顾的往事。

### 「此刻」的结构

```
秋 · 午后                     菜单
公用灶台                 还能忙一阵

[场景插画：灶火、雨云、眼前人物]

阿灶把柴堆拢了拢。
“今晚可能下雨，能借我一捆柴吗？”

[借给他]
交出 1 捆柴 · 一小会儿
你自己的烧窑准备会少一份材料

[问问其他人有没有]
需要找人商量 · 可能耽误一些时间

[说明自己也缺柴]

眼前的人与物                       展开
今天其他发生的事                   展开

此刻       行囊       熟人       人生
```

**普通状态不挤占顶部。** 饥饿、疲劳、负重在影响当前决策时才提高优先级，
其他时间保持安静。

## 五、交互原则

- 人物、物品、行动使用**统一的详情面板**，底部放主要操作。
- 长篇对话与重要决定进入**专注阅读状态**，暂停其他信息滚动。
- 返回时恢复原位置，保留刚才选中的对象。
- 词条以**点击**为主要入口，长按作补充（手机上长按发现不了）。
- 连续行动可中止；**结婚、重大失约、严重危险**等节点停下来让玩家决定。
- 首次接触系统时才解释规则，不在开局展示所有模块。

## 六、三条主线

### 人物：先做深 6–8 位

每位核心人物至少需要：

- 一项日常需要
- 一件正在烦恼的事
- 一段与其他人的关系
- 一个与玩家可能发生分歧的理由
- 一种随时间变化的处境

关系不是单一好感度：可以信任你的手艺却不愿讲家事，也可以有矛盾但仍愿履约。

### 时间：三种尺度

| 尺度 | 玩家做什么 |
| --- | --- |
| **关键一天** | 亲自处理选择、交谈、探索、重要生产 |
| **平常一段时间** | 安排已熟悉的生活，系统处理重复劳动 |
| **换季或人生节点** | 阅读变化、调整目标、作重要决定 |

自动安排省去重复操作，**但保留需要玩家参与的节点**。否则跨代只是一个
需要大量点击才能抵达的远景。

### 传承：下一代接到具体的东西

- 一间终于修好的屋子
- 一门有人教过、也可能失传的手艺
- 一位记得父辈恩情的邻居
- 一笔尚未偿清的债
- 一件具有来历的器物

基因、时代、文明系统提供**背景**，但玩家最容易产生感情的是这些**具体事物**。

## 七、这一轮不做什么

| 暂缓 | 原因 |
| --- | --- |
| 继续扩充时代数量 | 已有一整套，缺的是玩家能感受到的推进 |
| 宏面制度数量 | 同上 |
| Mod 工具链功能 | 内容作者先用现有工具写出一批真正有后果的故事，再按遇到的困难扩 |
| 给所有已存在系统安排一级入口 | 入口按「玩家来解决什么问题」分，不按「我们写了几个模块」分 |

远行、文明、职位等代码**保留**。近期投入以「它们如何服务前四个阶段」为准。

## 八、判据

每项工作交付前，Leader 层只问三句：

1. **这项让玩家多了什么理解？**
2. **多了什么选择？**
3. **多了什么牵挂？**

三样都答不出，就不该进这一轮。
