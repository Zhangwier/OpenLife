# 地图生活改造实施与交付记录

日期：2026-10-25。基线：`integrate/history-lab@2b63728`。用户指令：“你来完成”。本轮负责人：Codex，顺序开发并集成。设计依据：[策划书](../design/map-life-design-2026-10-25.md)。

目标：正式入口默认进入可操作俯视地图，既有生产、交往、跨日、远行和传承通过同一生活状态继续运行。地图坐标和现有 Place/Space 对齐，经 world-space 命令保存，画面帧不推进世界。

采用现有 TypeScript、原生 ES modules、Canvas；不增加运行时依赖。地图短距离移动不扣日内额度，跨地点/房间沿用既有规则。旧档没有坐标时在当前语义空间安全落位；已存坐标绑定场景版本、地点与空间。

## 实施任务

- [x] 地图规则：`modules/world-space/src/local-grid.ts` 注册持久化位置、权威移动与拒绝理由；`local-map.ts` 提供确定性布局、BFS 路径、目标锚点。测试墙、水、不可达、过期位置、存读档、同种子重现和不推进日期。
- [x] Web 接口：`apps/web/src/local-map.ts` 从当前玩家投影构建地图，过滤人物/物件；`server.ts` 接入 `map.walk` / `map.interact`，后者到达后重新检查目标、动作和距离；重复/过期请求拒绝。地图移动不暂停已授权的日程安排。
- [x] 正式场景：`public/life-map.js` 与 `life-map.css` 提供地图绘制、路径动画、点击/键盘移动、取消、镜头、地点/室内出入口、附近对象；`settlement.js` 对接现有对象操作面板，默认地图模式，文字入口保留。
- [~] 玩家路径：隔离服务器/存档驱动行走→选人→靠近交谈→真实取物/采集→跨地点→跨日 NPC→保存/读取；检查不可达、离线错误、返回与手机布局。复用已有三生计、事件、地区旅行与传承入口，避免复制模拟系统。
- [~] 收口：完整规则检查、类型、设计令牌、内容目录、两种世界演示和浏览器实际路径；记录实际结果与真机/真人未覆盖边界。更新策划里程碑，不把历史内容与新开发混算。

接口约定：地图投影 `settlement.map` 带版本、sceneId、placeId、spaceId、width/height、tiles、player、targets。`map.walk` 输入整数格目标、sceneId、expectedPosition；返回实际世界状态和权威路径。`map.interact` 输入原动作 action/payload 和 targetKey，服务端从当前投影匹配可执行动作，禁止客户端自造地图目标。所有实际行动仍进入原命令/事务。

## 验证过程

先写移动与集成失败测试并运行，接着实现；小组检查通过后运行整体验证。浏览器使用隔离 Edge profile/端口，用户存档不参与测试。计划执行中记录新增证据与修正。
