# UI 与交互第六轮（2026-10-21）：人生记忆（存档与读档）和主菜单

前五轮都没有碰这两处：「记忆」弹窗是唯一的存档、读档入口，☰「人生与世界」是所有二级功能的总入口。

## 改动文件
- 新增 `apps/web/public/memory-ux.js`、`memory-ux.css`、`menu-ux.js`、`menu-ux.css`
- `app.js` 改了 4 处：
  1. 第 3、4 行引入两个新模块
  2. `writeMemory` 遇到浏览器存储满时抛出中文原因
  3. 存档按钮记下失败原因
  4. 自动记忆失败时记下来，不再只打在控制台里

没有改 `index.html`、`shell.js`、`stories.js`、`player.js`、`codex.js`，也没有改服务端。存档、读档、跳转仍然走原来的按钮。

## 题一：人生记忆弹窗

| 以前 | 现在 |
|---|---|
| 格子只写「公元前 2054 年 · 第一代 · 启 禾 · 16 岁」一行；存档时间（`savedAt`）存了却从不显示 | 分三行：第一行是人物和代数；第二行是年代、月份、当时所在的地点和日子；第三行是「12 分钟前存的」，悬停显示具体时间。地点取自存档那一刻页面上的场景，另外存一份小记录；如果对不上同一次存档就不显示，免得张冠李戴 |
| 「留住此刻」直接盖掉已有记忆 | 先在格子里问一次：「会盖掉这里原来的记忆（启 禾 · 16 岁，3 分钟前存的）」，下面是「先不 / 盖掉并存入」。空格子不问，直接存 |
| 「回到这里」直接替换眼前的人生 | 先说明：「眼前这段人生会换成这里的样子；最近一次自动记忆是 n 分钟前，那之后的经历会丢掉」。确认后才读档 |
| 存好了只闪一下 toast | 存好的那一格左边框亮起，写「✓ 刚刚留下」；弹窗顶部有一条 `aria-live` 状态（已存进记忆一 / 正在回到… / 已清空） |
| 不能删掉旧记忆 | 有内容的手动格子多一个「清空」，同样先确认（「清空后就找不回来了」） |
| 存储满了报英文 DOMException；自动记忆失败也没有提示 | 存储满了时用中文写「没存上：浏览器给这个网站的存储空间满了。清空一个不要的记忆再试」；自动记忆失败时，「最近的记忆」格子里标红说明。底部显示「已用 0.6 MB，约占 11%」和用量条，超过 60% 变橙，超过 85% 变红 |
| 空格子写「这里还是空的」 | 改写成「空着。点『留住此刻』把眼前存进来」，加虚线边框；有内容的格子按钮改叫「存到这里」 |
| 首页「人生存档」固定写「找回之前留下的记忆」 | 改写成「3 份记忆 · 最近一份 12 分钟前」，没有记忆时写「还没有留下记忆」 |
| 手机上按钮挤成竖排单字 | 手机上按钮另起一行占满宽度，高 40px |

## 题二：主菜单（☰ 人生与世界）

| 以前 | 现在 |
|---|---|
| 8 个按钮两列平铺，只有名字 | 分三组：这段人生（保存与读取、时间与日程）；回头看看（家族谱、记忆与历史、时代与世界、模块管理）；离开这段人生（返回主菜单、开启新人生）。每个入口有线条图标和一行说明 |
| 看不出当前状态 | 显示「最近一份 3 分钟前」「日程已启用 / 未启用」「第 1 代」「公元前 2054 年」；当前所在的页面标「在这里」，并设 `aria-current="page"` |
| 「开启新人生」和普通入口长得一样，点了直接进新人生表单 | 改用警示色，说明写「眼前这段人生会结束」。点了先在菜单里确认，给出「先不 / 先留住此刻 / 开始新人生」；「先留住此刻」直接打开记忆弹窗；确认时按 Esc 只收起确认，焦点回到原来的按钮 |
| 打开后只能按 Tab 一个个走 | 打开后焦点落在第一个入口；↑↓←→ 在两列网格里移动（手机上是一列，↑↓ 一次走一格），Home / End 跳到头尾 |
| 手机上两列，说明放不下 | 手机上改成一列，每项高 56px |

## 验证
- 单测 `tests/unit/memory-menu-ux.test.ts`，共 7 项，覆盖：
  - 相对时间、格子文字
  - 存储用量、空间满的判断
  - 菜单登记表：入口、分组、图标都存在，只有一个警示项
  - 方向键、状态文字、接线
- 浏览器 `verify/verify6.mjs`：桌面 1366×800、手机 390×844、深色模式各跑一遍，共 82 项。「存储满了」那一项是让浏览器在存档时报 QuotaExceededError 来模拟的。
