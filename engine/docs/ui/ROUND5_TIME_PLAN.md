# UI 与交互第五轮（2026-10-20 晚场）：时间与日程

前四轮没有碰过「时间与日程」。这是玩家把日子交给时间的唯一入口，但弹窗里看不出一天的安排排不排得下，日程常常一开始就停下；推进时只有顶栏一行小字，停下后的原因只闪一下提示就没了。

改动文件：新增 `apps/web/public/time-ux.js`、`time-ux.css`；`app.js` 加了 1 行 import 和 4 处只读事件（`openlife:state`、`openlife:autorun` 的 start / batch / end）。另外，小结里已经写了停下的原因时，就不再弹同一句提示。没有改 `index.html`、`stories.js`、`player.js`、`codex.js`，也没有改服务端规则。

## 题一：日程编辑弹窗

| 以前 | 现在 |
|---|---|
| 只有下拉框、↑、×；看不出每件事花几格活动时间 | 每一步前有图标，后面标「1 格 / 3 格 / 不花」；雨雪天在户外劳动标「雪天户外 +1」，腿脚快的头两趟走动标「不花时间」（价目和服务端 `ACTIVITY_COST` 一致） |
| 不知道一天排不排得下 | 合计「一天约用 n / 8 格」，配格子条，超出的格子标红 |
| 排了走不通的日程，要开始推进才发现，还常常一开始就停 | 保存前就标出来：吃饭时手里没有熟食、所在地点也没有粮食；连着两次去同一个地方；没去陶窑就开工；超出一天的格数；每天都不吃饭。出问题的那一行标红，并设 `aria-invalid` |
| 默认日程是「吃饭 → 劳动 → 休息」，新开的人生在庭院里没吃的，日程第一步就停 | 提供三套现成日程：下地的一天、窑上的一天、歇一歇，都从先去灶台吃饭开始 |
| 只能上移 | 加上下移（替玩家点下一项的 ↑，所以仍然走 app.js 原来的交换逻辑） |
| 改了没保存也看不出来；三个金色主按钮 | 显示「有改动还没保存」；有改动时主按钮是「保存」，没有改动时是「开始持续生活」；「等到孩子成年」退成次按钮；保存后按钮变「已保存」并置灰；顶部标「已启用 · 每天重复 / 未启用」 |
| 手机上一行挤着下拉框和三个按钮 | 手机上分两行：第一行图标和下拉框，第二行花费和上移、下移、删除，按钮触控区 40px |

## 题二：持续推进时的反馈

| 以前 | 现在 |
|---|---|
| 推进时只有顶栏小字「自动推进中」；手机顶栏放不下暂停键 | 顶部（手机在底栏上方）常驻「时间在走 · 已过 n 天」，写今天的日期和「照日程过 · 已做 n 件事」，带大号「暂停」。整页忙碌时，这个按钮仍然能点 |
| 点暂停后要等当前一小段做完，期间没有反应 | 立刻显示「正在停下…」，按钮变「停下中」 |
| 停下后只闪一句提示，过 2.6 秒就没了；看不出这段时间发生了什么 | 推进条变成小结，一直留到你关掉：按原因分成「你按了暂停 / 安排做完了 / 到了一个坎 / 有事要你处理（红边）」，写出过了几天、从哪天到哪天、饥饿/年龄/所在地点的变化、日程做了什么（走动合并成「村里走动 ×n」），并给出「看人生纪事」和「再走一段」（卡住时这个按钮叫「去改日程」）。焦点移到小结上 |

纯文字模式和「减少动态效果」下，推进条上的圆点不闪。
