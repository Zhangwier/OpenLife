# 玩家路径验收

来源：DSH S20/T011–T016、T035–T051 和 S24/T004–T005。是执行要求，不是对当前版本缺陷的断言。

每个面向玩家的任务以一条可操作链验收：入口 → 条件/代价 → 行动 → 可观察结果 → 返回或恢复。功能矩阵分别记后台、投影、入口、交互、验证状态；NPC能运行或命令行有模块不能写成网页版已交付。

- 手机/桌面切换：在当前页面能找到入口并实际切换，布局改变且原按钮仍能点击；报告环境和视口，桌面模拟不写成真机通过。
- 插件开关：入口可见，切换后生效边界明确，检查重开或读档时是否符合设计。未接入的选项明确标记，不显示一个无响应的控制。
- 新存档：验证旧存档任务、消息、关系不会混入新世界；使用隔离测试存档，不覆盖用户现有存档。
- 人物信息：按实际观察、介绍、交谈等信息来源解锁；不在消息、生日、病情播报中泄露角色尚未知的信息。
- 跨系统整合：先交付一个小而完整的玩家流程，再扩充其他已授权系统；不能用模块数量代替完成度。

用户只要评审或明确“不测试”时只读并说明这些路径尚未运行。开发任务则完成与改动相关的实际验证；已有证据充分后收尾，不无限扩测。
