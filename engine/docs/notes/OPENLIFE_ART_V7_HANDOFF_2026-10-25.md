日期：2026-10-25。角色：美术体验与独立样例实现。读取时仓库基线 `fe58e5e`；分支和原有未提交改动保留，未提交/推送本轮文件。

## 目标与基线

用户在 v6 林缘庭院后表示“现在这个还可以”，要求继续精进并留下别人可以照做的规范。因此 v6 是保留的视觉基线，v7 是增加动态与交互的候选；本轮没有替换已认可的构图或整体配色。

## 交付位置

- 规范入口：[像素地图美术工作规范](../design/PIXEL_ART_WORKFLOW.md)。根目录 `AGENTS.md` 和文档索引已建立触发入口。
- 生成/编辑分支：[素材提示词模板](../design/pixel-art/ASSET_PROMPTS.md)。
- 可运行样例：[tools/art-lab](../../tools/art-lab/README.md)。源图、认可基线、布局清单、准备脚本、预览与检查都在仓库内，不依赖个人临时目录。
- 像素检查工具：[check_pixel_grid.py](../../scripts/art/check_pixel_grid.py)，只使用 Python 标准库。
- 最新预览：本机 `tools/art-lab/scene.html`；运行生成的图片/报告在 `tools/art-lab/output/`，该目录不作为认可基线。

## 本轮变化

1. 生成并修订一套单朝向四帧行走图，统一原生帧尺寸 16×38 和脚底基线。帧随行走距离切换，向左采用镜像，尚非完整四向动画。
2. 样例由直线移动改为沿道路网格转弯，连续坐标只用于运动计算，绘制为整数像素；加入断路与不同帧率到达测试。
3. 人物受树冠遮挡时局部淡出；树干下段保持不变，开关可对比。
4. 采摘有短提示与少量碎屑；单株移除不改变邻近植物，也不改变树的风动相位。动画相位改为稳定 ID 派生。
5. 普通模式与摆放模式分开；认可基线哈希受保护，源图按清单记录哈希和参数。
6. 修复滚动条引发的画布半像素居中；截图保持固定视口，避免扩大捕获时重排页面。

## 当前实际验证

从仓库路径运行：

```powershell
python tools/art-lab/prepare.py
node --test tools/art-lab/motion.test.mjs tests/unit/workspace-structure.test.ts
node tools/art-lab/check.mjs
python scripts/art/check_pixel_grid.py --native tools/art-lab/output/scene-native.png --scaled tools/art-lab/output/scene.png --scale 2 --report tools/art-lab/output/pixel-grid-check.json
```

实际结果：

- 12 个源 PNG 校验和准备通过，认可基线图保留且哈希一致。
- 运动测试 3 项、既有 workspace 结构检查 9 项，共 12 项通过。
- 独立 Edge 中验证四张动作缓存不同、脚底基线同为第 37 行；点选/采摘、恢复、沿路行走及四帧切换、树冠淡出、近景切换和 844px 横屏宽度检查通过。
- 固定动画时刻采摘另一株植物，树冠区域逐像素保持一致，确认风动相位不随对象列表变动。
- 实际 1536×864 显示截图逐块对应 768×432 原生图，331,776 个 2×2 块均内部同色且内容一致，异常块为 0。
- 像素检查器的自检能接受准确放大，并拒绝损坏一个像素的样例。

没有运行全量游戏回归或真机测试。本轮没有修改 `apps/`、`modules/`、`packages/` 的正式运行代码，也没有启动/重启游戏服务或操作用户存档。

## 下一位从哪里开始

先按规范打开 v6 基线和当前样例，复现以上命令。继续动画时先补同身份、同原生比例的其他朝向；继续美术时一次选择一个局部问题，固定镜头比较。接入正式游戏前，由现有实现者对齐地图投影、位置、权限、成本、保存与拒绝反馈。

当前路径、采摘、计数和遮挡都是独立小样能力，不能据此报告正式游戏已交付。当前 v7 的技术检查不代替用户对美术候选的视觉认可。
