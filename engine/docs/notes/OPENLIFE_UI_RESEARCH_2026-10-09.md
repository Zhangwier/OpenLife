# OpenLife UI 竞品与现状调研报告（2026-10-09）

**性质：调研、诊断、信息架构建议；不属于已实现的代码修改。** 先确认新方案，再做低保真原型与真实触摸测试，不直接改动 NPC、物品与时间引擎。

## 一、调研材料与可靠性

1. **已查看的真实本项目浏览器截图**：`artifacts/ux-390px-context.png`（390×844 场景与底部操作层）、`artifacts/ux-390px-backpack.png`（390×844 行囊）、`artifacts/ux-1280px-settlement.png`（1280×820 桌面周围页）；补查 `apps/web/public/shell.js`、`settlement.js`、`shell.css` 和 `index.html`。这些对应当前工作区而不是 UI 理想稿。此前 CDP 冒烟只能说明页面能打开、目标可点、无明显水平溢出，不代表玩家顺畅。
2. **《未来人生》TapTap 官方页** https://www.taptap.cn/app/230041?os=android 和玩家实操攻略 https://www.taptap.cn/moment/581973335970154733 ：活动→地区→场所→具体动作、人物→互动→交友、物品→背包→使用/卖出、根据年龄条件开放玩法。官网宣传图片多为营销合成图，不能据此认定真实操作层布局；我们主要采用攻略中的可靠文字路径。
3. **《众生游》玩家讨论** https://www.taptap.cn/app/15444/topic ：作为“生活模拟重在代入感与生活选择”的定性补充，不以论坛评论替代真实 UI 测量。
4. **移动设计规范**：Nielsen Norman Group, Bottom Sheets https://www.nngroup.com/articles/bottom-sheet/ （上下文动作按需显示、避免盖住当前必要信息）；Android https://developer.android.com/guide/topics/ui/accessibility/views/apps-views （触控目标至少 48dp）；Apple https://developer.apple.com/design/human-interface-guidelines/tab-bars （顶栏/底栏是导航，不是把当前页面每个动作都当 tab）；https://developer.apple.com/design/human-interface-guidelines/layout （安全区与必要信息优先）。
5. **局限**：未对《未来人生》作完整真人设备录屏/实机量测，未获取用户手机本机截屏和实际点击轨迹；项目已有 Edge 视口仿真截图，尚不能等同荣耀 MagicOS 上的浏览器/触屏验收。

## 二、当前 OpenLife UI 实际缺陷（不是简单换色能修）

| 观察证据 | 根本原因 | 玩家体感与等级 |
| --- | --- | --- |
| 390px 场景上方分两行摆 logo/副标题、主菜单、记忆、重置、时间、年份、聚落状态；真正的村民与物品很靠下 | 每个系统都争抢常驻首屏 | P0：主目标弱、首屏空间被消耗 |
| 底部操作浮层同时显示“劳动与休息 / 移动地点 / 收起”，背后又有“去别的地方 / 劳动与休息”，底部仍有五项目录 | 同一层级的路径重复曝光，弹层/底栏都占据拇指区域 | P0：即使减少总按钮，玩家依然不知道点哪一个 |
| 同一页有“陶婶”字卡与“编织袋/陶碗/兽皮披”等纯文字胶囊；桌面版场景标题很大但 NPC/物件很小 | 用 Web 信息卡表示游戏场景，缺少角色/材料视觉和清晰的空间主次 | P0：看起来像物资表而不是生活世界 |
| 390px 行囊只有两个巨大的圆角白卡、0/4 容量和大片空白 | 作品/库存/装备没有以实际物件为视觉主体；缺少空背包如何获得物品的可操作指引 | P1：背包更像统计页 |
| 日期同时出现“公元前2054年·1月”与“第5760天·冬”，世界时间、角色年纪混杂 | 内部时钟字段直接面向玩家，显示层缺少统一时间文案 | P1：沉浸感与时间理解受损 |
| 桌面 1280px 中上部有较大的文学开篇插画和重复信息，下部真正操作场景被挤出首屏；右下弹出通知可能遮操作 | 桌面未把宽度用于周围人物/行为信息，侧栏与主栏主次不合理 | P1：桌面也要重做信息层级 |
| 当前五个底部项“此刻/周围/行囊/人际/我”，此刻页又有一张“去周围”，周围才是主要行动 | 把“概览”和“生活交互”拆成两个主流程 | P0：不要靠多点一次进入游戏 |

## 三、竞品真正可复用的结构

- 《未来人生》可学的是**带条件的逐级进入**与角色/物品操作中心，而不是复制它的赛博朋克 UI、数值、按年节奏。OpenLife 的真实日活动、地点/房间、NPC 会移动，因此应比《未来人生》有更强的**当前位置、当日事件和物理库存**可见性。
- 应避免机械地为每个世界功能创造一个入口。例如“编织”不是顶层常驻按钮：在“芦苇（携带 ×2）”的物品上下文展示“编苇席/提袋”，并预览材料、消耗与产出；不在编织处时显示地点提示而非整个禁用动作墙。
- 小尺寸优先用**渐进披露**：场景正常状态只展示最主要的人、物、位置；选择对象再出现最多 2–4 个相关动作。一个操作层即可，避免选中对象时同时有一排二级导航按钮和独立底栏竞争。

## 四、推荐的新版信息架构（优先四个底部项，而非继续五项）

| 底部入口 | 必须承担什么 | 不再承担什么 |
| --- | --- | --- |
| **生活**（主入口） | 当前位置、今天时间与饥饿、可见人物/物品/附近地点、事件反馈；直接在此交互 | 大段人生概述、所有命令及所有制作菜单 |
| **行囊** | 真实物品卡、双手/容器/家中物品来源和实际负重、选中后的操作；可跳到对应工作台 | 仅显示“0/4 件”的空统计卡、旧“作品”与实际物品混用 |
| **人际** | 见过/搭话/相识/朋友的联系、上次接触、关系与意愿；只有真实信息才展示 | 把当前所有在场村民直接当好友 |
| **人物** | 自身年龄、状态、技能成长、职业、记忆与设置；支线家族/历史可二级进入 | 全局重复的“此刻”仪表盘 |

“地图/旅行”作为**生活页的地点卡或顶部定位入口**；重要的“时间继续/暂停”使用一个固定而且文案明确的位置，避免顶部多个功能按钮同时抢注意。玩家一打开游戏就进入“生活”，不需要先看概览再点击“看看周围”。

## 五、390×844 移动端低保真布局（内容尺寸建议，而非现成截图）

```text
┌────────────────────────────────┐
│ ◇ 北岸聚落       冬 · 第12天  ⋯ │  48–56px 顶部
├────────────────────────────────┤
│ [角色小头像] 陶叔家的院子         │
│ 饥饿 2/10  · 今天还可行动 6 格    │  64–80px 状态
├────────────────────────────────┤
│ ┌────────────────────────────┐ │
│ │  [院落/窑/树/人物的场景插画] │ │  160–220px 场景
│ │  阿灶正从河边搬回柴草        │ │
│ └────────────────────────────┘ │
│ 今天在这里                        │
│ [陶婶·搭话]  [地上芦苇 ×2]       │  可见目标卡
│ 附近  [灶台] [田地] [住处]        │  目标/旅行
│                                │
│     [结束这一天 / 继续运行]       │  独立时间工具
├────────────────────────────────┤
│  生活       行囊     人际     人物 │  56–68px + safe area
└────────────────────────────────┘
```

当玩家点“地上芦苇”：出现**同一处上下文操作面板**，显示“芦苇 ×2 / 重量 / 所属地点 / 能否拾起”，下方“拾取 / 加工（缺条件则有具体提示）/ 关闭”。不要再另摆“劳动与休息、移动地点、收起”三按钮及重复的常驻捷径。浮层若遮挡信息，使用下沉式细节页或单一底部抽屉，带明确关闭，页面内容在底栏/刘海安全区内。

## 六、风格方向与差异化

建议 **A. 温暖手绘聚落（首选）**：低饱和米白/苔绿/陶土棕继续作为背景，加入统一的 2D 场景小插画、角色半身像或剪影、可读的材料图标与真实事件条。让“芦苇、柴草、陶器、田地”能被视觉辨认，再用文字说明约束。不是给现有标签随便加 emoji。
- B. 文本手账人生：轻量、开发快，适合回忆/家族档案，但不适合作为本项目“当面遇 NPC 与材料互动”的唯一场景；
- C. 完全像素化/地图 RPG：空间表现强，制作与资源投入大，在游戏可玩性尚未稳定前不建议重做整套引擎。
- 文字：大标题只用于章节和当日事件，普通信息/按钮使用可读字号和对比度，避免灰绿淡字和大面积空白卡。内容先于装饰。

## 七、下一步实施建议（调研阶段不动代码）

**阶段 0：原型冻结** —— 先做“生活主屏 / 点 NPC / 点芦苇 / 行囊 / 人际”五个低保真静态状态，用户确认选用的 UI 密度和画风。不能同时开 8 个导航模块。

**阶段 1：信息架构** —— 使打开游戏直接见“生活”的真实可交互地点；合并此刻+周围；右上精简更多菜单。保留原真实世界命令，视图只做逐级映射。错误和结果清晰，不触碰交易原子逻辑。

**阶段 2：场景/物品/角色表现** —— 低成本统一素材库，首批仅院子、芦苇滩、田头、公灶四处；阿灶、阿予、陶婶 3 人；芦苇、柴草、粟、陶器、提袋 5 类物品。制作卡必须预览材料需求、来源/可用性和真实产物。

**阶段 3：行囊与时间** —— 显示真实持物与容器、实际负重、家中放物位置，空态提供可执行目标；日期只显示同一套人可理解的时间描述；所有操作保留相应活动成本、世界推进与证据。

**阶段 4：视觉/触控验收** —— 实测 360×800、390×844、430×932、桌面 1280；触控目标至少 48dp；页面无水平溢出；折叠面板不能同时遮挡底部交互和导航；支持系统安全区、返回/关闭/恢复状态。录制真实操作流程，不能只凭 HTTP 与截图判断。

**可量化验收**：新开局 5 秒内能找到当前位置和下一步行动；三次点击以内能从“生活”找到并开始采集；从物品卡能了解材料→制作→产出；能辨认陌生人而不被误当朋友；在 390px 下，主屏不出现两个作用重复的“劳动/移动”入口；底栏不被弹层和手机系统导航条盖住；取物/交易失败后的资源数量仍正确。未实测不宣称通过。

## 八、本轮明确不做

不新建 NPC 数值、认知系统或经济市场，不重写世界时钟，不复制《未来人生》视觉皮肤，不马上给整个项目填满 AI 插画。先确认交互逻辑，再为少数代表性页面制作素材。
