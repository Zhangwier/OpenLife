# OpenLife 试玩问题：交互与基础生活规则重构方案（2026-10-09）

状态：**试玩反馈已核实；方案冻结新功能，待实施和真人/浏览器验收**。本文件是问题审查/产品任务，不表示功能已修复。当前工作区多轮代码尚未提交；保留既有数据和测试。

## 1. 证据来源与现状

- 用户第一轮试玩：页面大量纯文字和密集按钮；制作动作不附着在材料/工作地点上；“此刻”与“活动”内容混乱；点击直接认识人物；人物双手可无限持物并跨天携带；未来还要适配手机。
- 竞品参考：《未来人生》（万匠）TapTap 官方产品页 https://www.taptap.cn/app/230041?os=android ；TapTap 游戏攻略 https://www.taptap.cn/moment/659389962227025232 和 https://www.taptap.cn/moment/581973335970154733 。**只借鉴信息架构**：人生概览、活动地点、人际和背包各司其职；进入场景、选目标、再操作；交友要先接触再交流。竞品不同题材/世界规则不照搬其数值和画风；未进行完整竞品实机拆解。
- 源码证据：`apps/web/public/shell.js` 把旧 `.life-stage` 迁入「活动」，并单独生成「此刻」概览；`apps/web/public/settlement.js` 将所有 `settlement.actions` 按移动/房间/其他三类完整铺成按钮，单个按钮携带长 hint/禁用原因；`modules/settlement-locations/src/module.ts` 的 `homesteadActions` 在当前位置遍历材料、携带物品和容器来生成众多命令；`apps/web/public/shell.css` 在窄屏主要改列数并让顶部导航换行，没有独立移动端交互架构。
- **P0 社交规则错误**：`apps/web/server.ts` 的 `friend` 动作直接调用无 `targetId` 的 `family.make_friend`，传入硬编码名称；`modules/family/src/module.ts` 在无目标时直接 spawn 新角色并创建 `friend_of`。这与“现实地点中相遇、逐步结交”冲突，属于权威规则缺陷，不是纯 UI 问题。
- **P0 携物规则缺失**：`modules/world-objects/src/module.ts` 中 `take` 仅验证物件可搬、所有权和可达性，**没有玩家总质量/容积/持握位限制**；原型虽有 `mass`，容量仅用于容器内部。跨日持续持有是正确的物品持久化，但无限持有且无负担是错误的世界约束。
- **P1 不一致的地图入口**：`shell.js` 当前地图页仍描述“地点移动尚未接入”，与已经存在的聚落地点移动割裂；玩家可能在「地图」看不到实际可玩的地点。
- 目前自动化 Node/HTTP 测试不等于真实浏览器点击/手机适配；本次不宣称上述问题已修复。

## 2. 立刻改动优先级（暂停继续加 NPC、认知、市场和新手艺）

| 优先级 | 目标 | 必须通过的验收 |
| --- | --- | --- |
| **P0-1** | 正确的认识人物规则 | 旧“认识一个人”不能点一下凭空生成朋友。认识必须基于**当前位置真实可见 NPC**、本人选择搭话、对方响应；遇见≠熟人≠朋友。没有 NPC 或异地不允许建立关系。旧存档可读，记录初见/交流事件。 |
| **P0-2** | 人物携物限制 | 明确双手/随身携带/容器/住处储物。拿起、取出、交换、采集都统一校验承重与持握；失败不产生物品/不扣资源和额度；NPC 走同一规则。背包和长期持有应当有条件，但**隔日不自动丢弃合法随身物品**。 |
| **P1-1** | 移动端优先的导航 | 将顶层收敛到「此刻」「周围」「行囊」「人际」「我」五项（可调整为四项合并我与此刻）；隐藏旧“活动”作为重复入口。当前地点内进行移动/探索，不再把全部世界动作平铺；旧年时钟操作另作清楚说明。 |
| **P1-2** | 点对象/材料才显示操作 | 点击地上物件/随身芦苇/灶台/田地/人物，底部抽屉显示**仅对该目标**成立的 1–4 个动作。制作从原材料“芦苇 ×2 → 编织”或窑口工作台进入；未解锁配方到「工艺」内，绝不在场景直接平铺全部制作命令。 |
| **P1-3** | 手机上的信息密度与按钮规则 | 以 360–430 CSS px 竖屏为默认；底部安全区导航、至少 44×44px 触控目标；首屏只显示 1–2 个主要动作及必要的当日状况；禁用原因在对应操作详情显示，不在总览堆说明。不能横向溢出，连续运行/暂停位置固定。 |
| **P1-4** | 此刻、周围、行囊、人际不重复 | 此刻只看角色当日状态/事件/继续生活；周围为唯一实际场景/地点互动页；行囊为所有真实物品及收纳/使用；人际分“陌生人（当前位置见过）/相识/亲友”，不把 14 人默认视为朋友；「地图」进入可以实际去的地点。 |
| **P2** | 美术表现与完整玩家引导 | 早期聚落采用统一的地点场景图、人物头像、材料图标、短事件卡；不复制《未来人生》赛博朋克视觉。补一段 3–5 分钟新手生活流程和操作反馈。 |

## 3. 推荐的玩家流程（移动端首屏不需要知道全部底层命令）

- **此刻**：头像、所在地点、今天剩余活动时间、饥饿与今日重要事件；主按钮“继续生活”。不重复显示「活动」的全部按钮。
- **周围 / 场景**：先选择【人】【物】【地点】之一。选阿灶→人物底部卡（陌生/初见/熟悉度）→搭话/询价；选芦苇→物品卡（来源、重量、数量）→拾取/加工；选灶台→工作台卡→放材料/烹饪。
- **行囊**：上层显示“手上 X/2、身上容器 X/Y、总负重 A/B”；点击原料出现“放下/装袋/使用/加工（需地点）”。制作完成物品原位显示；不能为展示 UI 新造第二套库存。
- **人际**：通过**真实见面/交流事件**进入相识列表，再慢慢深化信任。点“认识”只能尝试交流/介绍，不能强制 NPC 接受或瞬间生成外来朋友。
- **时间**：固定的日推进/暂停入口；每次动作显示真实耗时和结果。旧版“让一年流逝”与当日生活不是同一操作层，避免误触。

### 人物关系状态与携物边界（首版建议，数值待校准）

- 社交：`陌生（只知道有人）→见过→搭过话→相识→熟悉/亲近→朋友`；身份名称的可知性按事件/角色介绍控制，不能因为 UI 列表显示而默认已相识。区分世界事实、人物知道什么、玩家视图。
- 双手持握建议**最多 2 个占手位**，再依实物重量与体积约束；本来就存在的提袋应增加**容器内**承载上限而非无限加手位。粮食、柴草、衣物、容器应分别定义合理物性；超出时只能搬运/分次、放在现场或家中存储。
- 不用“到了第二天自动丢包”掩盖问题；正确行为是**真实物品可持久携带，但有体力/空间/重量代价**。重物不能与空手动作无差别。

## 4. 分片实施顺序与防回归

1. **UX-STOP-P0**：先修 `friend` 一键无目标造人以及重量/手数缺失；修复要落在 `family` / `world-objects` 权威规则层和相关场景命令；专项、跨日、存档、权限、同 seed 与前面农业/交换流回归。
2. **UX-IA**：移除面向玩家的全动作平铺；保留后台 `SettlementCommands` 与事务，不删除业务系统。先做「周围→选物→材料上下文操作」以及「周围→选人→交谈」两个真实流程。
3. **UX-MOBILE**：做移动优先导航/底部抽屉和真正能操作的「行囊」，合并重复入口；仅在 CSS 无溢出、键盘/触摸可用、手动验证后算完成。
4. **UX-PLAYTEST**：玩家至少完成“出门→拾材料→收纳→制作→找人搭话→回家放物→结束一天→保存/读档”全程，屏幕 360px/390px/430px 与桌面均核对；记录每个失败点，先修可玩性后恢复 M4/NPC 新开发。

**架构守则**：保留 Kernel/Command/Transaction/Event/RNG/权威物品关系与已通过的农业、陶艺和 NPC 基础实现；调整的是**交互入口与缺失的生活规则**，不应全部推翻重写。不得把控制按钮隐藏当作规则修复。不要在没有浏览器可操作证据时声称已完成“实玩验收”。
