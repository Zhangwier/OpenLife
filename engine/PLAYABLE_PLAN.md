## 目标与范围

把现有模拟能力连接成「年轻手艺人 → 制陶取舍 → 作品用途 → 人际关系 → 家庭传承」的可玩流程。目标体验长度 20–30 分钟，须通过真人试玩验证，自动测试不替代该结论。

场景为古代聚落，默认从 16 岁开始。保留现有世界、历史、家族和存档能力；使用现有 practice-runtime 与 craft-pottery，不另造制陶规则。新生活规则由内容模块提供，Web 只组合命令、推进时间和渲染投影。Core Contract 无计划变更。

## 阶段与完成标准

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| P1 可操作的手艺 | Web 接入制陶四阶段；材料、条件、风险提示；结果与作品用途 | 开局一分钟内有选择；四阶段均可操作；不同路线有不同结果；失败可重新尝试 |
| P2 人物与积累 | 学习积累、采集补给、两位有诉求的人物；交往与作品赠送 | 行动推进时间；关系变化可见；不能重复领取同一作品收益；遗产需要真实作品与积累 |
| P3 家庭与交棒 | 与已认识人物成家、间隔生育、成年后代交棒、继承摘要 | 同一时点不能连续生育；成年后代可在父母在世时接手；无继承人给明确说明 |
| P4 玩家界面 | 当前处境与选择为主；人物/家族/世界分视图；持久结果反馈 | 条件与代价可见；键盘可用；桌面和窄屏无横向溢出；保存/恢复闭环 |
| P5 验证与交接 | 模块测试、HTTP 流程、浏览器截图、当前状态 | 全套测试通过；验证确定性与存档；已知限制明确，不把自动化通过称为好玩 |

## 规则决策

- 世界现有 1 tick = 1 月；首版以一段生活/制陶阶段为月级抽象，界面说明这是阶段时间。
- 制陶质量与缺陷以 craft-pottery 为准；新模块负责学习资格、人物关系、作品处分和传承。
- 主界面呈现一个当前情境；已开始的手艺在选择节点等待玩家，快进不能跳过该节点。
- 成果可换取补给、赠给人物或留给家族，三者互斥。失败成品提供复盘并可重新采集制作。
- 人物相处有积累，成年且关系足够才能成家；孩子到成年后可交棒，不等待父母死亡。
- 自动/手动存档保存完整世界；旧存档继续读入，并提供显式进入手艺生活的入口。读入本身不重置旧人生。
- 自动化不能证明 20–30 分钟的趣味性；最终保留真人试玩任务。

## 实施边界

本轮工作区已有未提交的地理、气候、生态、制陶与 Kernel 改动。以现状为基线，不回滚、不覆盖；优先新增 settlement-life 模块与 Web 组合层。复用现有制陶文件的当前接口，避免改写其物理规则。

## 验证

基础回归：`node --test --test-reporter=tap`。新增测试覆盖规则绕过、重复处分、未成年交棒、同月重复操作、存档恢复、同种子同命令。

HTTP/浏览器验证使用独立端口和独立浏览器上下文，避免修改用户现有服务器及浏览器存档。检查初次选择、四阶段制陶、作品处分、关系、交棒、存档与手机布局。

## 当前状态

### M1 生活底座（2026-10-08 完成）

默认新人生不再从制陶开始，而是落在一个有 14 名居民、8 个场所、169 件实例的真实聚落里。第一个可复验闭环是「借一个陶罐 → 走到河边 → 装水 → 带回家 → 归还」，全流程经 HTTP 与浏览器双重验收。

- 时间：日尺度时钟与月聚合（`modules/world-clock`，契约见 `docs/rfc/TIME-RFC-001-life-time-scale.md`）。一次取水、一次谈话记 1 天；30 天为一个月；年龄、婚育、季节与历史锚点继续按原有月/年语义发生。旧存档不静默换算。
- 空间：四层空间与移动（`modules/world-space`）。院落内房间是 0 天，跨场所按天计费；一个人同一时刻只有一个位置。
- 物品：通用原型、容器与借还（`modules/world-objects`）。借来的东西不会变成自有财产；归还时记录是否逾期。
- 聚落内容：`modules/settlement-locations`，8 场所 / 18 空间 / 32 原型 / 169 实例 / 7 处可恢复资源点。
- 场景界面：`apps/web/public/settlement.js` + `styles.css`，按「场景—目标—操作」呈现。

当前基线：**352/352** 测试通过。原始输出 `artifacts/settlement/tests.tap`；浏览器证据 `artifacts/settlement/browser-results.json` 与同目录截图；CLI 演示日志 `modern-demo.log`、`magic-demo.log`。

M1.2-B 时间语义统一已完成：世界声明自己的刻度（`day`），其他模块读世界时钟而不是自行除以 12 或 360；时代漂移由每年 29 年降为 0。一致性证据见 `tests/unit/time-consistency.test.ts`。

旧档兼容由 `tests/unit/save-migration.test.ts` 守卫：一个拥有成品陶器、伴侣与孩子的旧档载入 M1 模块集后，tick、身份、作品、伴侣、孩子与生活状态逐项一致，且不静默注入时钟或聚落。空间与库存不变量由一次 96 步持续混合作业巡检守住（每步只有一个有效位置、任何地方都不出现负库存、同种子指纹一致）。

### 已实现的体验变化

1. 新人生从 16 岁开始；旧存档可以显式进入新玩法，时间与身份保持。
2. 学习、采集、相处均消耗时间；学习和制作积累的经验会改善下一批泥料的均匀性与杂质状态。
3. 复用真实制陶检查点与风险；每一步显示取舍、阶段时间、不可用原因和实际反馈；失败可以补充材料重试。
4. 三位人物有身份、性格与诉求；相处、帮助、赠送积累熟悉程度；与已成年且相互信任的人建立家庭。
5. 可用陶器的交换、赠送、家族留存互斥；传承需两段学习与真实家族作品。
6. 孩子在九个月的准备期结束后出生；一年内不能重复计划生育；孩子成年后可以在父母在世时接棒。
7. 下一代继承家族作品与入门经验，能够查看原作者；主界面展示当前处境，人物、作品、家族、世界分视图。手机优先呈现当前选择。
8. 每次选择自动保存，刷新恢复最近存档；手动存档可回到未完成的制陶节点。旧页面的过期动作请求被拒绝并刷新。

### 已知限制与下一步

- 固定的三位聚落居民；居民离世后尚无新居民补充。第二代可以接续制作，但多代人物内容仍需扩展。
- 人物诉求目前通过相处、帮助与赠物体现，缺少专属后续事件与冲突。下一步优先各补一条会随玩家选择变化的事件链。
- 日常和制作按月抽象，尚未引入天级时间；经验影响泥料处理，未形成完整专长树。
- 当前服务维护一个世界，适合本机单人试玩；多人会共享世界。新生儿准备期与作品行动有模块约束，材料采集仍属于首版简化补给。
- 已死亡人物的未完成手艺保留在历史状态中；不会阻止成年后代接棒，目前没有专门的活动终止界面。
- 美术为代码绘制的聚落与人物剪影，仍需后续场景、人物和季节表现。
- 完成自动流程不等于达成 20–30 分钟的游玩体验；接下来进行下面的真人试玩，再决定内容与节奏调整。
